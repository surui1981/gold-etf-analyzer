## 产品定位

本工具是为**个人黄金投资者**（尤其做**中短期 ETF 波段**）做的数据参考平台。你看到的核心问题是：单一行情 App 只给报价，没有「综合多空」判断；自己拉一堆宏观数据又太散。我们把这几件事缝成一个产品：

1. **量化多空** — 把技术面、宏观面、消息面、资金流面四个维度按权重加权成一个 0-100 的「综合趋势评估指数」，看一眼就知道现在偏多还是偏空。
2. **持仓闭环** — 你的开仓 / 加减仓 / 清仓都进系统，**实时盈亏、胜率、最大回撤、收益曲线**自动算。
3. **决策可解释** — 系统给出「买 / 加 / 持有 / 减 / 卖」建议时，每一条都附**理由明细**（指数分位、持仓状态、阈值依据），而不是黑盒。

延续 PM-Evaluator 架构思路：各因子按经验赋权、输出**红绿着色**的机会窗口与多空信号；**消息面由你基于主流财经网站的投行展望自行打分**，避免「被算法替你判断」。

> **这个项目的一条纪律：诚实优先于好看。**
> 缺数据写「—」而不是 0、拿不到就说「降级中」而不是给个假中性值、
> 没算出来的 `null` 与「算出来是 50」**不同形** —— 见
> [docs/composite-trend-index.md](docs/composite-trend-index.md) §五「口径纪律」的 7 条。

## 三大核心能力

### 1️⃣ 综合趋势评估指数

**公式**：`综合指数 = 技术面 × 25% + 宏观面 × 35% + 消息面 × 25% + 资金流面 × 15%`（权重可在 `/weights` 页面调整）

**技术面**（5 维度）：结构 30% · 动量 20% · 支撑 20% · 动能（RSI）15% · 回撤 15%。
默认走**组内平均**（趋势组 0.50 / 超买组 0.30 / 风险组 0.20，组权重同样可调）。

**宏观面**（11 因子，V0.119.0 起）：

| 因子 | 权重 | 与黄金 | 100 分位 | 0 分位 | 数据源 |
|------|------|-------|---------|--------|-------|
| 美元指数 DXY | 13% | 负相关 | 94 | 107 | Yahoo `DX-Y.NYB` |
| 美债 2Y | 5% | 负相关 | 3.0% | 5.0% | 美联储 H.15 |
| 美债 10Y | 7% | 负相关 | 3.8% | 5.4% | 美联储 H.15 |
| 美债 30Y | 5% | 负相关 | 4.3% | 5.7% | 美联储 H.15 |
| 美债 10Y-2Y 利差 | 9% | 负相关（倒挂利多） | -0.5% | 1.5% | 派生（10Y − 2Y） |
| 美债 10Y 实际利率 | 18% | 负相关 | 0.8% | 3.2% | FRED `DFII10` |
| VIX 恐慌指数 | 9% | 正相关 | 30 | 13 | FRED `VIXCLS` |
| 央行购金（吨/年） | 22% | 正相关 | 1200 | 500 | WGC GDT 季度 |
| 美国政府债务/GDP | 5% | 正相关（债务↑ 利多） | 140% | 60% | FRED `GFDEGDQ188S` 季度 |
| 中国政府债务/GDP | 4% | 正相关（债务↑ 利多） | 95% | 40% | FRED `GGGDTACNA188N` 年度 |
| 欧洲政府债务/GDP | 3% | 正相关（债务↑ 利多） | 95% | 60% | Eurostat `GOV_10Q_GGDEBT` 季度（EU27_2020） |

> 表中 100/0 分位是**硬编码兜底值**；历史样本充足（≥60 个交易日）时自动切换为
> **近 252 日滚动 90/10 分位**，阈值跟随市场自动调整。滚动分位的方向与上表的
> 「负相关 / 正相关」标注一致（负相关因子取 `best = P10`，即值越低越利多黄金）。
> **例外**：央行购金与 3 个政府债务因子是**季度 / 年度**低频序列，不参与滚动分位
> （日频落表会把同一个值重复几十次 ⇒ P10 == P90 ⇒ 阈值退化）。
> 详见 [docs/parameter-evaluation.md](docs/parameter-evaluation.md)。

**消息面**：由你在 `/news` 页面自行打分（0-100：>55 看多，<45 看空，50 中性），**每日 3 次槽位**，1:2:3 加权合成，越晚权重越高。没打分 ⇒ **整面从指数里剔除**，不是记 50 分。

**资金流面**（6 因子，V0.120.0 新）：只看**钱往哪儿流**，不收任何价格类读数（不收 SHIBOR / 汇率 / 利率 —— 那些归宏观面，避免同一条逻辑计两遍）。

| 因子 | 权重 | 节奏 | 与黄金 | 口径 | 数据源 |
|------|------|------|-------|------|-------|
| 黄金 ETF 4 周累计净申赎 | 22% | 周 | 正相关 | 亿元 | 上交所 518880 官方每日份额 |
| 黄金投机净多占 OI | 18% | 周 | 正相关 | % | CFTC 分类持仓 |
| 黄金投机净多 4 周变化 | 14% | 周 | 正相关 | 张 | CFTC 分类持仓 |
| 美元净流动性 4 周变化 | 14% | 月 | 正相关 | $M | FRED `WALCL`−`WTREGEN`−`RRPONTSYD` |
| A 股融资余额月环比 | 16% | 月 | **负相关**（杠杆撤出 ⇒ 黄金机会成本降） | % | 沪深两市融资余额 |
| 中国 M1−M2 剪刀差 | 16% | 月 | **负相关**（存款淤积 ⇒ 抗通胀需求升） | 百分点 | 央行 M1/M2 |

> **周 54% / 月 46%** —— 按用户要求「关注近期资金数据」，周频因子（更近、领先性更强）
> 权重合计过半，月频因子（噪声低、可信度高）作压舱石。
>
> **符号口径**：两个中国因子取**机会成本**口径（值越高越利空黄金）——
> 融资余额上涨 = 股市杠杆加码 = 黄金承压；剪刀差走阔 = 钱淤积在定期存款 = 抗通胀资产需求上升。
>
> **阈值**：滚动分位窗口按**观测节奏**取（周频 104 周 = 728 日、月频 60 月 = 1826 日），
> 不是日频 252 日 —— 否则周频只装得下 36 个观测、月频只有 8 个 ⇒ 样本不足 ⇒ 阈值永远退回硬编码。
> **观测日按节奏锚定**：周频锚 ISO 周的最后一个交易日、月频只取**已过完的月**
> （`us_liq_net` 的源是周更，但值是「4 周变化」⇒ 按周采样会重叠 3/4 ⇒ 按月观测）。
>
> **一个因子都没取到读数时整面返回 `null`**，从综合指数里**剔除**（不是记 0 分）——
> 0 分会被当成「资金正在撤离黄金」，而真相是「没数」。

**等级阈值**：`≥75 强势上升` / `≥55 上升` / `≥45 震荡` / `≥25 下降` / `<25 弱势下降`（趋势页红绿着色）

### 2️⃣ 个人持仓管理

- **多账本** — 默认账户 + 自定义账本（归档管理），全站顶栏账本切换器；持仓 / 收益曲线 / 业绩分析均按账本隔离
- **完整交易闭环** — 开仓 → 加仓 → 减仓 → 清仓，**实时盈亏** + **已实现盈亏** + **胜率 / 盈亏比 / 平均持仓天数**
- **双单位持仓** — 同时支持**份数**（ETF 标准 100 份一手）和**克数**（实物金 / 积存金口径），单位切换器在收益曲线右上角
- **收益曲线** — 流水回放重建，含**最大回撤**标注
- **决策可解释** — 「买 / 加 / 持有 / 减 / 卖」建议附理由明细（指数分位 / 持仓状态 / 阈值依据），不是黑盒

### 3️⃣ 央行购金监控

- **数据源**：WGC（世界黄金协会）Gold Demand Trends 季度报告
- **覆盖**：全球合计季度数据 **2014Q1–2026Q3（51 季度）** + **24 个国家**的季度明细 + UZB/IRN 手工补丁
- **⚠ 口径纪律（V0.121.4 治本）**：库里的**全球合计行**（含未披露国家的估算）与**各国明细行**（仅已披露国家）**语义不同、不可相加** ——
  「合计 + 明细」相加是**重复计数**（2026Q2 实测 336.7 = 合计 288.9 + 各国 47.8）。现在合计行用独立伪 ISO `WGC_AGGR` 标记，

  `country_count` 与 Top 榜**排除**合计行。

## 隐私 & 安全

- **数据本地化** — SQLite 文件存本机，**不上传任何持仓/打分/账本数据**
- **多用户登录（V0.75.0）** — 会话式认证，**默认关闭**（`AUTH_ENABLED=false` = 单用户模式）。开启后除健康检查/登录注册/埋点外**全部 API 需登录**：
  - 密码 **bcrypt cost=12** 哈希，明文永不落库、不入日志；未知账号也跑一次同代价哈希以打平耗时（防账号枚举）
  - 会话 cookie `HttpOnly` + `SameSite=Strict`；**服务端 sessions 表**存储会话（登出 / 改密 / 禁用可**即时撤销**）
  - 写端点 **CSRF 双提交校验**（`X-CSRF-Token` 头 vs `pm_csrf` cookie，恒定时间比较；`sendBeacon` 埋点豁免）
  - 登录失败**账号 + IP 双维度节流**（默认 15 分钟内 5 次即锁定 15 分钟）
  - `APP_ENV=prod` + 开启认证时自动关闭 `/docs` `/redoc` `/openapi.json`（不暴露接口清单）
  - ⚠️ **本版为「认证骨架」**：登录后才可访问 API，但多个用户之间**尚未做数据隔离**（数据隔离属 V0.75.2）；单机自用建议保持 `AUTH_ENABLED=false`
- **管理员守卫** — `X-Admin-Token` 头（`secrets.compare_digest`），写端点全覆盖（无 `ADMIN_TOKEN` env 时 skip，dev 友好）
- **速率限制** — per-IP 60s sliding window 120 req/min（`app_env!=test` 自动禁用，避免测试 429 误伤）
- **Web Push** — VAPID EC P-256 密钥对持久化到本地，订阅表 endpoint unique + 退订硬删

## 测试与门禁

```bash
python -m pytest -v                                      # 全量 2285 用例；离线口径 2235（按文件名排除 2 个联网 fetcher）
ruff check src tests                                     # lint
ruff format src tests                                    # format
```

**10 道脚本门禁**（`scripts/`，CI 里跑 7 道 + 1 道经 pytest 包装）：

| 脚本 | 拦什么 | 在 CI |
|------|--------|--------|
| `check_static_js.py` | 前端内联 JS 语法 / 未定义调用 / DOM id（项目无构建步骤，必须另设关卡） | ✅ |
| `check_docs_claims.py` | 文档里的表名 / localStorage key / 静态页 / API 端点是否真实存在 | ✅ |
| `check_links.py` | 死链与标题锚点（含「长得不像链接」的 link reference definition） | ✅ |
| `check_pwa_assets.py` | SW 缓存版本 / `SHELL_ASSETS` 逐条可解析 / manifest 目标存在 | ✅ |
| `check_version_sync.py` | 4 处版本号同步 / CHANGELOG 版本段降序 / version-status 基线 | ✅ |
| `check_deps.py` | `src`+`tests` 的三方 import 必须在 `dependencies` 里 | ✅ |
| `check_i18n_keys.py` | i18n key 三语覆盖 + **字典文件是否真被页面加载** | ✅ |
| `check_cluster_render.mjs` | 前端渲染行为（抓真实代码块在 Node 里执行后断言产出） | ✅（经 pytest 包装） |
| `check_routes.py` | 路由与文档双向验证 | 手动 |
| `check_freshness_consistency.py` | 「引了 `freshness.js` ⇒ 必须有容器」等接线一致性 | 手动 |

> ⚠️ **`-m "not network"` 在本仓是无效过滤** — `pyproject.toml` 未注册 `markers`、`tests/` 也无任何 `@pytest.mark.network`，该过滤**不排除任何用例**。真正的离线口径是**按文件名排除**：`--ignore=tests/test_services/test_irfcl_fetcher.py --ignore=tests/test_services/test_h15_fetcher.py`（50 用例）。
>
> ⚠️ **前端没有构建步骤** — JS 写错不会被任何编译期拦截，却会让整页脚本失效（按钮无响应、数据不加载），而后端测试依旧全绿。改完 `static/*.html` / `static/*.js` 后**务必**跑 `check_static_js.py`。
>
> ⚠️ **改 `static/*.html` / `static/*.js` 必须 bump `static/sw.js` 的 `VERSION`** ——
> `/static/` 走 cache-first，SW 字节未变就不重装 ⇒ 用户会看到「HTML 新 + JS 旧」的错配。

|---|---|
| **可信度层** | 命中分析缺「为什么这次错」；宏观因子的**阈值口径可覆盖**（改一次阈值，历史结论就跟着变，而 UI 上看不到「这次用的是哪套阈值」） |
| **数据纵深层** | 仍缺的数据源：CFTC 黄金净多的连续周序列、美元净流动性的日频、黄金 ETF 份额直采 |
| **参数可信度层** | K 项 · 多市场独立校准（宽表样本量仍薄）；判定阈值本身要进入回测网格（能回答「阈值定 55 是不是比 50 好」） |
| **决策闭环层** | verdict card 的置信度没有校准依据；参数 → 实盘闭环还差最后一跳（把回测结论回流到建议侧） |
