# 参数评估改进方向与后续参数值建议

> **目的**：系统梳理当前应用所有**可调参数**（综合指数权重 / 5 维度技术面权重 / 5 因子宏观阈值 / 等级阈值 / 决策矩阵 / 共振信号 / 消息面口径 / 回测网格），指出现状的 8 类问题，并给出**带新值**的改进建议与执行优先级。
>
> **范围**：本文件聚焦"评分与决策"参数；测试规模、CI/CD、推送、认证等工程参数不在此处。
>
> **基线版本**：V0.77.2（2026-10-03，commit `5ffc650`）

---

## 0. TL;DR

- **核心问题不是参数值"对不对"**——多数值是合理起点；**真正的瓶颈是三件事**：
  1. **阈值口径分散且冲突**：同一份 0-100 分在 5 个模块里被解读成不同方向（消息面 `>55`、综合等级 `≥55`、单维度方向 `≥60`、共振 `≥55`）。
  2. **静态参考值的时代错位**：宏观 5 因子的 `best/worst` 阈值（95/105 / 3.5%/4.5% / 25/12）反映 2020-2023 的市场结构，2024-2026 已多次触顶/触底，长期输出 0 或 100，信息含量退化。
  3. **技术面 5 维度内部高度相关**：结构/动量/支撑/动能 4 个维度都围绕均线 + 价格动量，加权后实质上变成「4 倍趋势 + 1 倍回撤」，回撤信号被稀释。
- **推荐 7 项改进**，分近（1-2 周）/ 中（2-6 周）/ 远（2-3 月）三期，全部可纳入 V0.78.0 → V0.80.0 路线。
- **改进的元方法**：所有新值都应通过 V0.71.0 已落地的 `backtest` 引擎扫描后用 Sharpe + 命中率 + 校准分箱三维交叉验证，**而非凭经验拍数**。

## 3. 当前待解决的 8 项参数问题（详细诊断）

### 3.1 阈值口径分散且冲突 ⚠️ **P0**

**问题**：同一个分值在不同模块里**方向解读不一致**：

| 阈值 | 模块 | 解读 |
|------|------|------|
| **55 / 45** | `services/news.py:40-41` 消息面方向 | **严格不等号**（`>55` 看多，`<45` 看空；55 是中性） |
| **55 / 45** | `services/trend.py:654-664` 综合指数等级 | **含端点**（`≥55` UP，`<55` 才 SIDEWAYS） |
| **55 / 45** | `services/resonance.py:38-39` 共振信号 | **含端点**（`≥55` BULLISH） |
| **60 / 40** | `services/trend.py:645-651` 单维度方向 | 单维度比综合指数**严格一档** |
| **70 / 60 / 55 / 45** | `services/decision.py:139-159` 决策矩阵 | 阈值与等级阈值部分重叠但不对齐 |

**实际后果**：
- 消息面给 55 分：方向判定为「中性」，但共振信号认定「tech/macro/news 三维同向」（≥ 55）。
- 决策矩阵认为「idx ≥ 55」就是 BUY 候选，但综合指数等级里 55 仍属「UP」（非强势），措辞不一致。

**建议**：统一阈值常量到 `schemas/thresholds.py`（新增），并在文档里建立"55 看多 / 60 强多 / 45 看空 / 40 强空 / 70 行动"的**单一口径表**。

### 3.2 静态参考值的时代错位 ⚠️ **P0**

**问题**：宏观 5 因子的 `best/worst` 阈值（"友好分=100/0 分位"）都是**静态硬编码**，反映 2020-2023 的市场结构：

| 因子 | 阈值 | 2024-2026 实际市场 | 后果 |
|------|------|------------------|------|
| DXY 95/105 | DXY 在 2024-2025 已破 107 多次，2026 长期在 100-104 | 长期触顶（**DXY > 105 → friendly_score = 0**），宏观因子长期输出 0 |
| US10Y 3.5/4.5 | 2023 末至 2026 多次到 4.7%+ | 长期触顶 → friendly_score = 0，宏观偏空 |
| US30Y 4.0/5.0 | 2024-2026 长期 4.2-4.8% | 频繁触顶 → 信号失真 |
| VIX 25/12 | 2024-2026 VIX 长期 < 20（平静市） | 长期触底 → friendly_score 接近 0（**反向**：VIX 低 = 不避险 = 看空黄金，但代码逻辑"正相关"指 VIX 高 → 黄金利好，所以 VIX 低时黄金应该偏中性——这个解读是对的，但 25 这个阈值过高导致 VIX 永远在中性区下沿） |
| cb_gold 1200/500 吨/年 | 央行年购金 2022-2024 高位（>1000 吨），2025-2026 略回落 | 接近阈值上限，敏感度合理 |

**核心问题**：当某个因子长期输出 0 或 100 时，**加权后该因子的权重被「浪费」**——5 因子宏观权重变成「4 因子宏观权重 + 1 因子空权重」。

**建议**：阈值改为**滚动百分位**（`best = 近 252 个交易日 90 分位`，`worst = 10 分位`），用 `services/macro.py` 缓存计算，每日 07:00 BJT 随快照刷新。短期改造量：1-2 周。

### 3.3 技术面 5 维度的内部相关性 ⚠️ **P0**

**问题**：5 维度的算法（`services/trend.py:501-595`）有**严重的内部重叠**：

| 维度 | 算法 | 与其它维度的相关性 |
|------|------|------------------|
| **结构** | MA5/MA20/MA40 排列 + MA20 斜率 | 与动量 / 支撑 / 动能强相关 |
| **动量** | 近 20 日涨幅（mom20） | 与支撑（MA20 乖离）/ RSI 强相关 |
| **支撑** | 价格相对 MA20/MA40 的乖离 | 与结构（MA20 斜率）/ 动量（动量必然包含乖离）几乎等价 |
| **动能（RSI）** | RSI(14) | 与动量（涨跌幅度累积）相关 |
| **回撤** | 距区间高点 | **相对独立** |

**实测推论**（NY 金 60 日数据）：
- 当 MA20 斜率 > 0 时，结构 = 60-90，动量 = 60-90，支撑 = 60-90，RSI = 60-75 → **前 4 维度天然同向**。
- 加权后：`(结构+动量+支撑+动能) × 0.85 + 回撤 × 0.15` ≈ **趋势信号 × 4 + 反趋势信号 × 1**。
- 回撤维度的**风险提示**能力被严重稀释。

**建议**：技术面 5 维度重构为「3+1+1」组合：
- **趋势组**（动量 + 结构）→ 占 50%，组内平均
- **超买超卖组**（RSI + 乖离）→ 占 30%，组内平均
- **风险组**（回撤）→ 占 20%，独立加权
- 或者：**降维到 3 维度**：结构（MA 排列）/ 动量（mom20 + RSI 平均）/ 风险（回撤 + 乖离），权重重构为 0.40 / 0.30 / 0.30。

短期建议先**让用户能在回测引擎里扫技术面内部权重**（当前回测只能扫 tech/macro/news 三层），再根据扫描结果决定是重构还是微调。

**V0.79.0 Step F 验证结论**（2026-10-07，commits `45044f6` `020ab5e` `479bd32` `999decf`）：

- **实施状态**：采用上述「3+1+1」组合方案（趋势/超买/风险），代码已上线并默认开启：
  - 权重：`trend(结构+动量)=0.50` / `overbought(动能+支撑)=0.30` / `risk(回撤)=0.20`
  - `TrendService.combine_by_group()` 静态 helper：返回 `(group_scores, weights_norm)`
  - `TrendIndexOut.composed_by: Literal["weighted", "grouped"]`（仅技术面）
  - `GoldTrendOut/SilverTrendOut.tech_composed_by` 顶层字段透传
  - `WeightConfig.group_combine: bool = True`（可持久化，UI 在权重配置页切换）
- **回滚通道**：UI 或 `PUT /api/v1/settings/weights` 设 `group_combine=false` 即恢复历史行为，无需重启（除 60s 配置缓存外）。
- **实测对比**（合成数据，seed=42，100 样本）：
  - 单维度加权：avg_tech=49.40, hits=34/100 = 34.00%
  - 组内平均：  avg_tech=49.49, hits=33/100 = 33.00%
  - diff:       avg_tech=0.088, hits=1
  - **结论**：两种方法数学上不同（权重分布 0.25/0.25/0.15/0.15/0.20 vs 0.30/0.20/0.20/0.15/0.15），决策 hit_rate 仅差 1/100。
- **默认值保留**：`group_combine=true`（推荐方案 2）。理由：
  - 数学上消除「4 维趋势同向 + 1 维回撤」的结构性偏向；
  - 实证上未观察到 hit_rate 显著下降；
  - 趋势组/超买组/风险组权重大小符合「重要维度给权重，重要**组**也该给权重」的语义；
  - 用户切回路径简单（单 toggle），风险可控。
- **报告**：`docs/parameter-evaluation/sharpe_compare_2026-10-07.md`
- **后续观察**：待真实历史数据（≥ 60 个 tech_detail 完整快照；Step G #162 实测目前 16/24）二次验证。

### 3.4 决策矩阵的"档位缺位" ⚠️ **P1**

**问题**：`services/decision.py:139-159` 决策矩阵共 11 个硬编码阈值，但**没有一份文档说明为什么是这些数**。

矩阵里的不规则：
- 无持仓：`≥70 BUY high` / `≥55 BUY medium` / `≥45 WAIT low` / 其余 WAIT medium
- 有持仓：`pnl≥15 且 idx<60 → SELL` / `pnl≤-10 且 idx<40 → REDUCE` / `idx≥70 ADD` / `idx≥55 HOLD medium` / `idx≥45 HOLD low` / 其余 REDUCE medium

**缺位**：
- **`idx ∈ [55, 70)` 且无持仓**：`BUY medium` 触发，但仓位档位是 60%——若同时按 idx 推荐仓位与决策 BUY medium，实际操作 = 60% 仓位建仓，没有「低仓位试仓」选项
- **`idx ∈ [40, 45)` 且有持仓**：直接 `REDUCE medium`，没有「观望 HOLD」缓冲
- **`pnl_pct ∈ [-10, +15]` 且 idx ∈ [60, 70]`**：什么都不触发（HOLD 也不触发），属于"卡死区"

**建议**：决策矩阵改为**网格化**：`(idx 档位) × (pnl 档位) × (持仓状态) → action`，档位化便于回测扫描；同时把 BUY 拆为「BUY_LIGHT（30%） / BUY（60%） / BUY_HEAVY（80%）」3 档，让仓位档位与决策动作对齐。

### 3.5 共振信号 DIVERGENT 定义不完整 ⚠️ **P1**

**问题**：`services/resonance.py:89-95` 只识别 **tech vs macro 反向**，不识别 **tech vs news 反向**。

但根据 V0.66.0 复盘数据经验：
- 消息面打分 = 客户对投行展望的主观判断
- 当客户已经给 65 看多但技术还在 35 看空 → **消息面是反转先行指标**
- 当前共振信号会判定为 `neutral`（既不满足 strong 也不满足 divergent），**遗漏了一类重要的反转信号**

**建议**：DIVERGENT 扩展为「**任意两维反向且幅度 ≥ 15**」，并增加 `news_vs_macro`、`news_vs_tech` 两个子类。

---

### 3.6 回测盲区：技术/宏观内部权重不可调 ⚠️ **P1**

**问题**：回测引擎 `services/backtest.py` 的 `weight_grid` 只支持 tech/macro/news 三层组合，**不扫**：
- 技术面 5 维度内部权重（结构 / 动量 / 支撑 / 动能 / 回撤）
- 宏观 5 因子内部权重（DXY / US10Y / US30Y / VIX / cb_gold）

这意味着即使 3.3 / 3.4 / 3.5 提出的问题用户想"用回测找到最优"，也**回测不到**。

**建议**：扩展 `WeightGrid` schema 为**嵌套字典**（默认结构不变，开放内部权重扫描）：
```python
class WeightGrid(BaseModel):
    tech_macro_news: list[tuple[float, float, float]]  # 默认保留
    trend_5: list[dict[str, float]] | None              # 可选：5 维度内部
    macro_5: list[dict[str, float]] | None              # 可选：5 因子内部
```
短期用「**回测覆盖报告**」告诉用户"当前默认配置的 Sharpe 是 X，比 Y 配置低 Z%"，倒逼用户使用精细化扫描。

---

### 3.7 数据不足兜底的"中性=50"乐观化 ⚠️ **P2**

**问题**：多处数据不足时返回 `score=50`（中性），但用户看不到"这是默认值还是真实数据"：

| 位置 | 兜底 | 用户感知 |
|------|------|----------|
| `services/trend.py:611-614` 结构维度（< 40 个交易日） | 返回 50 | 看不出来 |
| `services/trend.py:195-196` RSI（< 14 根） | 返回 50 | 看不出来 |
| `services/trend.py:533` 动量（不足 21 根） | mom20 用首日兜底 | 看不出来 |
| `services/news.py:35` 消息面未打分 | NEUTRAL_SCORE=50（**V0.77.1 之前**，首页会显示 50 分） | **V0.77.1 已改为 `—` 占位** |

V0.77.1 已经修了消息面的兜底显示，但**技术面 5 维度内部仍输出"假中性 50"**。

**建议**：把兜底值改为 `null` + "数据不足"标签，由综合指数合成时按**已知维度数重新归一**（而不是把空维度当 50）。`Schema` 改为 `Optional[float]` 即可。

### 3.8 回测样本阈值过严 ⚠️ **P2**

**问题**：`_MIN_SAMPLES = 20`（`backtest.py:41` + `review.py:71` + `resonance.py:40`）三处硬编码。

金价大周期（央行政策转向 / 地缘危机 / 美元周期切换）可能半年才有一次有效的多空转换。**20 个样本 / 一个 horizon** 要求太严：
- 90 天回测 × 3 个 horizon = 270 个"判定样本"，但每个 horizon 的样本数只是 90 个（实际还要去掉起始 N 天无 T+N 价格的）→ ~85 个 / horizon
- 标签胜率分析按 12 个 basis 标签切片 → 每个标签平均 7 个样本 → **频繁触发"仅供参考"**

**建议**：分层样本阈值：
- **总体命中率**：`_MIN_SAMPLES = 10`（够统计显著性）
- **分维度分析**（按方向 / horizon / basis）：`_MIN_SAMPLES = 5`（标注「样本极少，仅供探索」）
- **显示规则**：当 `n < MIN` 时仍展示原始数，但加灰底小字「样本 N < 5，仅供参考」——比直接隐藏更有用

## 6. 评估方法论：怎么知道新值更好

> **核心原则**：所有"经验值"都必须经过 V0.71.0 回测引擎扫描后，**用数据说话**。本节给出三维交叉验证框架。

### 6.1 三维验证指标

| 维度 | 指标 | 计算 | 解读 |
|------|------|------|------|
| **收益性** | Sharpe Ratio | `mean(daily_pnl) / std × √252` | > 1.0 算「可接受」，> 1.5 算「良好」，> 2.0 算「优秀」 |
| **风险性** | 最大回撤 | `max(peak - trough) / peak` | < 10% 算「低风险」，10-20% 「中风险」，> 20% 「高风险」 |
| **稳定性** | 命中率 + 校准分箱 | T+1/T+3/T+5 三个 horizon 的命中数 / 总数；5 桶校准偏离斜率 | 命中率 > 55% 算「优于随机」，校准分箱偏离 < 10% 算「概率可信」 |

### 6.2 评估步骤（任一参数改进的标准化流程）

1. **基线快照**：记录改进前的 Sharpe / 最大回撤 / 命中率 / 校准分箱（用近 252 个交易日数据）
2. **参数替换**：实施新参数
3. **回测扫描**：用 `POST /api/v1/backtest/run` 在相同数据窗口上对比
4. **三指标对比**：新值是否在 Sharpe 上有 > 10% 提升？最大回撤是否未恶化？命中率是否提升？
5. **滚动窗口验证**：把窗口切成 4 个 63 日子窗口，看新参数是否**在 4 个子窗口都优于基线**（防止过拟合）
6. **实盘小流量验证**：新参数先在「模拟交易」（P3 #13 未做）跑 30 天，再切主路径

### 6.3 防止过拟合的三条纪律

- **回测覆盖期 ≥ 252 日**：覆盖至少一个完整的金价波动周期（牛市 / 熊市 / 震荡各一段）
- **样本外验证**：留 30% 数据不参与扫描，仅作最终验证
- **不扫超过 5 个参数同时调整**：每版只调整 1-2 个参数，确认有效后再叠加——**单变量因果链**
