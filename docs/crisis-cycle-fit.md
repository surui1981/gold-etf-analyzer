# 经济危机金价拟合曲线（V0.128.0）· 口径真源

> ⚠⚠⚠ **这不是预测、不是统计回归、不是目标价。**
> 它是「**历史形态参照 + 情景假设**」：把历史危机周期按「距金价阶段高点月数」对齐、
> 以高点归一为 100、逐月**等权平均**成一条模板，再按当前周期所处的位置缩放
> （拟合线精确穿过当前点），最后外推未来 N 个月。
>
> **与 V0.127.0 的金价区间扇形图方向性相反**：扇形图刻意「不预测涨跌」（中心恒等于最新收盘价），
> 本功能**有方向** ⇒ 两者**不画在同一个面板里**，页面上也互相不引用为「升级版」。

---

## 一、接口

```
GET /api/v1/forecast/crisis-fit?target=ny&horizon=30&drift=0.003
```

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `target` | `ny` | `ny` / `etf` / `gram` | 标的；**产物带标的护栏** —— 别的标的拿不到 ny 的周期证据 |
| `horizon` | **`30`（固定）** | 6–60 | 外推月数 —— **用户 2026-11-19 确认「拟合的外推形态是 30 个月」** ⇒ 前端固定请求 `horizon=30`，产物也声明 `horizon_months=30`（**loader 有护栏**：两者不一致就不加载产物 ⇒ 口径不会漂） |
| `drift` | `0.003` | −0.02 … 0.02 | **每月漂移假设（研究示意参数）** |

**响应里必须同时给出 `endpoint`（drift=假设值）与 `endpoint_drift0`（drift=0）** ——
drift 是假设，不是结论，页面永远把两者并列。

## 二、算法（逐条，可复核）

| 步骤 | 口径 | 代码位置 |
|---|---|---|
| ① 月聚合 | 日线按自然月取**均价**（不是月末价） | `aggregate_months()` |
| ② 锚点 | **日线最高收盘价所在月**；价格锚 = 该月的月均价 | `peak_daily()` / `anchor_month_from_days()` |
| ③ 对齐 | 每轮周期以它的金价阶段高点月为 `t=0`，高点价归一为 **100**；只取 `t ≥ 0` | `build_template()` |
| ④ 平均 | 逐月**等权**平均（缺一轮就少一轮，**不补 0**）；同时记录每个 `t` 由几轮支撑 | `build_template()` |
| ⑤ 插值 | 线性插值，**端点 clamp**（模板之外取端值，不外推斜率） | `make_interpolator()` |
| ⑥ 定位 | `t0` = 锚点月 → 末月的月数；`curNorm` = 末月均价 ÷ 锚点均价 × 100 | `_fit_once()` |
| ⑦ 缩放 | `scale = curNorm ÷ 模板(t0)` ⇒ 拟合线**精确穿过当前点**（不重新拟合历史） | `_fit_once()` |
| ⑧ 外推 | `norm(t) = 模板(t) × scale × (1+drift)^(t−t0)`；`price(t) = 锚点月均价 × norm(t) ÷ 100` | `_fit_once()` |
| ⑨ 离散度 | 每轮周期用自己的路径外推到 `t0+horizon` ⇒ 终点区间（**不是置信区间**） | `_fit_once()` |

> ⚠ **模板只覆盖到各轮周期结束的那几个月**；之后是插值器的**平台外推** ——
> 那里没有历史信息。接口给出 `template_max_t` 与 `template_counts`，
> 页面必须把这条边界画出来（图注 + 支撑轮数）。

## 二·补 · 拟合集与参照集（V0.128.1 / V0.128.2）

### 2.0 ★ 拟合集 = **显式指定**的两轮（V0.128.2，当前口径）

用户 2026-11-19 拍板：「**我要 2000 年互联网和 2008 年房地产危机的黄金价格走势的拟合**，
**2000 年以前的黄金价格变动更没有参考性**」⇒ 拟合集**不再自动挑选**，而是显式指定：

| 锚点 | 名称 | 峰价 | 为什么是这个锚点 |
|---|---|---|---|
| `1999-10` | 2000 互联网泡沫 | 310.72 | 金价**泡沫前夜**的局部高点 —— ⚠ **不是**泡沫顶点（2000-03）：金价在泡沫破裂时**没有破裂特征**（2000-03 → 2001-04 横盘 12 个月，274→300→260）。用金价高点做锚点才与 2008 轮**同口径** |
| `2008-03` | 2008 房地产危机 | 968.43 | 危机中金价的高点（雷曼前 6 个月） |

⇒ 两轮形状可比（都先跌 13–15% 再涨）⇒ 模板 = 两者等权平均。
⇒ 生成脚本 `--fit-anchors` **校验锚点必须是合法局部高点**（手滑写错月份直接报错）。
⇒ 产物声明 `fit_anchors` + `fit_selection="explicit"`。

### 2.1 ★ 参照集（7 轮，全部**不参与**等权平均）

| 类别 | 轮次 | 画法 | 为什么参考性低 |
|---|---|---|---|
| 2000 年以前 | 1969-05 / 1974-12 / 1980-01 / 1983-02 / 1990-02 | **虚线** + 淡色 | 固定汇率/布雷顿森林体系下金价被**行政管制** ⇒ 形态与现代市场不可直接类比（用户口径：「更没有参考性」） |
| 2000 年后未入选 | 2006-05 / 2011-09 | 实线 | 是现代市场，只是**没被选中** ⇒ 对照用 |

### 2.2 ⚠️ 外推长度固定 **30 个月**（用户 2026-11-19 确认）

外推**就是 30 个月**（不是「模板能支撑多久」来决定）⇒ 接受「最后 10 个月在平台外推区」
这个事实，并用两条常驻告警把它讲清楚，而不是把外推偷偷缩短。

### 2.3 ⚠️ 收窄的真实代价（必须让用户看见）

拟合集只剩 2 轮 ⇒ 模板覆盖与支撑都变薄：

| 模板的 t | 支撑轮数 | 说明 |
|---|---|---|
| 0 – 17 | **2** | 两轮都在 |
| 18 – 30 | **1** | 2008 轮的序列只到 t=17（2009-08 收复高点） |
| 31 及以后 | — | **平台外推**（模板只到 t=30） |

⇒ 当前点 t0=10、终点 t=40 ⇒ **最后 10 个月全是平台外推** ⇒ 接口给
`endpoint_beyond_template=true` ⇒ 页面**常驻告警**：
「这个终点不是形态参照出来的，只是把模板最后的形状拉平再乘漂移」。

## 二·补二 · 拟合窗口与参照集（V0.128.1 初版，已被 2.0 取代）

用户 2026-11-18 拍板：**「拟合只用 2000 年到现在的几次金价破裂周期，其他周期放到别的图表显示」**。

| 集合 | 产物字段 | 内容 | 用途 |
|---|---|---|---|
| **拟合集** | `cycles` | **2006-05 / 2008-03 / 2011-09**（3 轮） | **进等权平均** ⇒ 模板本体 |
| **参照集** | `reference_cycles` | **1969-05 / 1974-12 / 1980-01 / 1983-02 / 1990-02 / 1999-10**（6 轮） | **只展示**（页面第三张图），**不进模板** |

- 窗口由产物的 `fit_window` / `reference_window` 声明，接口原样透出，页面图注写明。
- 「金价破裂」的阈值 = 高点后 36 个月内回撤 ≥ **10%**（V0.128.0 时是 15%）。
  ⚠ 2000 年以后没有真正的熊市（2006 −13%、2008 −21%、2011 −31%）⇒ 15% 会把现代周期
  **只剩 2 轮**（不够拟合）⇒ 放宽到 10% 才凑出 3 轮。

### ⚠️ 收窄的真实代价（必须让用户看见）

3 轮里有 2 轮**很快就收复**（2006 那轮 11 个月、2008 那轮 18 个月）⇒

| 模板的 t | 支撑轮数 |
|---|---|
| 0 – 10 | **3**（全部拟合周期） |
| 11 – 17 | **2** |
| 18 及以后 | **1**（只剩 2011 那一轮） |

⇒ **当前的外推终点（t0+horizon = 40）落在「1 轮支撑」区** ⇒ 长程外推几乎等于
「2011 那一轮之后怎么走」，**不是「几轮的平均」**。
⇒ 接口给 `support_at_horizon`；页面在 ≤1 时**常驻告警**（不折叠、不隐藏）。

## 三、产物（历史危机周期）· 数据来源与格式契约

### 3.0 ✅ 本仓库的实际数据（**已入库**，不是待办）

| 项 | 值 |
|---|---|
| 来源 | **世界银行 Pink Sheet**（Commodity Price Data）月度表 `Gold` 列（$/troy oz，**London fix 月均**） |
| 链接 | `https://thedocs.worldbank.org/en/doc/5d903e848db1d1b83e0ec8f744e55570-0350012021/related/CMO-Historical-Data-Monthly.xlsx` |
| 覆盖 | **1960-01 → 2024-12**（780 个月；表内更新日 2025-01-03） |
| 生成脚本 | `scripts/build_crisis_cycles.py`（**可复现**：联网抓 / `--offline <xlsx>` 离线复算） |
| 选出的周期 | **8 轮**：1969-05 / **1974-12** / **1980-01** / 1983-02 / 1990-02 / 1999-10 / 2008-03 / **2011-09** |
| 周期选取规则 | ① 局部高点（±6 月窗口内最高）② prominence ≥ 10% ③ 同 episode（相隔 < 18 月）取更高者 ④ 高点后 36 月内回撤 ≥ 15% ⑤ 整体早于当前周期起点（2016-11）—— **无人工挑选** |

⚠ **口径差异（必须知道）**：模板用**伦敦现货**，当前周期用仓库自己的 **COMEX 期货**
（`gold_price_daily` / `target='ny'`）⇒ **绝对价位不可比、归一后的形状可比**
（算法对每轮周期各自归一，模板只贡献形状）⇒ 产物 `provenance.note` 里写明了这一点。

⚠ 为什么不用东财的 COMEX 日线（`push2his`）做模板：它只到 **1990-01** ⇒ 拿不到 1974 / 1980。

### 3.1 格式契约（人工/外部导出的数据按这个格式）

**位置**：`src/app/assets/forecast/crisis_cycles.json`（**必须进版本库** —— `data/` 被 gitignore）。

```json
{
  "schema_version": 1,
  "target": "ny",
  "horizon_months": 30,
  "price_basis": "monthly_average",
  "provenance": {
    "source": "<数据源名>",
    "url": "<可核的链接>",
    "coverage": "<覆盖区间>",
    "method": "<口径：月末价还是月均价、是否通胀调整、汇率口径>",
    "exported_at": "<YYYY-MM-DD>"
  },
  "cycles": [
    {
      "name": "1974-1980 滞胀危机",
      "short": "1974",
      "goldPeak": "1974-08",
      "peakPrice": 850.0,
      "series": [["1974-01", 175.0], ["1974-02", 180.0]]
    }
  ]
}
```

**两批周期（V0.128.1）**：`cycles` = 拟合集（`fit_window` 内）、`reference_cycles` = 参照集
（`fit_window` 之前，只展示不进模板）—— 两批都过同一套校验。

**校验规则（不合规 ⇒ 剔除并告警，绝不静默修补）**：

| # | 规则 | 不合规的后果 |
|---|---|---|
| 1 | `series` 按月升序、**连续**（不跳月） | 剔除该周期（跳月会让「距高点月数」错位 ⇒ 整条模板失真） |
| 2 | `goldPeak` 必须在 `series` 里 | 剔除（归一化靠它） |
| 3 | `goldPeak` 必须是该周期**价格最高的月** | 剔除（对齐原点错了 ⇒ 形状全错） |
| 4 | 价格为有限正数 | 剔除 |
| 5 | **不得与当前周期月份重叠** | 剔除（自我拟合 ⇒ 证据门 E3） |
| 6 | 有效周期数 ≥ **3** | 否则整个产物 `available=false`（等权均值 ≈ 单轮） |

⇒ 被剔除的周期与原因会出现在接口的 `warnings` 里，页面显示出来。

## 四、已知失效条件（页面常驻，不是折叠里的脚注）

1. **等权平均不是加权最优** —— 2008 年后 QE 时代的大牛市周期会整体抬高模板 ⇒ 结论**偏乐观**；
   样本只有几轮时，一条周期就能左右结果。
2. **锚点决定一切** —— 当前金价若就在高位，`t0` 很小 ⇒ 模板最早期主导 ⇒ 锚点换一个月结论可能差很多
   ⇒ 接口给出 `sensitivity`（锚点 ±1 月的终点区间），页面必须显示。
3. **模板之外没有信息** —— 见 §二 的 clamp 边界。
4. **drift 是假设不是结论** —— 默认 +0.3%/月只是研究示意参数 ⇒ 页面永远并列 drift=0 的终点。
5. **周期样本本身有选择偏差** —— 哪些危机算作「周期」由人决定；换一批周期，模板就会变。

## 五、证据门（每条都做过**反向验证**：撤销 ⇒ 必须变红）

| # | 断言 | 在哪验 |
|---|---|---|
| **E1** | 无前视：只用 ≤ 末月的日线 | `tests/test_services/test_crisis_cycle_fit.py` |
| **E2** | 锚点 = 日线最高收盘价所在月 | 同上 + API 用例 |
| **E3** | 当前周期不进模板（月份重叠 ⇒ 剔除并告警） | 同上 |
| **E4** | 曲线起点 = 当前点（隐含价 == 末月均价） | 同上 + API 用例 |
| **E5** | 锚点 ±1 月的终点敏感度能算出来并显示 | 同上 + 浏览器门禁 |
| **E6** | drift=0 对照永远在（后端给 + 前端显示） | API 用例 + 浏览器门禁 |
| **E7** | 无产物 ⇒ `available=false` + 明确 reason；页面显示「待数据」且**不画曲线** | API 用例 + 浏览器门禁 |
| **E8** | 形态拟合页不含扇形图；扇形图页不含形态拟合曲线 | 浏览器门禁 |
| **E9** | **模板只由拟合集构成**（参照集绝不混进等权平均） | **API 用例**（浏览器门禁 mock 了接口 ⇒ 后端混进去它看不见，实测踩过） |
| **E10** | **外推终点的支撑轮数必须报出来**（薄了页面要能告警） | API 用例 + 浏览器门禁 |

⚠ **浏览器门禁打的是「活着的服务」** ⇒ **改了后端必须先重启服务再跑门禁**，
否则门禁验的是旧进程里的代码（实测踩过：反向验证时没重启 ⇒ 门禁照样全绿）。
