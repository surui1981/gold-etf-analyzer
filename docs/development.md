## 10. 版本历史

> ⚠️ **下表「日期」为提交日期，不是标签创建日期 —— 两者在历史上并不总是同一天。**
> 2026-10-03 的全量标签审计（39 个标签的对象 SHA 与剥离提交 SHA 同远程逐一双向对账，**39/39 全等**）确认两点：① **11 个标签是事后批量补打** —— v0.53.0–v0.60.0 共 8 个于 2026-09-12 一次性补齐、v0.67.0–v0.69.0 补于 09-19、v0.70.0–v0.73.0 补于 09-23，故这些版本的**真实发布时刻在 Git 中已不可考**（只有提交时刻可靠）；**自 v0.74.0 起已规范**，每个标签都在对应提交后 1 分钟内创建。② `v0.74.0` 与 `v0.75.1` 两个标签**指向晚于「版本号首现」的提交**，其中 v0.75.1 为**有据可查的有意重发**（该提交信息即写明「修复 V0.75.0/V0.75.1 发布链路中断（重发 v0.75.1 标签）」）。
> 结论：**不影响版本归属**（39 个标签内声明的版本号与标签名全部相符），**只影响「取到哪一刻的代码」** —— 例如 `git checkout v0.74.0` 取到的是「V0.74.0 + 8 个后续修复」而非发布当刻快照。完整说明与审计方法见 `README.md` 的「版本历程」节。

## 12. 备注

- 本应用输出为**研究参考**，不构成投资建议。
- 权重与阈值为典型经验值（rule-based），随数据积累逐步用回测校准。
- 数据来源：AKShare（东方财富 / 新浪财经 / 上海黄金交易所 / 英为财情 / 中债收益率）+ WGC Gold Demand Trends（央行购金月度统计，HTML chart JS 自动抓取），第三方接口可能变化，已做降级容错。
- **认证能力边界（V0.75.0）**：本版为**认证骨架**，`AUTH_ENABLED` 默认 `false`（单用户模式，与 V0.74.3 行为一致）。开启后具备凭证校验、服务端会话、CSRF 与权限守卫，但**业务表尚未按用户隔离** —— 数据隔离（V0.75.2）与找回密码 / 用户管理（V0.75.3）在后续两个版本落地。生产启用前请务必同时设置 `SESSION_COOKIE_SECURE=true` 与 `TRUST_PROXY_HEADERS=true`（反代场景）。
- **结论卡可信度边界（V0.75.1）**：结论卡展示的「宏观参考」维度中，`美元指数` / `美债10Y收益率` / `美债30Y收益率` / `VIX恐慌指数` 四项来自**静态参考值**（非实时行情），且行情源降级时可能整源为演示(Mock)数据 —— 卡片**不会隐藏这两点**，而是在「数据质量」区如实标注项数、名称与最新数据日，供使用者自行折减对结论的置信度。`position_ratio` 恒为 `0`，故卡片只显示持仓状态（空仓 / 持有 N 份），**不给出仓位占比**。
- **消息面写接口的字段更新语义不对称（V0.76.0 实测澄清）**：`PUT /api/v1/news-score` 是**全量 upsert**，但仓库层 `repositories/news.py::upsert` 的 UPDATE 分支对三个文本字段处理不同 —— `notes` 与 `basis` 是**硬覆盖**（不带就清空），`review_note` 写的是 `review_note or existing.review_note`（**空值保留旧值，因此无法通过 API 清空已写的复盘批注**，注释称「复盘批注可就地补充，不必重打分数」）。任何前端在「修改既有槽位」时都**必须把 `notes` / `basis` / `review_note` 一并回填并回传**（首页打分器已按此实现）。⚠️ 若要支持「清空批注」，需先改仓库层的 `or` 语义，**改前端 textarea 是没用的**。
