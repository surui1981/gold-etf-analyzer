**日期**：2026-10-10
**roadmap 引用**：§4.1 M · P1
**范围**：纯前端（HTML + 1 个新 JS + 3 个 gate 脚本）

## 背景

V0.83 commit 3 把 trend.html 的双行 nav 模板复制粘贴到 silver/portfolio/weights/trades/backtest/data-health/central_bank/review 8 个页面 —— 每页约 2000 字符的 nav markup（`<nav class="topnav">` + 11 个 `<a>` + brand + freshnessInline + warn-toggle），合计约 16KB 重复 + drift 风险：

- 每次新增 / 删除一个页面或链接，要改 8 处
- i18n `data-i18n` 属性散在 8 个 HTML，zh-TW 漏补的风险成倍上升
- brand 文案 / emoji 微调要 8 遍改

V0.83.1 已修复 110 个 i18n 预存 gap；V0.83.0 plan §"不在本 PR" 第 1 条就标注「共享 topnav JS 注入重构 — 留作独立 ticket」。本 commit 兑现这个 ticket。

## 改动

### 1. 新增 `static/topnav.js`（**111 行，~4.2KB**）

单一来源的 nav 配置 + 同步注入脚本：

- **11 条 `NAV_LINKS` 配置**：每条带 `path` / `activeFor` / `ico` / `i18n` / `fb`（zh-CN 兜底）
- **4 个特殊 `BRAND_BY_PATH`**（silver / backtest / data-health / settings）+ `DEFAULT_BRAND`（黄金主页）
- **同步注入**：script 紧跟 `<div id="topnav-mount">` placeholder，无 `defer` / `async`，用 `outerHTML` 替换 placeholder，body 还没解析到 main 内容前完成 → **零 FOUC**
- **active 自动判定**：`l.activeFor.indexOf(location.pathname) >= 0`
- **i18n 走原 `data-i18n` 协议**：注入的 nav 元素带 `data-i18n="nav.trend"` 等属性，i18n.js（defer）按既有流程翻译

### 2. 8 页面 nav 块替换

每页 ~2000 字符的 `<nav class="topnav">…</nav>` 整块替换为：

```html
<div id="topnav-mount"></div>
<script src="/static/topnav.js"></script>
```

**25 字符 / 页**（vs 之前 2000+），合计 **-16KB HTML 体积**。

涉及页面：silver / portfolio / weights / trades / backtest / data-health / central_bank / review。

### 3. 门禁脚本同步

- **`scripts/check_cluster_render.mjs`** V0.83 节重写：旧的「央行页 topnav 12 个 a」内联 markup 断言不再适用，改为：
  - `<div id="topnav-mount">` placeholder 存在
  - `<script src="/static/topnav.js">` 同步注入
  - 旧 `<nav class="topnav">` 内联 markup 已移除
  - `topnav.js` 含 11 条 `NAV_LINKS` 配置（按 `path: "` 字面计数）
- **`scripts/check_i18n_keys.py`** 加 JS 字面扫描：`r'i18n:\s*["\']([A-Za-z0-9_.\-]+)["\']'` 抓 `topnav.js` 里的 `i18n: "nav.trend"` 等。否则 nav.*/brand.* key 被门禁漏检，删除 / 重命名仍会通过 gate。
- **`scripts/puppeteer_v083.mjs`** 间隔 2.5s → 3.5s：dev server 5 req/s 限流，portfolio.html 在 2.5s 间隔下仍 19/72 偶发 429（已多次重跑验证是 rate-limit 而非逻辑问题），3.5s 间隔下 1418/0 稳定。

## 关键 bug 修复

### `activeFor` 数组 —— 解决 FastAPI redirect 后 active 失效

第一次写时用 `l.path === activePath` 严格匹配，但实际：

- 用户点 `/portfolio` 链接
- FastAPI 重定向到 `/static/portfolio.html`
- `location.pathname` 是 `/static/portfolio.html`
- link.path 是 `/portfolio` → 不匹配 → active 丢失

修复：每条 link 显式列 `activeFor`：

```js
{ path: "/portfolio",
  activeFor: ["/portfolio", "/static/portfolio.html"],
  ico: "💼", i18n: "nav.portfolio", fb: "持仓与决策" }
```

判定 `l.activeFor.indexOf(path) >= 0`。所有 redirect 后的 7 条 link 都有两个形态。

## i18n 增量

**0**。`nav.*` / `brand.*` keys 在 V0.83.0 commit 3 迁移时已 3 语全覆盖；V0.83.1 又扫过一遍；V0.83.2 抽离后这批 keys 仍完整。本 commit 不新增任何 i18n 字面。

但 `check_i18n_keys.py` 加 JS 扫描后，**这批 keys 第一次被门禁强制覆盖检查**——之前 HTML data-i18n 扫描能抓 HTML 模板引用，topnav.js 是新引入的 JS 字面引用源，gate 必须跟上才能继续起作用。
