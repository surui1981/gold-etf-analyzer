# V0.114.1 · 修全站 favicon 404

> 日期：2026-10-22 ｜ 类型：hotfix ｜ 无 UI 布局变更
>
> 一句话：21 个页面曾全部不声明 `rel="icon"`，根路径也没有 `/favicon.ico` 路由 ——
> 每次访问必产生一个 404。

## Context

V0.114.0 的 puppeteer 实跑里，`/favicon.ico` 的 404 一直躺在「豁免清单」里。
当时的判断是「全站性既存项、纯装饰、不在本轮范围」，于是豁免掉了。

但豁免存在过本身就是它坏了的证据 —— 一旦豁免留在脚本里，下次真出问题时它会自动
被一起豁免掉。所以单开一轮修。

## 根因

浏览器约定 favicon 在**站点根** `/favicon.ico`。而本项目：

- `StaticFiles` 只挂在 `/static/` 下 ⇒ `/favicon.ico` 无路由
- 21 个页面**全部**没有 `<link rel="icon">` ⇒ 浏览器只能去根路径找
- 20 个页面引了 `rel="manifest"`，但 **manifest 的 icons 不做标签页 favicon**
  （那是 PWA 安装图标）⇒ 引了 manifest 也照样 404

`static/icon-192.png` 早就在仓库里（413 字节，被 manifest 与 SW `SHELL_ASSETS`
引用），**不需要新造任何资源**。

## 改动

### ① 21 个页面补 `<link rel="icon">`

统一插在 `<link rel="manifest" href="/static/manifest.json">` 之后（20 页）；
`static/offline.html` 无 manifest 行（SW 离线兜底页刻意保持最小 head），
在 `<meta name="theme-color">` 后单列一行并注明原因。

```html
<link rel="icon" href="/static/icon-192.png" type="image/png">
```

`type="image/png"` 如实写 —— 媒体类型要与实际字节一致，撒谎会让部分浏览器
拒绝解析（所以门禁会查这一项）。

### ② 根作用域 `/favicon.ico` 路由

`src/app/main.py` 新增路由，理由与既有的 `/sw.js` 完全相同（StaticFiles mount
默认只覆盖 `/static/`，而浏览器约定在根找）。

兜的是仍会打这个路径的情况：旧书签、收藏夹、PWA 安装前的首屏，以及不解析 link
标签的客户端（curl / 抓取器）。

⚠️ 返回的是 192px **PNG** 而不是真多尺寸 `.ico`。实测全站 404 才是真问题，补一个
真 ico 纯属锦上添花，收益/维护成本不成比例 —— 但 `content_type` 如实写 `image/png`，
不撒谎。

### ③ 门禁补第 4 项检查

`scripts/check_pwa_assets.py` 从 3 项检查扩到 4 项：扫描 `static/*.html`，每页必须有
`rel="icon"`、href 必须指向真实文件、`.png` 必须带 `type="image/png"`。

⚠️ **诚实记录反向验证的结果**：我试过「删掉某页的 rel=icon，看新门禁会不会红」——
**会红**（门禁有效）。但试过「删掉某页的 rel=icon，看浏览器还会不会 404」——
**不会**，因为根路由兜住了。

也就是说 ② 是真正止血的那层，① 是声明式加固（省一次根路径往返 + 路由被 nginx 改写
时仍有效）。两条都留着是有意的分层，不是冗余。

### ④ `check_routes.py` 登记 `/favicon.ico` → 200

门禁自己报的：`在 FastAPI 路由表里但未登记在 EXPECTED_STATUS`。路由数 19 → 20。

### ⑤ 验证脚本**删掉**豁免

`scripts/_verify_multi_source.mjs` 原先豁免 `/favicon.ico`，现在直接删掉，
并把 `page.on("response")` 里的 4xx 也计入断言。新增 5 条 favicon 断言
（声明存在 / type 如实 / 图标可取 / 根路径 200 / Content-Type 与字节一致）。

## 教训

**豁免清单会自我腐化。** 一个「已知无害所以豁免」的 404，一旦留在验证脚本里，
下一次真的出现同类 4xx 时它会跟着一起被跳过 —— 门禁从此对这一类问题失明，而且
没人会注意到。

豁免要么限时修掉，要么写进注释说明**为什么**无害、以及**什么条件下**必须重新启用。
本轮之前那条只有一句「与本轮无关」，没有失效条件，所以它实际是在永久放行。

## 不做

- ❌ 不生成真多尺寸 `favicon.ico`（收益/维护成本不成比例，见上）
- ❌ 不改 `apple-touch-icon` —— 20 页已有一致写法，缺的那几页是既存差异，
  与 favicon 404 无关，不在本轮扩散
