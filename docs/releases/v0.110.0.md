# V0.110.0 · 宏观因子手动校准 + docs 整理

> 发版日期：2026-10-21
> 前置：V0.109.2（白银页面数据时效透明化）
> 性质：功能 + 文档整理

## 一句话

宏观面 5 个因子里 `dxy` / `vix` **没有自动实时源**，用的是 `STATIC_REF` 里
**2026-08-28 的硬编码常量**（96.5 / 18.5）—— 相当于**综合趋势指数的 16% 建立在两个
半月前的常量上**，而 UI 上完全看不出来。现在可以在 `/weights` 页直接录入当日真实读数。

---

## 根因

`src/app/services/macro.py:82-91`：

```python
STATIC_REF: dict[str, dict] = {
    "dxy": {"value": 96.5, "date": "2026-08-28", "note": "静态参考值"},
    "vix": {"value": 18.5, "date": "2026-08-28", "note": "静态参考值"},
    ...
}
```

权重账：

| 层级 | 权重 |
|------|------|
| `dxy` 0.25 + `vix` 0.15（宏观面内部） | 0.40 |
| 宏观面占综合指数 | 0.40 |
| **合计** | **综合指数的 16%** |

`us10y` / `us30y` 虽然有美联储 H.15 自动源，但上游失败时静默回退到同样的过期常量，
且只有一行 `logger.warning` —— 用户侧同样看不出来。

---

## 改法

### 1 · 存储：`macro_factor_overrides` key

复用既有的 `app_settings` KV 表（`WeightService` 已注入 `SettingRepository`），
**新增独立 key**，不与 `weight_config` 混存 —— 避免保存权重时把覆盖一起冲掉。

```python
class MacroFactorOverride(BaseModel):
    value: float          # 覆盖值（点位 / % / 吨每年）
    as_of: date           # 该读数对应的交易日；用于算滞后
    note: str | None      # 备注（如数据来源）

class MacroFactorOverrideSet(BaseModel):
    dxy / us10y / us30y / vix / cb_gold: MacroFactorOverride | None
```

`as_of` 设成**必填**：没有日期就算不出滞后，也无法向用户披露时效 —— 这正是
V0.109.2 白银页面踩过的坑（数据是哪天的看不出来）。

### 2 · 优先级链

`_collect()` 从"静态常量 → 自动源"改成**用户覆盖优先**：

```
用户手动覆盖  >  自动源（央行购金表 / 美联储 H.15）  >  STATIC_REF 内置常量
```

覆盖优先级最高的设计理由：用户从行情终端抄进来的当日读数，在任何情况下都比
两个半月前的常量新。覆盖的 `as_of` 原样写进 `MacroFactorOut.data_date`，
`source` 标为「手动输入」—— **前端按来源决定是否显示滞后 chip**，服务端不做静默过期。

### 3 · 端点

| Method | Path | 鉴权 |
|--------|------|------|
| GET | `/api/v1/settings/macro-overrides` | 公开（与 `/settings/weights` 同口径） |
| PUT | `/api/v1/settings/macro-overrides` | `require_admin_session` |

整体替换语义：传全 `null` 即清除全部覆盖。

### 4 · UI：`/weights` 新增「宏观因子手动校准」卡片

5 行（因子 / 当前生效 / 手动值 / 数据日期 / 备注 / 清除），其中「当前生效」列
直接复用 `loadTrendForPreview()` 已经拉取的 `gold/trend` 响应里的 `macro.factors[]`
—— **不新增请求**。

- `source === "手动输入"` → 该行高亮 + 「手动输入」chip
- 滞后 > 1 交易日 → 琥珀 chip「滞后 N 天」
- 「清除全部覆盖」走**二次确认弹窗**（与 `/weights` 既有的 `confirmDialog` 复用）：
  清除会让 DXY / VIX 退回 2026-08-28 的常量，综合指数会变，不能一次误点就生效
- i18n 22 个 key × 3 语

### 5 · 保存即失效缓存

```python
saved = await service.save_macro_overrides(payload)
clear_macro_cache()                        # MacroFactorService._CACHE，600s
TrendService.invalidate_cached_results()   # served_cache，600s，在上一层之上
```

**两层都要清。** 这一点是 puppeteer 实跑才暴露的（见下「验证期修掉的 3 个缺陷」），
初版只清了 `MacroFactorService._CACHE`，实测覆盖已落库、`GET /market/gold/trend`
仍返回 `dxy 96.5 · 2026-08-28` —— 页面提示"已保存"而数值纹丝不动，日志无异常。

## 验证期修掉的 3 个缺陷

按项目惯例，改完 `static/weights.html` 必须 puppeteer 实跑（见记忆
`frontend-undefined-rendering`：模板字符串字段名不一致会静默渲染 undefined，
静态检查一律抓不到）。`scripts/_verify_macro_override.mjs` 15 项断言，逐一暴露：

### ① `served_cache` 漏清 —— 功能等于没做（本版最严重的那个）

`TrendService.analyze()` 在 `MacroFactorService` **之上**还有一层 `served_cache`
（`services/cache.py`，TTL = `served_cache_ttl_seconds`，默认 600s）。只清前者时，
`/market/gold/trend` 从 served_cache 回放覆盖前的响应。

**顺带修掉一个既有缺陷**：`PUT /settings/weights` 原先一个缓存都不清，
改完权重后首页最长 10 分钟仍显示旧指数。

新增 `TrendService.invalidate_cached_results()`（原 `invalidate_for_news`
改为转发别名 —— 名字带 news 但现在两条写入路径都调它，不改名会说谎），
`TrendService.invalidate_cached_results()` 文档串里列明三条调用路径。

回归锁：`tests/test_api/test_settings.py` +2，两条都验证过**去掉修复即 FAIL**。

### ② 重渲染冲掉用户正在输入的值 —— 静默提交空值

`renderOverrides()` 整块替换 `#moRows` 的 innerHTML，输入框 value 按 `overrideState`
重新生成。而首屏 `loadOverrides()` 与 `loadTrendForPreview()` **并发在飞**，
冷启动下后者要现拉 60 根 K 线（实测数秒）。用户在这段时间填的 dxy 一旦被迟到的
`loadOverrides()` 冲掉，点击保存提交的就是全 null —— **表现为"我明明填了却没生效"，
且一次覆盖全被清空**。实测复现：保存后提示"已保存"，数值却回到静态常量。

修法：重渲染前用 `snapshotUserEdits()` 捞出"与 `overrideState` 不一致的字段"，
渲染后 `restoreUserEdits()` 写回。保存成功后 base 已更新，快照自然为空，不干扰正常路径。

### ③ 备注输入框漏 class，整行折行

`<input type="text" id="mo_${key}_n">` 少了 `class="mo-note"`，导致
`.mo-row .mo-note { width: 132px }` 整条 CSS 失效，字段退回浏览器默认宽度，
累加后超过卡片宽度 → 「清除」按钮被挤到第二行，**5 行全是折的**。

> 断言本身也踩了一次坑：初版按 `getBoundingClientRect().top` 判折行，
> 而 `.mo-row` 是 `align-items:center`，同行元素高度不同 → top 本就各不相同，
> 于是把"1 行"误报成"4 行"。改判**垂直中心**后正确。

### 另：冷启动显示「暂无读数」

`macroFactors` 尚未填充时列显示「暂无读数」，会被读成"因子丢了"。新增
`macroFactorState`（loading / ready / failed），加载期间显示中性「加载中…」，
失败才落「暂无读数」—— 与 `freshness-degrade-ux` 的原则一致。

## 设计取舍

| 决策 | 理由 |
|------|------|
| 覆盖**不设过期**（填了就一直生效） | 服务端静默过期会造成"我明明填了却没生效"的困惑；改为前端显式提示滞后天数，把判断权交给用户 |
| 覆盖**不做有效期**，但**显示滞后 chip** | 同上。滞后透明度 > 自动失效 |
| `as_of` **必填** | 算不出滞后就无法披露时效；可选字段会被前端"忘了传" |
| 值和日期**都填才生效** | 只填其一属于半截数据，静默生效比不生效更危险（前端已处理成"视为清除"） |
| 复用 `WeightService` 而非新建服务 | `MacroFactorService` 已注入 `WeightService`，同一条 `SettingRepository` 链路，无需新增 DI |
| 新增独立 key 而非塞进 `weight_config` | 保存权重时不应连带覆盖用户的因子校准 |
| 重渲染前快照用户输入 | 整块 innerHTML 替换必然丢未保存的输入；不快照则并发首屏下静默提交空值 |
| 加载中显示中性文案而非「暂无读数」 | 冷启动要现拉 60 根 K 线，「暂无读数」会被读成"因子丢了"（同 `freshness-degrade-ux`） |

`check_links.py` 在本版开始前报 12 条死链 —— CI 的 Links gate 会失败。全部修掉：

| `v0.87.0.md` 里带捕获组的 regex 字面量被 `LINK_RE` 当成链接 | 5 | 按该文件自己的教训改写：fenced code block **且** 捕获组 → 非捕获组 |

> 最后一条值得单独记：`v0.87.0.md` 当年总结的修法是"换成 fenced code block"，
> 但实测**只换 fence 不够** —— `LINK_RE` 扫全文不区分代码块，`(`…`)` 括号本身
> 就是链接语法的一半。已把这条教训补进 `v0.87.0.md` 正文。

### 新增门禁：release notes 索引完整性

死链门禁只看"**已写的链接能不能点开**"，看不见"**该写的链接根本没写**"。
`docs/releases/index.md` 停在 V0.100.2，而 V0.103 ~ V0.109 共 9 份 release notes
无人索引 —— 且**没有任何门禁报红**。

`check_links.py` 增加 `check_release_index()`：目录里有 `v*.md`、索引里没有入口 ⇒ 报红。
修完发现实际漏了 **13** 份（不只是 V0.103+），全部补登记。刻意**不设豁免名单**：
此前那 13 份被称作"有意合并进 v0.86.0 维护线"，但"有意"从未落纸，也没有任何机制
能区分"真的合并了"与"忘了登记" —— 全登记成本更低且不会再退化。

## 下一步：V0.111.0 阈值口径可覆盖

本版只解决"**输入值**过期"。"**阈值口径**过期"同样严重且用户完全看不见 ——

的市场结构，2024-2026 已多次触顶触底，长期输出 0 或 100；4 组 `IntEnum` 阈值

直接决定 9 档买卖建议。完整盘点与实施步骤见 [roadmap.md §2.2](../roadmap.md)。
