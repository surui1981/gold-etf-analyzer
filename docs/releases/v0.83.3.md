# V0.83.3 · 限速中间件 /static/ bypass + 默认 600/min

**日期**：2026-10-10
**类型**：Bugfix（用户报「主页数据时效加载失败」误报）
**roadmap 引用**：非 §4.1 计划项 · V0.83 收尾

---

## 用户报告

> 主页提示数据实效加载失败 ，什么问题

## 根因（不是 V0.83 代码 bug）

`src/app/middleware/rate_limit.py:30-33` 设计的限速中间件对**所有路径**都计数：
- 默认 `rate_limit_per_min = 120`（per-IP 60s 滑动窗口）
- 与 docstring line 11 承诺「不挂在 /static/」**实现不一致**
- 单次页面加载触发：HTML + 5 JS + 2 CSS + favicon + 1 API ≈ 10 请求
- `freshness.js:241` 每 60s `setInterval(load)` 再 +1
- LAN 用户多标签页几分钟内必打满 120 → 触发 429

用户实际看到的「数据实效加载失败」实际是：
1. `/api/v1/market/freshness` 返回 429
2. `freshness.js:213` 走 `!r.ok` 抛 `"HTTP 429"`
3. `.catch` 写入 `#freshnessInline`："数据时效加载失败：HTTP 429"

加 bug：
- `freshness.js:233` 引用 `fresh.load_failed_suffix` 但 **3 语 i18n 文件都没定义**
- i18n.js 走 `DEFAULT_LANG` 兜底（zh-CN）显示 inline fallback 文本
- 同时 telemetry 记录 `i18n_fallback_hit` 噪声

## 改动

### 1. `/static/` 路径 bypass（`rate_limit.py:60-62`）

```python
async def dispatch(self, request, call_next):
    if self._per_min <= 0 or request.method == "OPTIONS":
        return await call_next(request)
    if self._skip_static and request.url.path.startswith("/static/"):
        return await call_next(request)  # 新增
    ...
```

新增 `skip_static` 参数（默认 `True`），与原 docstring line 11 承诺对齐。`config.py:91` 新增 `rate_limit_skip_static: bool = True`，env `RATE_LIMIT_SKIP_STATIC=false` 可关闭（极端 DoS 场景）。

### 2. 默认限速 120 → 600（`config.py:87`）

实测单页面 + 60s 轮询 ≈ 10 req/min/tab，120 频繁打满。`/static/` bypass 后，仅 `/api/*` 进入滑动窗口，**600/min 给多 tab + 轮询留足余量**（10x 当前用量）。写端点（POST/PUT/DELETE）的业务级限速不在这层，由各 endpoint 自管。

### 3. 顺手补 i18n 漏洞（3 语 +1 key）

| 文件 | 改动 |
|---|---|
| `static/i18n/zh-CN.js` | 新增 `"fresh.load_failed_suffix": "（不影响页面其他数据）"` |
| `static/i18n/en-US.js` | 新增 `"fresh.load_failed_suffix": " (other data on page is unaffected)"` |
| `static/i18n/zh-TW.js` | 新增 `"fresh.load_failed_suffix": "（不影響頁面其他資料）"` |

`freshness.js:233` 现在 3 语都有正式翻译，inline 兜底文本不再触发 `i18n_fallback_hit` telemetry。
