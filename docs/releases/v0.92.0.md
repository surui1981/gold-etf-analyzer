# V0.92.0 · 历史打分数据汇总（物化宽表 + 汇总页）

## 摘要

V0.90.0 timeline + V0.91.0 报告页把「事后回看」补齐后，下一个客户痛点是**「跨日跨月跨 tag 看成绩单」**。本版为「历史打分数据汇总」补齐**数据 + 查询 + 视图**全链路：

- **`scoring_daily_wide` 物化宽表** —— 1 行/日，4 指数 + 消息面聚合 + 复盘 outcomes + basis_tags JSON，26 列 + 3 索引，写时 hook ETL
- **5 端点**：`/summary`（按 day/week/month 聚合）/ `/by-date/{date}`（单日详情）/ `/hit-stats`（按 horizon 命中率 + by_direction + by_month + calibration）/ `/by-tag`（basis_tag 维度）/ `/rebuild/{date}`（手动重算）
- **`/scoring` 汇总页** —— 双 Tab：日历视图（每日 4 指数热力图）+ 表格视图（4 指数时间序列 + basis_tag 频次 + 命中率 + by_direction 校准）
- **`backfill_scoring_wide.py` CLI** —— 一次性历史回填（默认从 V0.66.0 上线日 2024-09-01 起）

| 维度 | V0.91.0 | V0.92.0 | 提升 |
|---|---|---|---|
| 总测试数 | 1352 passed | **1362+ passed** | +10 例（service 套：rebuild / summary / by-date / by-tag + 失败空源 + pending 期 + tag 去重） |

| 历史成绩单视图 | 无（要 puppeteer 截图） | **日历视图 + 表格视图** | 5 段全部 RWD 表格化（V0.91 print 友好风格复用） |

### 2. 服务层 · `ScoringWideService` ETL + 4 聚合查询（C3）

**`src/app/services/scoring_wide.py`**（~250 行）—— 把 3 张事实表（`daily_snapshots` / `news_scores` / `gold_price_daily`）合并为 1 行宽表：

#### ETL 主流程

```python
async def rebuild(self, target_date: date, user_id: int | None = None) -> ScoringWideOut | None:
    """重算单日宽表行（幂等）。写时 hook 调用 + 离线 CLI 回填。"""
    try:
        row = await self._build_row(target_date, user_id)
        if row is None:
            return None
        await self._repo.upsert(row)
        return ScoringWideOut.model_validate(row)
    except Exception as exc:  # noqa: BLE001
        logger.warning("scoring_daily_wide rebuild failed: date=%s err=%s", target_date, exc)
        return None  # V0.79.0 #162：宽表写失败**不**回滚源表
```

**`_build_row` 关键步骤**：

1. **3 源都缺 → 返回 None**（不写空行；写空行会被 by-month 聚合稀释）
2. **`daily_snapshots`** → 复制 4 指数 + 价格 + data_source
3. **`news_scores`** 当日所有 slot → `aggregate_slots()` + `direction_of()` → 实时聚合 news_index（覆盖 snapshot 缓存值）；`parse_basis()` + `set()` 去重 + 倒序排（slot3 出现顺序优先）
4. **`gold_price_daily` 基准日 + T+1/T+3/T+5** → `judge_hit()` 判定；T+5 缺数据 → outcomes 留 NULL + `outcome_pending_until=last_bar_date`

**纪律**：
- basis_tags 应用层用 `BASIS_TAGS` 白名单过滤（防 schema 漂移脏数据）
- 失败时 log.warning 但**不**抛异常（V0.79.0 #162 教训：宽表是"读优化副本"，源表是真值）

#### 4 聚合查询

| 方法 | 端点 | 复用 |
|---|---|---|
| `summary(start, end, group_by, tag)` | `GET /scoring/summary` | `_bucket_key(day/week/month)` + ISO week 格式 `"2026-W42"` |
| `get_by_date(date)` | `GET /scoring/by-date/{date}` | — |
| `hit_stats(start, end, horizon)` | `GET /scoring/hit-stats` | `judge_hit()` + 5 个分值分箱（0-20/20-40/40-60/60-80/80-100） |
| `by_tag(start, end)` | `GET /scoring/by-tag` | basis_tags JSON `json.loads` + 白名单过滤 |
| `rebuild(date)` | `POST /scoring/rebuild/{date}` | 同上 ETL |

**复用 V0.86.0 决策可解释模式**：`ReviewStatsOut` schema + `MIN_SAMPLES_OVERALL=10` 阈值（by_tag sample_size < 10 时降级标"样本不足"）。
