# V0.105.0 · headlines 分类筛选（5 类 + 多 switch）

> 日期：2026-10-19
> 类型：功能（feature）—— 添加类目分类 + 顶部多 switch 筛选
> 前置版本：V0.104.0

## 用户原话

> 主要聚焦页面财经内容（"主要 聚焦页面财经内容"）

## 问题与目标

**问题**：用户在 `/headlines` 观察发现所有新闻都聚焦于财经 / 经济向（readhub 内部 API 6h 抓取窗口里 80%+ 是财经，挤掉了科技/创投/商业等其他类目）。当前无任何类目筛选，用户想看科技/创投类新闻时无能为力。

**目标**：给 `/headlines` 加类目分类 + 顶部多 switch 筛选，让用户能在「财经 / 科技 / 创投 / 商业 / 其他」间切换看不同主题新闻。

**决策（已 AskUserQuestion 锁定）**：
1. **5 类**：财经 / 科技 / 创投 / 商业 / 其他（readhub 内部主题分类）
2. **后端关键词分类器**（rule-based）—— readhub API 不带类目参数，必须自己分类
3. **顶部下拉筛选**（不强制用 chip strip，灵活）

## 关键设计

### 1. 5 类关键词分类器 `src/app/repositories/news_classifier.py`（新）

```python
CATEGORIES = ("财经", "科技", "创投", "商业", "其他")
# 4 个分类的关键词字典（顺序重要：财经优先）
_FINANCE_KW = ("央行", "汇率", "降息", "加息", "美联储", "通胀", "GDP", ...)
_TECH_KW = ("AI", "芯片", "半导体", "算法", "模型", "开源", "大模型", ...)
_VC_KW = ("融资", "IPO", "估值", "种子轮", "天使轮", "A 轮", "B 轮", ...)
_BIZ_KW = ("财报", "营收", "利润", "股价", "市值", "业绩", "季报", ...)

def classify(title: str, summary: str, site_name: str) -> str:
    """按关键词优先级返回 5 类之一。"""
    text = f"{title} {summary} {site_name}".lower()
    if _hit(text, _FINANCE_KW): return "财经"
    if _hit(text, _TECH_KW):    return "科技"
    if _hit(text, _VC_KW):      return "创投"
    if _hit(text, _BIZ_KW):     return "商业"
    return "其他"
```

**Why 财经优先**：readhub 抓的数据里财经站点（华尔街见闻、财联社）流量大；财经关键词与商业/创投有重叠（「估值」「收购」），先财经后创投防误分。

**Why 「其他」兜底**：所有 readhub item 必有 title + site_name，所以必落入 5 类之一。

### 2. 3 路 backfill 机制

| 路径 | 触发 | 性能 |
|---|---|---|
| **Lazy（无感）** | `service.refresh()` 走 `_normalize` 自动分类新条目 | 6h 抓取新条目 ≤ 20 条 |
| **Eager（启动）** | `main.py` lifespan `_backfill_news_categories()` 一次性 | 64378 行 / 500 batch ≈ 130 批 × 50ms ≈ 6-10s |
| **Upsert（重抓）** | `upsert_bulk` set_ 含 `category=stmt.excluded.category` | O(1) per row |

**幂等性**：`backfill_categories` 只处理 `category IS NULL` 行，已分类的不动。

### 3. UX 工具栏第 5 控件

```
┌──────────────────────────────────────────────────────────────────┐
│ 时间: [1 天] [7 天] [30 天]  📅 [◀] [2026-10-19] [▶]  来源 ▼ 语种 ▼ 分类 ▼  ⟳   │
└──────────────────────────────────────────────────────────────────┘
```

**位置**：`#categorySel` 在 `#langSel` 之后 / `<span class="spacer">` 之前（第 5 控件）

**正交性**：

- 切换 date/days/site/language 不清 category
- has_older/has_newer 不带 category 过滤（V0.104 翻页语义不变；empty-state 接受「该日无此类新闻」）

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 旧 ~64378 行 NULL，启动 backfill 5-10s 延迟 | 启动 lifespan 钩子里 `backfill_categories(batch_size=500)` 异步跑，不阻塞 readiness probe |
| 关键词分类器准确率 ~70-80%（rule-based 上限）| 接受现状；V0.106+ 引入 LLM 分类 |
| `has_items_outside_day` 不带 category 过滤 → ◀ 落到 0 条日 | 接受现状；empty-state 文案已解释「该日无此类新闻」|
| 5 类索引选择率低（cardinality 5）| SQLite 仍会选 B-tree 索引用于 LIMIT-bound query |
| `category` 字段加到 `NewsFeedItemOut` 是 Pydantic 序列化增量 | 不破坏现有 6 个 API 测试 |
| `on_conflict_do_update` set_ 不加 category → 旧行永远 NULL | **必须**在 upsert_bulk 的 set_ 加 `"category": stmt.excluded.category` |
