# V0.103 · 我的收藏（今日要闻「收藏 / 永久存储 / 档案管理」）

> 用户原话：「我们好好梳理一下 今日要闻的存储逻辑，给有价值的新闻可以在应用中添加永久存储并设计一个页面，帮助用户掌握市场动态。写一个计划。」
> 范围：① `user_news_favorites` 表 + 9 REST 端点；② `/favorites` 档案管理页（时间线 + tag 筛选 + 重要度 + 自由笔记 + 统计侧栏）；③ `/headlines` + `/home` 加 `⭐ 收藏` 按钮；④ 7 commit / ~1680 行净新增 / V0.103 正式发版。

## 背景

**为什么做 V0.103**：

- V0.102 落地的 `news_feed_items` 表是「共享上下文」（migration `m9g0a1b2c3` 显式不挂 `user_id`），6h 抓取 / 无清理 / 字段外部所有。用户在翻 今日要闻时看到「这条值得长期参考」想存下来，目前**项目里没有任何「用户标记数据」的表或字段**（Explore 全仓 grep 0 命中 watchlist / favorite / bookmark / starred / pinned / user_note 业务实体）。
- 需要新增完整的「用户策展」层：在「今日要闻」流里给每条加 `★ 收藏` 按钮 → 一键入库；新增 `/favorites` 档案管理页帮用户「掌握市场动态」（按 tag 维度聚合，按月 / 按来源站统计）。

**用户已确认的 2 个关键决策**（已通过 AskUserQuestion 锁定）：
1. **单用户（共享）模式** —— 与 `news-score` / `portfolio` / `decisions` 一致；不挂 `user_id` 隔离，AUTH_ENABLED=false 时零额外配置
2. **独立表 + 快照字段** —— 收藏时**冗余快照** `title / summary / url / site_name / publish_date / source`，与 `news_feed_items` 表完全松耦合；防 readhub 端撤稿 / URL 失效时收藏断链

**设计纪律**：
- 不挂 `user_id` 字段（与 `news_feed_items` 共享语义边界对齐）
- 不做全文搜索 / 标题模糊匹配（user_tags + importance 筛选够用）
- 不做收藏导出 / 导入（v0.103+ backlog）
- 不做断链检测（监控 news_feed_items 30 天未刷新 + 收藏过 → 提醒），v0.103+ backlog
- 不做收藏分享 / 公开链接
- 鉴权走 `Depends(require_user)`：单用户模式自动回退 LEGACY_USER（V0.97.0 hotfix 防 401）
- LAN-only 部署 + 4 处版本同步门禁（__version__ / pyproject.toml / sw.js VERSION / docs/releases）

## 5 条经验教训

1. **仓储 Core UPDATE 不刷 identity map** —— `UserNewsFavoriteRepository.update()` 用 `Model.__table__.update()` + `commit()` 不会让已加载的 ORM 实例失效，下次 `get(fav_id)` 返回陈旧对象。`expire_all()` 兜底（get_status 聚合测试暴露 → 修）
2. **单用户回退端到端必须测** —— `Depends(require_user)` 走 `LEGACY_USER` 兜底，单测里 `conftest._reset_db` 会 drop_all → 需 `autouse fixture` 显式建 LEGACY_USER（API 22 例全加 `_ensure_legacy_user` 兜底 fixture）
3. **依赖注入链路要包含 feed_repo** —— `UserNewsFavoriteService.__init__(fav_repo, feed_repo=None)`；`get_user_news_favorite_service` 同时注入 `fav_repo` + `feed_repo`，让 `add()` 能从 `news_feed_items` 回填快照保证与 readhub 一致
4. **静态页 /static/*.html + /static/*.js 拆** —— V0.99 沉淀的「拆 HTML+JS」模式在 V0.103 复用（favorites.html 12k + favorites.js 16k 拆出，headlines 模式一致）；`check_static_js.py` glob 自动发现新文件，零额外配置
5. **改 static 必须 bump SW VERSION** —— V0.100.1 沉淀的教训：activate 阶段按 cache name 删旧 SHELL/RUNTIME + RUNTIME_CACHE stale 清理（套 V0.92.0 `/scoring` 同模式）—— V0.103 加 `["/favorites", "/static/favorites.html"]` 清理
