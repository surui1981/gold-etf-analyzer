# V0.98 · 体验重塑 + 结构清偿（7 件大项 / 11 个 commit）

> V0.97.2 收尾后的整体重塑版。**用户体验重塑**（场景化首页 + SSE 流式 + URL 状态化 + PWA 兜底）+ **结构债清偿**（ai_chat 拆分 + CHANGELOG）。
> 纯增强，不破坏 V0.97.0 / V0.97.1 / V0.97.2 任何既有能力。

## 背景

V0.97.x 收尾后盘点 3 类体验 + 3 类结构债：

**体验**：
- 17 个业务页 13 个 topnav tab + 14 个 root alias，导航负担重

- 6 个有 filter 的页靠 LS 存状态，URL 不持久化 → 复制链接 / 跨页跳丢上下文

**结构**：
- `ai_chat.py` 428 行 1 文件，吃掉「多轮编排 + miniMax 2013 3 级降级 + 历史窗口 + 配额扣减」4 个职责
- 无 `CHANGELOG.md`，发版历史散在 `docs/releases/vX.Y.Z.md`，不可索引

**用户已确认的 4 个关键决策**：
1. 首页 = 5 大场景卡（决策 / 持仓 / 情报 / 配置 / AI）
2. 流式 = SSE（`sse-starlette` + `EventSource`）
3. URL 状态化 = 6 个有 filter 的页全做
4. PWA + toast = 全套（beforeinstallprompt + iOS 引导 + manifest 完善 + 全局 toast + 断网检测）

### C3 · 全局 toast + 断网检测 + PWA 安装体验（`d2fd513`）

#### 3a. 全局 toast 系统

**新模块**：`static/toast.js` + `static/toast.css`

**API**：
```js
window.PM_Toast = {
  info(msg, opts={}): toastId
  success(msg, opts={}): toastId
  warn(msg, opts={}): toastId
  err(msg, opts={}): toastId
  dismiss(toastId): void
  clear(): void
}
```

**特性**：
- 4 种类型：info（蓝）/ success（绿）/ warn（amber）/ err（红）
- 自动消失（默认 4s，可 `opts.duration = 0` 不消失）
- 最多同时 3 个（队列式：超 3 个挤掉最老的）
- 顶部居中 stacked，dark mode 兼容
- 支持 action button + undo

#### 3b. 断网检测 banner

**新模块**：`static/net-status.js`

- 监听 `online` / `offline` 事件
- 主动 `fetch('/api/v1/health', { cache: 'no-store' })` 每 30s 探活
- 失败 → `PM_Toast.err('网络异常', { duration: 0 })` + 顶部固定 banner
- 恢复 → banner 消失 + `PM_Toast.success('网络已恢复')`

#### 3c. PWA 安装体验

- 加 `appinstalled` 监听：toast.success「已添加到主屏」+ LS 标记
- install banner 文案改写：突出「离线浏览 + 主屏启动 + 推送通知」3 大价值
- dismiss 频率控制：7 天内不再弹
- manifest.json 加 `description` + `screenshots` 字段
- 抽 `static/pwa.css`（遵循 `scoring-page-css-block-tech-debt`）

### C5 · /ask SSE 流式响应（`89ed23f` + `13652e6`）

**核心**：从「整段等回」→「逐字流式 + 工具调用同流可见」

**新依赖**：`sse-starlette ^2.0.0`（唯一新 dep）

#### 后端

**`src/app/services/llm/claude.py` 加 `ask_stream()`**：
- `httpx.AsyncClient.stream("POST", self._endpoint, json={..., "stream": true})`
- 逐行读 Anthropic SSE 格式
- yield `StreamEvent` dataclass：`TextDelta` / `ToolUseStart` / `MessageStop` / `Ping` / `Error`

**`src/app/services/ai_chat/service.py` 加 `send_message_stream()`**：
- 与 `send_message()` 同结构（多轮 + 3 级降级），但 yield 事件流
- **保留 `send_message()` 不变**（向后兼容老前端 + 单元测试）
- 3 级降级（V0.97.2 hotfix）必须在 stream 版内逐级 fall back：
  - 2013 → 静默切换到 inlined stream 重试
  - 仍 2013 → 静默切到 fresh-only stream
  - 都失败 → `{"event": "error", "code": "llm_failed"}` 后正常结束

**新 endpoint**：`POST /api/v1/ai/conversations/{conv_id}/messages/stream`
- 用 `sse_starlette.EventSourceResponse` 包流式
- 旧 `POST /messages` 保留（V0.97.0 contract 不破坏）

#### 前端

**`static/ask.js` 重写 `sendMessage()`**：
- `fetch(url, { method: "POST" })` + `response.body.getReader()` + `TextDecoder` 逐行解析 SSE
- `appendDelta(msgId, delta)`：把 delta 追加到 assistant bubble 的 `textContent`（防 XSS）
- `renderToolCallStart/InputDelta/Result`：3 个 tool chip 渲染函数
- 错误处理：`{"event": "error", ...}` → `toast.err(...)`
- **断线自动重连**：fail 1 次 → toast.warn + retry 1 次（带 user 原始消息）
