# V0.86.1 · 数据健康跳转 404 hotfix

## 用户报告
> 现在通过内网测试主页发现数据健康的链接点击后出现 detail not found。

## Bug 根因

V0.85.0 引入的 chip 链接 `<a href="/data-health.html">` 在 9 页 statusPanel
summary 都装上了，但 **`src/app/main.py` 根路径别名列表漏注册 `/data-health` 别名**：

```
main.py 已有别名（V0.85 之前）：
  /                → /static/trend.html
  /portfolio       → /static/portfolio.html
  /weights         → /static/weights.html
  /news            → /static/news.html
  /review          → /static/review.html
  /central-bank    → /static/central_bank.html
  /trades          → /static/trades.html
  /login           → /static/login.html
  /reset-password  → /static/reset-password.html

main.py 漏掉：
  /data-health     → /static/data-health.html  ❌ V0.85 漏注册
```

`/data-health.html` 既不是根路径别名（没有 `@app.get` 装饰），也不是
`StaticFiles` mount 的 `/static/` 前缀路径 → FastAPI 默认 404。

```bash
$ curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8888/data-health.html
404   ← bug 现场

$ curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8888/static/data-health.html
200   ← 文件本身可访问
```

---

## 修复

### 主修复（最小侵入）

**`src/app/main.py`**：加 `/data-health` + `/data-health.html` 双别名

```python
@app.get("/data-health", include_in_schema=False)
async def data_health_page() -> RedirectResponse:
    """数据健康摘要页（V0.85.0）—— 6 数据源实时状态完整披露。
    9 页 statusPanel summary 都用 <a href="/data-health"> chip 跳本页
    （与项目 kebab-url 约定一致：/portfolio、/central-bank 等都无 .html 后缀）。"""
    return RedirectResponse("/static/data-health.html")


@app.get("/data-health.html", include_in_schema=False)
async def data_health_page_dothtml() -> RedirectResponse:
    """/data-health.html 别名（向后兼容 V0.85.0 chip 直链 + 外部书签）。"""
    return RedirectResponse("/static/data-health.html")
```

### 升级（kebab-url 一致性）

`health-summary.js` + 8 个 HTML 的 chip href 从 `/data-health.html` 升级到 `/data-health`：
- 与 `/portfolio`、`/central-bank`、`/trades` 等其他 chip 风格一致
- 偏离「直链静态文件」的设计——chip 现在走 FastAPI 别名（307），服务可控

### SW 缓存（让离线场景也修好）

`sw.js` SHELL_ASSETS 加 `/data-health`，VERSION bump 到 `v0.86.1`：
- SW 缓存名 `gold-shell-v0.86.1`（≠ v0.86.0）→ 触发浏览器重新安装 SW + 清缓存
- 否则老 SW 仍按 `gold-shell-v0.86.0` 缓存，新 SHELL_ASSETS 不生效

### 测试同步

`scripts/check_cluster_render.mjs` + `scripts/check_v085.mjs` 的 chip href
断言从 `/data-health.html` 改为 `/data-health`。

## 风险与缓解

| # | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| R1 | 旧 chip `/data-health.html` 书签在升级后拿到 307（不再直达） | 低 | 极低 | 同时加 `/data-health.html` 别名；用户视觉无差异 |

## 教训

1. **新增静态页必须同步注册根路径别名**：main.py 第 327-393 行的别名列表是
   「白名单」，漏一个就 404。**V0.85.0 引入 data-health.html 时没有 check
   `GET /data-health.html` 的 4xx 状态断言**，导致 V0.85.0 全部门禁通过但
   真实跳转 404。`check_pwa_assets.py` 只校验 SW SHELL_ASSETS，不验证 HTTP 200。
2. **chip href 直链 vs 别名**：V0.85 走 `/data-health.html` 直链静态文件，
   是「碰巧能用」—— 一旦 main.py 加新的 `@app.get("/data-health")` 路由
   优先匹配，static 直链失效（FastAPI 路由顺序）。升级到 `/data-health`
   别名后跳 307 是显式可控的。
3. **测试必须涵盖 HTTP 状态**：puppeteer 只验证 `document.body` 渲染，
   不验证 URL 跳转是否 200。考虑加 `scripts/check_routes.py`：
   扫描 main.py 别名 + curl GET 验证 307/200，纳入 V0.87。
