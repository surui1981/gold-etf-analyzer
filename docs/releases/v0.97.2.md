# V0.97.2 · /ask 页面布局修复（视口感知 + welcome 卡片）

> V0.97.0 / V0.97.1 后的 UX 收尾版。纯前端 CSS + HTML + JS 调整，无后端 / DB / API 变化。

## 背景

V0.97.1 部署后用户实测反馈：「**智能分析的页面布局，我看不到填写内容的对话框，页面布局也需要优化**」。

puppeteer 探针定位 3 个叠加缺陷：

| 视口 | 旧 msgInput.y | 视口底 | 旧 msgInput.w | 状态 |
|---|---|---|---|---|
| 1280×720 | 876 | 720 | 22px | **fold 下 156px** |
| 1366×768 | 876 | 768 | 22px | **fold 下 108px** |
| 1440×900 | 876 | 900 | 22px | fold 上 24px（勉强） |

**根因**：

1. `.ask-layout { min-height: 540px }` 写死 —— 与 topnav+hero 叠加后固定超出视口
2. `.input-bar` 在 `.ask-main`（flex 列）里没声明 `flex-shrink: 0` + 显式宽度 —— 塌缩到 `textarea 22 + gap 8 + send 62 = 92px`（`msgInput.w = 22px` 在所有视口）
3. 3 栏 grid `240px 1fr 280px` —— 右侧 `.ask-tools` 初始 `[hidden]` 但仍占第 3 列 280px 空白

## 4 项交付

### 1. 视口感知 flex 三层链布局

```
body     → display: flex; flex-direction: column; min-height: 100dvh
.wrap    → flex: 1 1 auto; display: flex; flex-direction: column; min-height: 0
.ask-layout → flex: 1 1 auto; display: grid; min-height: 0
  ├─ .ask-sidebar   (240px, flex-shrink: 0, overflow-y: auto)
  ├─ .ask-main      (flex: 1, min-width: 0, display: flex; flex-direction: column)
  │   ├─ .ask-header     (flex-shrink: 0)
  │   ├─ .message-stream (flex: 1 1 auto; min-height: 0; overflow-y: auto)  ← 关键
  │   └─ .input-bar      (flex-shrink: 0; width: 100%; background: var(--card))  ← 关键
  └─ .ask-tools     (默认 hidden, .has-tools 时 280px)
```

- `min-height: 0` 是允许 `.message-stream` 滚动的关键 —— 漏任一层 → 滚动失效
- `width: 100%` 显式 stretch 是治 22px 塌缩 bug 的兜底
- `min-height: 100dvh` 带 `100vh` 兜底（老 Safari < 15.4 降级）

### 2. 2 栏默认 / 3 栏按需

- 默认 `grid-template-columns: 240px minmax(0, 1fr)`（用 `minmax(0, 1fr)` 防 textarea min-content 撑爆列）
- 当 `askLayout.classList.contains('has-tools')` 时切换为 `240px minmax(0, 1fr) 280px`
- JS 在 `updateToolTrace()` 旁加 2 行 `setToolsVisible()` 调用 → 同步 `toolTraceEl.hidden` + `askLayout.classList.toggle('has-tools', visible)`
- 移动端 `<1000px` 仍走 1 栏（已存在媒体查询保留）

### 3. Welcome 卡片 + 5 个示例 chip

**改前**：

```html
<div class="empty-stream" data-i18n="ai.empty_state">还没有对话 — 点左侧「+ 新对话」开始提问</div>
```

**改后**：

```html
<div class="empty-stream" id="emptyState">
  <div class="empty-icon">💬</div>
  <h3 data-i18n="ai.empty_title">开始一次新的对话</h3>
  <p class="empty-desc" data-i18n="ai.empty_desc">试试这些常见问题...</p>
  <div class="example-chips" id="exampleChips">
    <button class="example-chip" data-prompt-key="ai.example_market_q" data-i18n="ai.example_market">📈 今天金价怎么样？</button>
    <button class="example-chip" data-prompt-key="ai.example_portfolio_q" data-i18n="ai.example_portfolio">💼 我的持仓表现如何？</button>
    <button class="example-chip" data-prompt-key="ai.example_scoring_q" data-i18n="ai.example_scoring">🎯 最近 T+1 命中率走势？</button>
    <button class="example-chip" data-prompt-key="ai.example_warning_q" data-i18n="ai.example_warning">⚠️ 当前有什么风险信号？</button>
    <button class="example-chip" data-prompt-key="ai.example_flows_q" data-i18n="ai.example_flows">💸 最近 ETF 资金流向？</button>
  </div>
</div>
```

- chip prompt 文案走 `t(ai.example_*_q)`，避免 zh-CN fallback 漏改（memory `i18n-init-await` 教训）
- `renderEmptyStream()` 不再 `innerHTML` 整片擦写，保留 `#emptyState` 节点 → chip 事件不丢失
- 点击 chip：填入 textarea + focus + auto-resize + char-count 同步；**不**自动开新对话（`sendMessage()` 内部处理 `activeId` 为空的情况）
- `i18n:change` 事件触发 `renderExamplePrompts()` → 切换语言时 chip 文本随语言变化

### 4. 输入栏微优化

| 旧 | 新 |
|---|---|
| 单行无 keyboard hint | textarea + send-btn 加 `title="Enter 发送 · Shift+Enter 换行"` |
| `max-height: 140px` | `max-height: 120px`（缩一点让底部不挤） |
| 无字数提示 | `> 2000 字` 显示 `N / 8000` 软提示，> 8000 字变红（server 端 8000 截断护栏） |
| `i18n:change` 不重渲染 welcome | `i18n:change` 触发 `renderExamplePrompts()` |

## 设计纪律

- **不引依赖、不引新构建步骤** —— 纯 HTML + CSS + JS
- **不动后端 / API / DB** —— 纯前端重构
- **保留所有 i18n 既有 key**（18 个 key × 3 语 + ask.js 运行时 t() 用 ~20 个 key）—— 12 个新 key 走 `ai.example_*` / `ai.empty_*` 命名空间
- **sh.js SHELL_ASSETS 35 条不动** —— ask.html / ask.js 已在 precache 列表，VERSION bump 后 `gold-shell-v0.97.2` 与旧版完全分离，SW activate 自动清掉 `gold-shell-v0.97.1`
- **保持 LAN-only 部署**（192.168.0.204:8889/gold/）—— 改完走 hard-refresh 验证
