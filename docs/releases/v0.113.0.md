# V0.113.0 · 移动端可用性（表格滚动容器 + 44px 触摸目标 + 聚焦不被顶栏遮挡）

> 发版日期：2026-10-22
> 前置：V0.112.0（命令面板修好）
> 性质：UI + 门禁 · 无后端改动

## 一句话

这是本项目第一次**在 390px 真实视口下逐页实测**。此前所有「响应式」都是桌面
浏览器缩窄窗口看出来的，从没量过触控手指够不够得着、表格滑不滑得动、Tab 会不会
把焦点送到顶栏底下。量完的结果是三类缺陷，而且**全都不报错**：

| 缺陷 | 实测（修复前） | 修复后 |
|------|--------------|--------|
| 横向溢出 | 4 页表格溢出（`/scoring` **221px**、`/report` 175px、`/silver` 123px、`/central_bank` 71px）＋ 6 页因引导提示框硬编码宽度多出 11px | **18/18 页 0px** |
| 聚焦被 sticky 顶栏遮挡 | **17 处**（Tab 把焦点送到顶栏底下 ⇒ 看着像「点不动」） | **0** |
| 触摸目标 < 44px | `/headlines` 单页 **115 个**、其余页零星 1–30 个 | **18/18 页 0 个** |

「不报错」是重点：这三类都不会抛异常、不会被 `check_static_js` 抓到、DevTools 里
也看不出异常，只是**在手机上很难用**。所以本轮除了修，还把三个基元钉进门禁。

## 一、`.table-scroll` 表格横向滚动基元

### 为什么不用 `overflow-x:auto` 一把梭

宽表在窄屏上横向溢出，最直接的做法是给容器加 `overflow-x:auto`。但 `theme.css`
是全站共享基元，加错了会**在桌面端也生效** —— 1352px 下每个表格都被塞进滚动条里，
白白多一根横向滚动条。所以这个基元刻意写得**保守**：

```css
.table-scroll {
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;   /* iOS 惯性滚动 */
  overscroll-behavior-x: contain;     /* 横向拖到头不连带整页回弹 */
  max-width: 100%;
}
```

落地前先写了一版带 `min-width: max-content` 的草案，验证时发现**含长文本的表格在
桌面端也被拖出滚动条**才删掉 —— 并且在门禁里钉了一条「不许再有人加回来」的断言。

### 无障碍三件套：CSS 做不到，只能写在标记里

可横向滚动的区域键盘用户必须能聚焦（WCAG 2.1.1），这靠 `tabindex="0"` +
`role="region"` + `aria-label` —— **全是属性，没有对应的 CSS**。11 处包裹全部带齐：

```html
<div class="table-scroll" tabindex="0" role="region" data-i18n-aria="silver.cmp_title">
```

`aria-label` **复用该表上方小节标题已有的 i18n key**，本轮**新增 0 个 i18n key**。
静态页用 `data-i18n-aria`（标签跟着语言翻），JS 模板用 `aria-label` 直写。

### 11 张表

| 文件 | 张数 | 说明 |
|------|------|------|
| `scoring.js` | 3 | 4 指数时序 / 依据标签频次 / 分值校准 |
| `report.js` | 5 | 持仓 / 决策时间线 / 消息面 / 收益曲线 / 央行购金 |
| `silver.js` | 1 | 多市场升贴水表 |
| `silver.html` | 1 | 央行白银 vs 现货对比 |
| `central_bank.html` | 1 | 前 20 大买家 |

### 门禁里为什么不数 DOM

其中 9 张表是 JS 在**数据到达后**才渲染的（升贴水表在报价未就绪时根本不建；
report 5 段各自有 `show(sec)` 门控）。按 DOM 计数会把「数据没到」误报成
「包裹漏了」。所以门禁只断言**源码契约**（每文件几张、每处开标签齐不齐三件套），
DOM 侧的实际渲染交给 `_verify_mobile.mjs` 实跑。

## 二、44px 触摸目标（WCAG 2.5.5 / Apple HIG 44pt）

```css
@media (max-width: 640px), (pointer: coarse) { ... }
```

触发条件取**或**：「视口窄」**或**「触摸输入」—— 平板横屏不窄但一定是触摸，
反过来手机竖屏很窄但可能是鼠标接键盘，只认一个都会漏。

### ⚠ 本轮踩到的最大的坑：换行 = 后代组合器

规则写完后实测输入框仍停在 **27–35px**，`min-height: 44px` 这串字符就在文件里，
`el.matches(selector) === true`、`matchMedia(...).matches === true` —— 全绿，
**就是没生效**。CSSOM dump 显示解析后的 `selectorText` 里，`[type="radio"]`
后面多了一个空格：

```css
/* 错的：换行 + 缩进被解析成后代组合器 —— 匹配「input 里的 input」，永不命中 */
input:not([type="hidden"]):not([type="checkbox"]):not([type="radio"])
       :not([type="file"]):not([type="color"]) { min-height: 44px }
```

CSS **不报错**，DevTools 里也不显形，只是安静地什么都不做。修法是把选择器写在
同一行，并在 CSS 注释里把这个坑记下来。

**所以门禁里那条核心断言查的不是「文件里有没有 `min-height: 44px`」（那样查不出
死规则），而是「选择器里有没有非逗号处的换行」。**

### 几条不显然的 CSS 事实

- `min-height` **无条件胜过** `height`（CSS2.1 §10.4）⇒ `news.html` 把 range 轨道
  压成 `height:8px` 的地方，等于白得一条 44px 高、看不见但可点的轨道
- `min-height` 对 **inline 盒子无效** ⇒ `span/a[role=button]` 必须先
  `display: inline-flex` 才吃得到规则
- `min-height` 的 **flex item 初始值是 `auto`**（解释过一次 `getComputedStyle`
  读出 `"auto"` 的困惑）

### 刻意**不**放大的两类

- **正文段落流里的文字链**（新闻标题、来源名，`/headlines` 有 23 个）—— 它们是
  排版的一部分，撑到 44px 会把整页文字撕碎
- **checkbox / radio 方块本身** —— 触摸区域是包着它的 `<label>`，
  规则写成 `label:has(> input[type=checkbox])`

### 一个级联陷阱

`responsive.css` 在各页内联 `<style>` **之后**加载，同特异性下胜出 —— 它原本写
`min-height: 40px`，光改 `theme.css` 的话全站 20 个按钮仍卡在 40px。两处必须同步，
门禁里钉死了「不许再出现 40px」。

## 三、聚焦不被 sticky 顶栏遮挡

浏览器滚动对齐**不知道上面压着 sticky 顶栏**，Tab 会把目标正好送到顶栏底下。
修法是 `scroll-padding-top`（浏览器的滚动对齐预留），高度**实测**而非硬编码：

```js
function syncScrollPadding() {
  var h = Math.ceil(nav.getBoundingClientRect().height);
  document.documentElement.style.scrollPaddingTop = h + "px";
}
```

挂在 `resize` + `ResizeObserver`（顶栏高度会因字体加载 / i18n 切换 / 子页挂载而变）
+ `document.fonts.ready` + `i18n:change` 上。

### 17 处遮挡里，16 处是同一个 bug

`command-palette.js` 的关闭态面板只有 `opacity: 0` —— 而 **`opacity:0` 的元素仍在
tab 序列里**（WCAG 2.4.3 焦点顺序 / 2.4.7 焦点可见）。键盘用户进页面第一个 Tab
到的就是这个**看不见**的搜索框，且正好落在顶栏底下，看着像「点不动」。
18 页里 16 页中招。修法是关闭时 `visibility: hidden`（参与 transition，淡出结束后
才真正移出 tab 序列），打开时 `visible`。

> 这也解释了为什么它一直没人发现：**只影响键盘用户**，鼠标用户完全无感。

## 四、顺手修的 2 个既存缺陷（不在本轮计划内）

验证过程中撞见的，都属于「静默展示错误内容」，按 V0.77.1 一并修掉：

### 1. 两页漏引 i18n 字典文件 ⇒ 整页渲染成 key 字面量

`/report` 的正文当时直接显示着 `report.section_positions` 这样的字面量
（21 处 `data-i18n` + `report.js` 里所有 `esc(i18n("report.*"))`），
`/reset-password` 同样 11 处。

**根因在 `i18n.js:46`**：非默认语言会动态插 `<script>` 去取字典，**唯独默认语言
zh-CN 走 `syncLoadDefault()`**，只读 `window.PM_I18N_ZH_CN`，**不会**自己去取字典
文件 —— 所以漏引字典文件这件事**没有任何机制会报错**，只能静态扫。

`check_i18n_keys.py` 新增 `check_dict_loaded()`：扫描每个含 `data-i18n` 的页，
缺 `/static/i18n/zh-CN.js` 即红。

### 2. `/report` 每访问一次吃一个 favicon 404

该页单独引 `/static/favicon.svg`，而 `static/` 下**从来没有这个文件**；
全站 21 页里也只有它引。图标已由 `manifest.json`（icon-192/512/maskable-512）
承担，直接删掉。

### 3. 引导提示框硬编码 320px 宽度（6 页各多 11px 横向溢出）

`help.js` 的 `positionTip()` 拿桌面的 320 去钳位，但 `help.css` 的窄屏媒体查询把
提示框改成 `width: calc(100vw - 24px)`（390px 视口下 = 366px）⇒ 右侧伸出视口。
改成**实测** `offsetWidth`，并补上漏掉的 `+ window.scrollX`。

## 五、门禁

### `check_cluster_render.mjs`：+28 条断言（461 passed / 0 failed）

三个新基元都是**静默失效**型，写坏了不报错 —— 所以必须钉住：

- `.table-scroll` 基元 4 条（含「不许加 min-width」）
- 44px 规则 7 条，**核心是「选择器有没有被折成后代组合器」**
- `responsive.css` 与 `theme.css` 的 44px 同步 2 条（含「不许退回 40px」）
- 命令面板 `visibility` 2 条
- `topnav.js` `scroll-padding-top` 2 条
- 11 张表的源码契约 11 条

### ⚠ 门禁自己也踩了同一个坑

第一版断言写的是「`.pm-cmd` 规则里有 `visibility: hidden`」，反向验证时**把真正的
声明删掉，门禁依然全绿** —— 因为该规则上方那段解释「为什么需要 visibility」的
⚠ 注释里就写着 `visibility:hidden` 字样，正则把注释当成了声明。

改成**只扫字符串字面量**（真正发到浏览器的那部分 CSS）。这与 V0.113.0 在
`check_static_js` 里踩的「注释里的 `<script>` 字面量让正则吞掉真脚本」是同一类坑：
**注释里的「代码样文字」不能当代码**。

### 反向验证：9 个注入缺陷，9 条各自变红

「崩的门禁不是门禁」同源 —— 只看退出码会把崩溃当通过，所以每条都要求**红在指定
那条断言上**（`grep '[FAIL]'` 而不是 grep 关键词，后者会连 `[OK]` 行一起命中）：

选择器折行 / 漏 `:not([type=color])` / 整条 44px 规则消失 / `table-scroll` 被补上
`min-width` / `responsive.css` 退回 40px / 面板去掉 `visibility` / 去掉
`ResizeObserver` / `report.js` 少包一张 / 某处漏 `tabindex`。

其中「整条 44px 规则消失」第一版**红在别的断言上**（同块里 `input[type=range]`
也带 44px，把「块内存在 44px 规则」顶住了）⇒ 断言改成判「input 规则**确实**带
44px（选择器与声明同属一条规则）」。

### `check_static_js.py`：`node --check` 前先剥 HTML 注释

注释里只要出现字面量 `<script>`（写注释说明「缺了这个标签」时太自然了），
`SCRIPT_RE` 的非贪婪 `.*?</script>` 就会从假标签一路吞到下一个真 `</script>` ——
把注释正文 + 真脚本的起始标签当成一段内联脚本去校验，报出的「语法错误」和
「未定义函数」两处都指向真实代码之外的行。修 `report.html` 的 i18n 注释时被它咬了
一次。代价是脚本体内的 `<!--` 也会被剥（JS 里的 `<!--` 是远古写法，本仓 0 处，
已全仓扫描确认）。

## 七、顺手记下来的门禁/验证经验

| 经验 | 出处 |
|------|------|
| puppeteer 测窄屏**不要开 `isMobile:true`** —— 它会让 `innerWidth` 比 `clientWidth` 大 ~11px，凭空造出一个不存在的横向溢出，本轮调查被它误导过一次 | `_verify_mobile.mjs` 文件头 |
| 「顶栏遮挡了内容」不能靠比较两个元素的 `top` 判断 —— `.topnav` 是 `.wrap` 的**子元素**，比出来的数没有意义。权威判据是 `document.elementFromPoint()` | `_verify_mobile.mjs` |
| 判「元素被遮挡」要排除顶栏**自己的子元素**（`a.skip-link` / `a.brand` / `button.nav-toggle`），否则一堆假阳性 | 同上 |
| 断言要 grep `[FAIL]` 行，不能 grep 关键词 —— 循环里的断言名会重复，`[OK]` 行会被误当成命中 | 反向验证脚本 |
| 反向验证脚本的备份列表必须**列全所有被注入的文件**，漏一个就会残留到下一个用例，表现为「某个本该无关的断言突然红了」 | 同上（第一版漏了 `silver.html`） |
