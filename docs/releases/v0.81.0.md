## 一、找回密码

### 为什么需要

V0.75.0 上线注册/登录后，**唯一遗失密码的恢复路径是 owner 后台 SQL 直改**。这在
本地单用户场景下勉强能用，多用户场景下不可接受 —— 用户找不回密码就直接
流失。本版把整条「忘记 → 邮件 → 重置」链路打通。

### 端点

| 端点 | 说明 |
|------|------|
| `POST /api/v1/auth/forgot-password` | 输入邮箱 → 始终返回 200（**恒定响应**，防账户枚举） |
| `POST /api/v1/auth/reset-password` | token + 新密码 → 一次性消费，重置成功撤销该用户所有会话 |

### 设计要点

- **存哈希不存原文**：`password_reset_tokens.token_hash = sha256(token)`。
  数据库泄露 ≠ token 泄露。
- **恒定响应时间**：`forgot-password` 即便邮箱不存在也走完整 token 生成 + sleep，
  防「通过响应时间差探测账户是否存在」。
- **邮件限流**：同一邮箱 60s 内最多 1 次（防邮件轰炸）。
- **一次性消费**：token 使用后立即 invalidate；同一 token 第二次提交失败。
- **TTL 24h**：过期后即便命中也失败。

### 测试覆盖

`tests/test_services/test_password_reset_service.py`（36 例）覆盖：
- 哈希生成 + 校验
- 邮件限流触发条件
- token 一次性消费（第二次 401）
- 过期路径
- 重置成功后撤销该用户所有会话
- 用户不存在 vs 邮箱不存在两种输入的等价响应

## 二、用户管理页

### 为什么需要

找回密码后，多用户场景下「owner 一个人能管所有人的账号」是必需能力：
- 某成员离职要**停用**账号（保留数据）
- 有人忘密码且邮箱也失效，要 owner **代重置**
- 重复注册 / 违规账号要**删除**

### 端点（owner 角色才可访问）

| 端点 | 说明 |
|------|------|
| `GET /api/v1/admin/users` | 列出所有用户（分页 + 关键字） |
| `POST /api/v1/admin/users/{id}/reset-password` | owner 代重置密码（自动生成新密码返回） |
| `POST /api/v1/admin/users/{id}/set-active` | 启用 / 停用账号（**不允许 owner 停用自己**，防自锁） |
| `DELETE /api/v1/admin/users/{id}` | 删除账号（同上不允许自删 + 需非 owner 才能删） |

### 设计要点

- **防自锁**：`require_owner` 依赖 + `is_self` 守卫双重保护 —— owner 不能停用 / 删除自己。
- **删除安全**：默认**软删除**（`is_active=False`），保留数据可恢复。物理删除仅在显式传 `?hard=true` 时启用，且保留审计日志。
- **代重置**：owner 改完密后**必须把新密码传达给用户**（无邮件通道）；密码一次性返回，后续不存。
- **角色模型**：`owner`（唯一）/ `member`（普通）两类，schema 层 enum 限定。

### 页面

- `static/admin/users.html`：表格 + 操作列（改密 / 启停 / 删除），全 owner 角色可见
- 账号菜单（auth.js 用户 widget）：新增「用户管理」入口，仅 owner 显示

### 测试覆盖

`tests/test_services/test_user_admin_service.py`（30 例）覆盖：
- owner / member 鉴权分流
- 防自锁（set_active / delete 都不能作用于 owner 自己）
- 改密生成新密码的强度校验
- 软删 + 硬删两条路径
- 用户列表分页 + 关键字过滤
- 跨用户影响隔离（改 A 的密码不影响 B）

## 四、迁移与回滚

### 数据库

新增单表 `password_reset_tokens`（迁移 `b4c6d8e2f0a1`）：
```sql
CREATE TABLE password_reset_tokens (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id),
    token_hash VARCHAR(64) NOT NULL UNIQUE,  -- sha256 hex
    created_at DATETIME NOT NULL,
    expires_at DATETIME NOT NULL,
    consumed_at DATETIME  -- NULL = 未使用
);
CREATE INDEX ix_password_reset_tokens_user ON password_reset_tokens(user_id);
```

⚠ 单步迁移，回滚 `alembic downgrade -1` 即可。

### 无需数据迁移

`users` 表已有 `is_active` / `role` 字段（V0.75.0 加的）—— 直接复用。

### 回滚通道

| 主题 | 回滚动作 |

| 找回密码 | `alembic downgrade -1`；`git revert c493b35 241bbfb 460af8c`；登录页入口消失，端点 404 |
| 用户管理 | `git revert 1cc3362 ee0431f`；`/static/admin/users.html` 不可访问，账号菜单入口消失 |

## 六、安全考量

| 项 | 设计 |
|------|------|
| **token 存储** | 数据库存 sha256(plain_token)，不存原文。库泄露 ≠ token 可用 |
| **响应时间差** | `forgot-password` 走完整 token 生成路径（即便邮箱不存在），防账户枚举 |
| **限流** | 同一邮箱 60s 1 次；同一 IP 5min 5 次 |
| **token 一次性** | DB 唯一约束 + `consumed_at` 字段双重保护 |
| **owner 防自锁** | owner 不能停用 / 删除自己（双重验证：依赖层 + 服务层） |
| **软删除默认** | 保留数据可恢复；硬删需显式 `?hard=true` |
| **代重置密码传达** | 服务端一次性返回，**不持久化**也不邮件发 —— owner 须线下传达 |
