## 〇 一页结论

**症状**：登陆主页（trend.html）信息密度高，时效分散在多处（每张 KPI 卡单独的
fsh-cell + hero `.notice` 重复），上方 11 条链接的单行 nav 在窄屏挤压；投资警示
横幅在每页都占一大块屏幕（旧的 `<div class="warn-banner">`），把下面的图表、
表格、决策面板挤到第二屏。

**根因**：V0.69.0 起时效接入但分散在 3 处，V0.75.0 加 nav 后没回头整合；警示横幅
是 V0.40 时代的「全屏显眼」设计，没跟上 V0.77+ 的「可折叠 + 集中」节奏。

**修法**：V0.83 系列 6 个 commit 拆解

1. **主页 redesign**（commit 1）：双行顶 nav（brand + 11 链接 + emoji 图标）+ 集中
   时效条 `#freshnessInline` 替换 3 处分散 fsh-cell + 警示 disclosure 改
   `<details>` 折叠；
2. **顶 nav i18n 修复**（commit 2）：text 重复 bug 修（`data-i18n` 从 `<a>` 下沉到
   内层 `<span>`，避开 `i18n.js:115-127` 的 `insertBefore` 陷阱）；
3. **a11y 兜底**（commit 3）：warning.js `aria-describedby` 绑定 + theme.css HC
   模式覆盖 + summary 触控目标 `min-height: 44px`；
4. **freshness 优化**（commit 4）：状态签名 `lastSig`/`sig()` 跳过相同状态重渲染
   （避免每 60s 重复 announce）+ help.js 弹窗去重；
5. **8 页面迁移**（commit 5）：silver / portfolio / weights / trades / backtest /
   data-health / central_bank / review 全部套用 V0.83 模式（topnav + warn-footer +
   freshnessInline）；
6. **静态门禁强化**（commit 6）：`check_cluster_render.mjs` 追加 V0.83 节 73 条
   断言 + 新增 `check_i18n_keys.py`（V0.83 命名空间严格模式）+ 新增
   `puppeteer_v083.mjs`（72 组合端到端实跑）。

## 一、问题

### 现象（V0.82 之前的 UI 状态）

- **主页信息密度高**：每张 KPI 卡上面都贴一个 `fsh-cell`，3 张卡 = 3 个时效 chip，
  hero 还有个 `.notice` 文字提示「数据时效 X 分钟」——用户扫一眼看不到全局
  「现在数据是新的还是旧的」；
- **警示横幅占地**：每页都有一段全屏宽度 `<div class="warn-banner">`，5 条 bullet
  写完占 200+ 像素（高于任何面板），把研判主图挤到第二屏；
- **窄屏顶 nav 拥挤**：11 个链接在一行，<768px 时要么横向滚动要么 wrap 破版；
- **重复警示文案**：help.js 数据来源 tab + 各页 warn-banner + settings 帮助区
  三处都有几乎一样的免责文案，3 语各重复 3 次 ≈ 18 条冗余条目。

### 期望体验

- 顶 nav 暗色双行，主链接行 + 时效/警示元信息行；当前页高亮可识别；
- 主页时效**集中**显示在 nav meta 行（一个 chip 反映 3 市场最差状态），hero 释放
  给核心研判图；
- 投资警示**默认折叠**，需要时点开；要 dismiss 有「本次会话不再展开」复选框；
- a11y：键盘焦点 / 屏读器 / 高对比度 / 44px 触控目标都符合 WCAG；
- freshness 重复 announce 减少（屏读器噪音）；
- 8 个迁移页与主页视觉一致。

## 二、修法

### Commit 1：主页 redesign（`7729646`）

- `static/trend.html` 双行顶 nav（`#1f2329` 渐变 + brand + 11 链接 +
  `#freshnessInline` 挂载点）；
- 警示 disclosure 改 `<details id="warnFooter">` 替换旧 `<div class="warn-banner">`；
- 移除 hero `.notice`（与主图标题重复）；
- 新增 `static/warning.js` IIFE helper（sessionStorage `pm_warn_dismissed_session`）。

### Commit 2：顶 nav i18n 修复（`37a5149`）

- `i18n.js:115-127` 的 `insertBefore` 把 `data-i18n` 文本塞到第一个子节点前面，导致
  emoji 图标和文本同时被覆写 → 修复：text 节点下移到内层 `<span>`。

### Commit 3：a11y 兜底（`ed4f886`）

- `static/warning.js` 在 `bind()` 末尾加 `aria-describedby="warnDismissHint"` 绑定；
- `static/theme.css` 加 `[data-theme="hc"] .warn-footer` 4 条覆盖（黄前景 #ffff00 +
  黑背景 #000，WCAG AAA ≥7:1）；
- `static/trend.html` summary CSS 补 `min-height: 44px; box-sizing: border-box`（触
  控目标 ≥44×44 CSS 像素）。

### Commit 4：freshness 优化（`44b98c3`）

- `static/freshness.js` 加状态签名 `lastSig` / `sig()`——相同状态跳过
  `innerHTML` 重写（屏读器不再每 60s 重复 announce）；
- 离线缓存 chip 加 `fsh-cached-chip` class 幂等检查；
- `static/help.js` `renderSourceTab()` 合并重复警示文案，新增
  `help.source_warn_prompt` 3 语指向各页底部 disclosure / `#warn` 深链。

## 三、设计取舍

| 决策 | 选择 | 依据 |
|---|---|---|
| **共享 topnav 抽文件？** | 否（复制粘贴与 trend.html 一致的 markup）| 纯静态 HTML 无 build 步骤；JS 注入 nav 会引入 FOUC 且破坏 view-source UX；后续抽离作为独立 PR |
| **legacy 页用 `#freshnessBar` 还是 `#freshnessInline`？** | 统一 `#freshnessInline` | `freshness.js:142` 已同时接受；与 trend.html 一致是设计目标 |
| **legacy 页 hero `.notice` 去重？** | 否 | EXPL §5 已确认只有 trend.html 重复；其他页 `.notice` 内容不同（central_bank 数据滞后 6-12 个月 / silver AKShare 来源 / portfolio 免责），全部非重复 |
| **data-health.html 蓝色 warn accent `#1d4ed8`？** | 保留 | 诊断页品牌标识；不强行统一为金色 |
| **central_bank.html 4 项 domain-specific warn 文本？** | 保留 i18n keys，只换容器 | 已识别领域特有文案；不迁移到通用 `warn.b*_*`；只包到 `<details>` 里 + 复用通用 `warn.dismiss_session` |
| **portfolio.html 旧 `warn.b1..b5` 整段合并键？** | 改为 `_strong/_rest` 配对 | zh-TW 缺旧 key（成员 1）—— 整段键缺失导致 i18n 静默回退到 zh-CN（参考 MEMORY `frontend-undefined-rendering.md`），配对键复用已有 `warn.b*_*` 命名空间 |
| **trades.html 无 warn-banner？** | 新增 `<details id="warnFooter">` | EXPL §13 列出 trades 无 banner；为对齐统一增加；通用 5 条适合交易语义 |
| **freshness 状态 diff 何时跳过？** | 仅当 sig 字符串完全一致 | 避免每帧重写破坏 a11y announce 时机；离线缓存 chip 仍挂载（`fsh-cached-chip` class 幂等）|

## 五、迁移

**零破坏性**：

- 所有旧 `<div class="warn-banner">` 块已**显式替换**为 `<details id="warnFooter"
  class="warn-footer">`，旧 CSS 选择器仍保留（不影响新 markup）；
- `#freshnessBar` → `#freshnessInline` 是**纯重命名**（`freshness.js:132,198` 同
  时接受两个 ID），无 API 变更；
- i18n 9 条 zh-TW 新增 key 全部为**新增**，未删除任何旧 key；
- 顶 nav 链接 href 一一对应（11 条原链接 + 1 个 brand），无链接断裂；
- Service Worker cache name 随 VERSION 换代（`gold-shell-v0.82.0` →
  `gold-shell-v0.83.0`）—— 用户首次访问新版会清理旧缓存，**预期一次刷新即可
  看到新 nav**。

**回滚路径**：

```bash
git revert ec77ee9 3fdbb85 44b98c3 ed4f886 37a5149 7729646
# 或独立回滚单个 commit
git revert <commit-hash>
```

**部署注意**：

- LAN 部署（`192.168.0.204:8889/gold/`，参考 MEMORY `lan-only-deployment.md`）：
  无变化，照常 `uv sync --frozen && systemctl restart gold-etf-analyzer`；
- PWA 用户：Service Worker 检测到 VERSION 变化会自动激活新版，**首次打开会有
  一次网络刷新**（用户可见一次短暂 loading）；
