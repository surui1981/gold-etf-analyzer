# V0.81.1 · admin token 缺失提示横幅（hotfix）

**发布日期**：2026-10-08
**commit**：`2e9a7c1`
**与上一版本对比**：V0.81.0（2026-10-08，`8fff11a`）—— 同日第二个补丁版

---

## 〇 一页结论

**症状**：局域网里**其他主机**打开页面，第一次保存打分直接 401 `admin token required`，
页面只弹一句干巴巴的英文错误，用户不知道该去哪儿配。
**根因**：V0.80.1 的自动附加头依赖 `localStorage` 的 `pm_admin_token`，而
**`localStorage` 按 origin 隔离** —— 换一台机器（不同 origin）或首次访问就是空的；
那时写请求自然被 `require_admin` 拒掉，而 401 的报错文案完全没有引导。
**修法**：在全局 `patchedFetch` 里拦截 401 且 `detail === "admin token required"`，
弹出顶部黄色横幅（三语文案 + 「去设置」按钮），每会话只弹一次。

**单文件功能改动（`static/auth.js` +90/-1）+ 三语 i18n 各 2 键 + 版本号四处同步。**
无 schema、无后端变动。

---

## 一、问题

### 现象

prod 部署（`APP_ENV=prod` + `.env.prod` 含 `ADMIN_TOKEN`）下，局域网内
**没在设置页配过 admin token 的机器**上：

```
PUT /api/v1/news-score → 401 {"detail":"admin token required"}
```

报错只有一行英文，页面不跳转、不提示去哪儿配 —— 用户只能干瞪眼。

### 为什么 V0.80.1 之后还会出现

V0.80.1 修的是「**配过** token 的浏览器不自动带头」，前提是
`localStorage` 里**已经**有 `pm_admin_token`。而：

- `localStorage` **按 origin 隔离**（协议 + 主机 + 端口），换机器 = 换 origin = 空；
- 首次访问、清过站点数据、隐私模式同理；
- 这三类场景下 V0.80.1 的补丁读到空值 ⇒ 不加头 ⇒ 401，**且没有任何引导**。

⚠ dev 模式 `ADMIN_TOKEN` 不设 ⇒ `require_admin` 直接 return ⇒ **本地与 CI 都看不到**。

## 二、修法

### 在基座里拦截，而不是改几十处调用

`static/auth.js` 是全站基座（每页都加载），`patchedFetch()` 已经在包装所有
`fetch`。V0.80.1 在这里自动**加头**，本版在这里**认错并引导**：

```js
// static/auth.js:243 附近
if (resp.status === 401 && detail === "admin token required") {
  showAdminTokenRequiredHint();
}
```

`showAdminTokenRequiredHint()`（`static/auth.js:125-160`）：

- `sessionStorage` 标记 `pm_admin_token_hint_shown`，**每会话只弹一次**
  —— 否则重试 / 连续写操作会刷屏；
- `injectAdminHintStyle()` 注入 `ADMIN_HINT_CSS`（`static/auth.js:92-113`）：
  顶部 `position: fixed` + `z-index: 9999` 黄色告警条，带 slide-in 动画与移动端响应式；
- 横幅含 ⚠ 图标 + 文案 + 「去设置」按钮 + 关闭按钮，**不阻塞后续操作**
  （用户可先关掉再手动去设置页）。

### 设计取舍

| 取舍 | 理由 |
|------|------|
| **全局拦截而非逐页改** | news / portfolio / weights 等几十处裸 `fetch` 完全不用动；逐个加 catch 会漏 |
| **`resp.clone()` 读 body** | 判 `detail` 需要读响应体，克隆后不影响调用方 `resp.json()` |
| **`sessionStorage` 而非 `localStorage`** | 标记只该活在当前会话；换机器要重新提示一次 |
| **设置页 URL 自适应** | `location.pathname` 含 `/gold/` 时跳 `/gold/static/settings.html`，否则 `/static/settings.html` —— nginx 两个 location 都代理到后端 `/static/` |
| **文案走 i18n** | 新增 `admin_token.missing` / `admin_token.go_settings` 两键，zh-CN / zh-TW / en-US 三语同步（`static/i18n/zh-CN.js:1006-1007`） |

### 版本号换代（必须做）

老浏览器装的 Service Worker 缓存名依赖 `sw.js` 的 `VERSION`，不换代就拿不到新
`auth.js` ⇒ 横幅永远不会出现。按 `src/app/__init__.py:3-13` 的同步清单四处：
`__version__` / `pyproject.toml` / `uv.lock` / `static/sw.js` VERSION 全部
`0.81.0 → 0.81.1`（`sw.js` 的 shell / runtime 缓存名随之换代）。

CI 拿不到这条 401 路径（与 V0.80.1 同一个盲区）：

1. prod 配置启动 uvicorn（`APP_ENV=prod` + `.env.prod` 含 `ADMIN_TOKEN`）
2. 清掉 `localStorage` 的 `pm_admin_token` → 打开 `/static/news.html` → 保存打分
3. 应出现顶部黄色横幅 + 「去设置」按钮（不是只有一行英文报错）
4. 点「去设置」→ 跳设置页；填 token 保存后再回来写 → 横幅不再出现、写入成功
5. 关掉横幅后**同一会话**再触发 401 → 不应重复弹（`sessionStorage` 标记生效）

## 五、遗留

| 项 | 说明 |
|---|---|
| **prod 401 路径无自动化测试** | `tests/conftest.py` 走 dev 路径，`require_admin` 不触发 401 ⇒ 本横幅与 V0.80.1 的自动加头都只能手测。补一个 `ADMIN_TOKEN` 已设的 conftest 变体是根本解法 |
| **服务端 401 文案未细分** | `detail="admin token required"` 不区分「缺头」与「不匹配」。V0.80.1 遗留项里已列（原计划 V0.81.0 做），仍未落地 |
| **`app_settings` 混合表** | admin token 与用户权重混存且双源（表 + `.env.prod`），见 V0.80.0 遗留项 |
