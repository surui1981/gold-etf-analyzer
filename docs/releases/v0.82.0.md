# V0.82.0 · admin session cookie + 单用户模式豁免（LAN 多终端）

**发布日期**：2026-10-09
**commits**：`341934c` `2621cd1` `f46838b` `e0305fe`（+ 版本号 5 处）
**与上一版本对比**：V0.81.1（2026-10-08，`2e9a7c1`）

---

## 〇 一页结论

**症状**：LAN 部署（`192.168.0.204:8889/gold/`）下，**多个终端**首次保存打分
直接 401 `admin token required`，即使按 V0.81.1 横幅提示去设置页配过 token，
**其他终端**（不同浏览器 / 不同设备）打开仍是 401——`localStorage` 按 origin
隔离，配过不算。
**根因**：admin token 校验只走 `X-Admin-Token` header，而 header 来源是
`localStorage.pm_admin_token`——**只对当前 origin 有效**。LAN 跨设备 = 跨 origin
= 空。
**修法**：双管齐下：

1. **Cookie session（端到端）**：新增 `pm_admin_session` HttpOnly cookie，HMAC-SHA256
   签名（30 天 TTL）；settings 页「设置 Session」按钮一次设置，**整个浏览器
   所有同源标签页 / 重新打开** 都自动携带。
2. **单用户模式豁免**：`AUTH_ENABLED=false` ⇒ admin 校验整体 skip ⇒ **根本不
   需要 token**。LAN 默认配置（`AUTH_ENABLED=false`）从此零摩擦。

## 一、问题

### 现象（与 V0.81.1 同源但更深）

V0.81.1 用横幅提示「去设置」——用户去了、配了，**当前浏览器**OK，但：

- LAN 里同事的电脑、手机、平板用同一个 URL，各自 origin 隔离，各需重设一遍；
- 隐私模式 / 清过站点数据 = 又要重设；
- 横幅是**被动响应**（必须先踩 401 才知道要去设置），新用户不知道。

### 期望的 LAN 体验

理想：浏览器打开 URL 即可写，**整个设备生命周期不需要任何手动配置**。
这对单用户 LAN 部署（gold-etf-analyzer 的目标场景）尤其重要。

## 二、修法

### Commit 1：双通道 + 单用户模式豁免（`341934c`）

`src/app/middleware/admin_auth.py`：

- 新增 `pm_admin_session` cookie 名 + 30 天 TTL 常量；
- 新增 `issue_admin_session_cookie_value()` / `verify_admin_session_cookie()`
  两个纯函数（HMAC-SHA256，密钥就是 `ADMIN_TOKEN` env）；
- 新增 `require_admin_session` Depends —— 同时接受 `X-Admin-Token` header 或
  `pm_admin_session` cookie，**任一通过即放行**；
- 保留 `require_admin` 旧语义（仅 header）—— CI / 脚本可不走 cookie；
- **新增单用户模式豁免**：`AUTH_ENABLED=false` ⇒ `get_admin_token()` 返回
  None ⇒ `require_admin` / `require_admin_session` 都直接 skip。

`src/app/dependencies.py:147` 的 `get_admin_token()`：

```python
if not settings.auth_enabled:
    return None  # V0.82：单用户模式 → admin 鉴权整体豁免
```

### Commit 2：admin-token 端点（`c9b8d04`）

新增 `src/app/api/v1/endpoints/admin_token.py`：

- `POST /api/v1/admin-token` —— 校验 body.token 与 `ADMIN_TOKEN` env 匹配后下发 cookie；
- `DELETE /api/v1/admin-token` —— 清 cookie；
- 单用户模式 POST ⇒ 400（提示「单用户模式无需 admin session」）；
- ADMIN_TOKEN 未设 ⇒ 503（配置错误）；
- 错误响应统一 401 + `{"code": "admin_token_invalid"}`，**不区分「缺 vs 错」**防枚举；
- 恒定时间比较（`secrets.compare_digest`）。

### Commit 3：18 处端点迁双通道（`2621cd1`）

把 `news / backtest / account / settings / push / position` 共 6 个端点文件
里 18 处 `Depends(require_admin)` 换成 `Depends(require_admin_session)`，
否则 cookie 即使存在也走不通。

### Commit 4：settings 页 UI + GET 状态查询（`e0305fe`）

- `GET /api/v1/admin-token` → `{has_session, ttl_seconds, auth_enabled}` 状态查询
  （HttpOnly cookie JS 读不到，必须服务端校验后告诉前端）；
- settings.html 新增 Session Cookie 卡片（admin token 输入框下方）：
  - 「设置 Session」按钮：POST + body 带 token → 服务端 HMAC 校验后下发 cookie；
  - 「撤销 Session」按钮：DELETE 清空；
  - 状态行：页面加载时主动 GET 查询 → 显示「已生效 · N 天」/「未设置」/「单用户模式无需」；
  - 单用户模式时按钮禁用 + 灰色提示。
- `/api/v1/admin-token` 加入 `PUBLIC_API_PATHS`（自举端点不能被登录墙挡掉——
  否则「登不进来 → 看不到 cookie 状态 → 永远登不进来」循环依赖）；
- i18n 7 个新 key 三语同步：`section_session_sub / _desc / label_session_token /
  placeholder / unsaved / btn_set_session / btn_clear_session`。

### 附带 fix：Auth/CsrfMiddleware 测试隔离（`f46838b`）

V0.82 commit 1+2 引入 `get_settings.cache_clear()`（admin_token 测试 fixture
里），中间件 `__init__` 缓存的 `self._settings` 仍指向旧对象 → `auth_on`
fixture 改新对象 `auth_enabled=true` 时中间件看不见，csrf cookie 不下发 →
write 端点 403 ⇒ `accounts_api + admin_token_endpoint + auth_api` 三件套
12 fail。

修复：移除 `__init__` 缓存，`__call__` 改用 `get_settings()` 每请求重取
（`lru_cache` 性能可忽略）。生产无影响——settings 在进程内本来就只构造一次；
测试侧从此任意模块都能放心 `cache_clear()`。

## 三、设计取舍

| 取舍 | 理由 |
|------|------|
| **HMAC-SHA256 签名而非服务端 session 表** | LAN 单机部署无 Redis；无状态 cookie 跨重启不失效；签名自带时间戳省一次 DB 读 |
| **Cookie 值含 `issued_at`** | 校验时先比对时间再校验签名（防未来时间戳 + 30 天过期）；时钟容差 ±60s |
| **HttpOnly + SameSite=Lax + Path=/** | XSS 偷不到；同站请求自动携带；LAN HTTP 不强制 Secure |
| **`require_admin_session` 与 `require_admin` 并存** | CI / 脚本可不走 cookie 路径（`X-Admin-Token` 头照常可用）；浏览器 / 桌面端走 cookie |
| **单用户模式 `require_admin_session` 直接 skip** | LAN 部署默认 `AUTH_ENABLED=false` ⇒ 零配置启动；多用户场景需 `AUTH_ENABLED=true` |
| **`/admin-token` 加入 PUBLIC_API_PATHS** | 自举端点不能被登录墙拦——否则未登录用户看不到 cookie 状态、死锁 |
| **错误响应 401 不细分原因** | 防枚举（攻击者无法区分「缺 token」与「token 错」） |
| **GET `/admin-token` 仅返 `has_session` bool** | 不返回 cookie 值 / 签名 / 任何凭据细节；前端只用于 UI 状态显示 |

## 五、迁移

### 从 V0.81.1 升级到 V0.82.0

**零数据库变更 · 零服务端契约破坏 · 零必需配置**：

- 既有 `pm_admin_token` localStorage 仍可用（`auth.js` / `settings.js` 仍读它
  自动加 `X-Admin-Token` 头）；
- `require_admin` 旧 Depends 仍存在（未删除），所以既有用 `Depends(require_admin)`
  的脚本不需改；
- 升级后建议：把所有 LAN 用户的 `AUTH_ENABLED=false`（默认就是 false）→ admin
  鉴权整体豁免，**最省事**；只有多用户场景才需要 `AUTH_ENABLED=true`。

### 推荐配置（LAN 单用户）

`.env.prod`：
```bash
APP_ENV=prod
AUTH_ENABLED=false          # V0.82 起 LAN 默认；省 admin token 配置
# ADMIN_TOKEN 不需要设 —— 整条 admin 校验链完全 skip
```
