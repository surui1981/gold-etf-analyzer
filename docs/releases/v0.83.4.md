## 用户报告

> 主页的数据时效 换一个显示方式，避免这样影响用户体验的设计存在

V0.83.3 修完限速后，再看 freshness 错误态的 UX ——「数据时效加载失败：HTTP 429」红框 + 错误样式 占据顶 nav 整行，**比「显示陈旧数据」更干扰用户**。需要换一种用户友好的降级方式。

## 顺手挖出的关键 bug（用户没报但实际更严重）

V0.83 commit 3 引入 `sig()` 函数做 a11y 优化（避免 aria-live 每 60s 重复 announce），原代码：

```js
function sig(d) {
  return (d && d.degraded ? "D" : "-") +
    ((d && d.markets) || []).map(function (m) {
      return (m.name || "") + "|" + m.freshness + "|" + (m.status || "ok");
    }).join(";");
}
```

但 `/api/v1/market/freshness` 实际返回 `markets` 为 **dict（按市场名 key）**，不是 array。`dict.map` 不存在 → `TypeError`。这个 throw 被 `.catch` 吞了，然后 V0.83.3 之前的代码会走 fsh-error 路径。

**生产影响**：V0.83.0 → V0.83.2 三个版本期间，freshness bar 一直处于「错误态 + 红色显示」状态。puppeteer 测试用 `{"markets":[]}` 假数据掩盖了 bug。

V0.83.4 修复：sig() 与 render() 共用同一组 `order` 序列（`["ny", "sge", "etf"]`），dict/array 兼容。

## UX 重设计

### 旧行为

| 场景 | 显示 |
|---|---|
| 首次失败（429 等） | 🔴 `数据时效加载失败：HTTP 429（不影响页面其他数据）` |
| 后续失败 | 同上（重复） |
| 成功 | 正常 chips |

红色 `fsh-error` 样式 = 用户感知「应用坏了」。

### 新行为

| 场景 | 显示 | class |
|---|---|---|
| 首次失败 | `⏳ 数据加载中…`（中性灰） | `fresh-inline` |
| 成功 → 后续失败 | 保留末次 chips（半透明 .55）+ `⏳ 离线/缓存（数据可能过期）` chip | `fresh-inline fsh-stale` |
| 失败 → 成功 | 恢复正常 chips（清理 stale 状态） | `fresh-inline` |

**关键不变量**：
- **绝不显示** 红框 / `fsh-error` class / 「失败」字样
- 末次数据**保留**（用户能看见市场状态）
- 「离线/缓存」chip 是 amber 警示色（不是红色），表明「数据可能过期」但不暗示「应用故障」

---

## 智能退避（顺便加的）

成功 → 60s 后下一次；失败按指数退避：

```
0 fail → 60s
1 fail → 120s
2 fail → 300s
3+ fail → 600s（封顶 10min）
```

成功一次后重置回 60s。实现：把 `setInterval` 换成 `setTimeout` 自递归，可以动态调整间隔。

**效果**：429 限流时不再每 60s 反复打 API，最多 600s 才重试一次。

## 改动文件

### `static/freshness.js`（核心）

1. **新模块状态**（line 12-19）：
   ```js
   var BACKOFF_MS = [60000, 120000, 300000, 600000];
   var _consecutiveFails = 0;
   var _lastGoodData = null;
   var _lastGoodSig = null;
   var _timer = null;
   ```

2. **新函数 `renderStale()`**（line 38-67）：错误态降级渲染
   - 有 `_lastGoodData` → 在末次数据后追加 stale chip，bar 加 `fsh-stale` class
   - 无 → 显示「⏳ 数据加载中…」（中性）

3. **`sig()` 关键修复**（line 27-43）：dict/array 兼容，与 render() 共享 order 序列

4. **`load()` 重写**（line 247-267）：
   - 成功：清 `fsh-stale` + 重置 `lastSig = null`（确保 render 一定重写 DOM）+ 记末次数据
   - 失败：递增失败计数 + `renderStale()`

5. **替换 `setInterval` → 自递归 `setTimeout`**（line 270-280）：智能退避

6. **CSS 新增 2 条**（line 112-114）：
   - `.fresh-bar.fsh-stale .fsh-chip, .fresh-inline.fsh-stale .fsh-chip { opacity:.55 }`
   - `.fsh-loading-text { color:var(--muted); padding:4px 0 }`

7. **fsh-cached-chip 改色**（line 220）：`fsh-bad`(红) → `fsh-warn`(琥珀)，与「加载失败」红框做语义区分

### `static/i18n/{zh-CN,en-US,zh-TW}.js`（+2 keys × 3 语）

| key | zh-CN | en-US | zh-TW |
|---|---|---|---|
| `fresh.stale_chip` | `⏳ 离线/缓存（数据可能过期）` | `⏳ offline/cache (data may be stale)` | `⏳ 離線/快取（資料可能過期）` |
| `fresh.loading_first` | `⏳ 数据加载中…` | `⏳ Loading data…` | `⏳ 資料載入中…` |

旧 `fresh.load_failed` / `fresh.load_failed_suffix` 保留在字典（其他模块可能用），但 freshness.js 不再引用。
