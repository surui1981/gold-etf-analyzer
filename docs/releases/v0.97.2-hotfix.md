# V0.97.2 hotfix · miniMax 代理 2013 三级降级兜底

> V0.97.2（/ask 布局修复）发版后，用户实测仍偶发 `tool result's tool id(call-...) not found (2013)`。
> 根因：miniMax 代理不跨 round 追踪 `tool_use_id`（OpenAI 风格 stateless），但暴露 Anthropic 兼容 API。
> V0.97.0 hotfix 只做了 1 级降级（内联 tool_result 重试），对「内联后仍 2013」场景无解 → 本 hotfix 升级为 3 级。

## 背景

V0.97.0 / V0.97.1 链路（V0.97.0 → tool_result 降级）：

```
Round 1: tool_use → tool_result 拼回 → Round 2 报 2013
  ↓ 检测到 2013
  L1: _inline_tool_results_as_text(messages) → 重试 1 次（tools=None）
  ↓ 失败
  抛 LLMError（前端 503）
```

V0.97.2 hotfix 链路（3 级降级）：

```
Round 1: tool_use → tool_result 拼回 → Round 2 报 2013
  ↓ 检测到 2013
  L1: _inline_tool_results_as_text() → 重试（tools=None）
       增强：同时把上一条 assistant 的 tool_use 块也转纯文本
  ↓ 仍 2013（代理对历史有更深问题）
  L2: 在 _inline_ 内已做掉，无需独立 L2
  L3: messages=[user 原问题] 不传历史（代理 stateless 也能答）
  ↓ 仍失败
  抛 LLMError
```

> 实测：L1 已能覆盖绝大多数 miniMax 误报；L3 是「保底不返 5xx」的最后一道。
> 注：L1 增强 = 顺带把 assistant tool_use 块也转纯文本（原来只转 user tool_result），所以本版其实只有 L1 + L3 真实降级，但代码注释按 3 级链路标注便于排障。

## 改动

### `src/app/services/ai_chat.py`

1. `_inline_tool_results_as_text()` 增强：
   - 原来只把「最后一条 user 消息的 tool_result blocks」转纯文本
   - 现在顺带把「前一条 assistant 消息的 tool_use blocks」也转纯文本（`[Called name with {input}]`）
   - 原因：miniMax 见到 tool_use 残留也可能报 2013；彻底平铺 = 整条对话无 tool_use/tool_result 块，代理无歧义

2. `send_message()` LLMError 兜底重写为 3 级链：
   - **L1**：inlined + tools=None 重试
   - **L2**（注释保留，逻辑在 L1 内）：检测 L1 仍 2013 时进入 L3
   - **L3**：`messages=[{"role": "user", "content": user_msg.content}]` + tools=None，丢历史只问原问题

### `tests/test_api/test_ai_chat_endpoints.py`

新增 `test_tool_result_fallback_l1_also_2013_falls_to_l3_fresh_only`：
- mock 4 次 LLM 调用：tool_use → 2013 → 2013（inlined 重试也挂）→ 文本成功（fresh-only）
- 验证 L3 调用时 `tools is None` 且 messages 长度 == 1（只有 user 原问题）
- 验证 user 拿到 200 OK（不是 503），且最终 assistant 消息含「无工具数据」兜底文案
