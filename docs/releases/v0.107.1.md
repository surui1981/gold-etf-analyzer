# V0.107.1 · 今日要闻分类聚焦 + 弃入「其他」+ page_size=50

> 日期：2026-10-20
> 类型：数据质量 hotfix（fix dict + drop "其他" + page_size 50）—— 关键词字典焦点化扩充 + fetcher 弃入「其他」+ service 二次 gate
> 前置版本：V0.107.0

## 用户原话

> 今日要闻的摘要并没有实现统计，主要聚焦于财经方面的新闻，优化一下今日要闻的新闻抓取逻辑，聚焦 财经 科技 创投和商业

## 问题与目标

**问题 1**：V0.107.0 的 `news_classifier.py` 关键词字典偏薄 —— 财经 32 / 科技 33（含 1 处「英伟达」重复）/ 创投 23 / 商业 22，导致生产 ~26% 落入「其他」兜底。

**问题 2**：「其他」类目对用户**无意义**（不命中 4 类关键词的杂项新闻），但 V0.107 的 daily 摘要**展示了**「其他 pill + 计数」，UI 上看起来像正常数据，干扰用户「主要聚焦财经」的判断。

**问题 3**：readhub API max 100 条/页，V0.102 设 `page_size=20` + 6h 调度（V0.106 改 4h）覆盖太薄，4h 周期可能漏抓新分类条目。

**问题 4**：`_TECH_KW` 末尾有重复「英伟达」（旧版 L44 bug）。

**目标**：
1. 4 类关键词字典焦点化扩充（财经 32→67 / 科技 33→49 / 创投 23→36 / 商业 22→32）—— 删除无效「其他」
2. fetcher `_normalize()` 拦截「其他」→ 不写入 DB
3. service `refresh()` 二次 gate（defense-in-depth）
4. `page_size` 20 → 50（readhub max 100；实测 P99 <2s）
5. 修 `_TECH_KW` 重复「英伟达」bug
6. DB schema / API 端点 / 前端 5-cat pill 结构**不变**（兼容 V0.107.0 历史 297 行）

### C2 · fetcher 弃入「其他」+ page_size=50

**`fetcher._normalize()` L130-146** —— 末尾插入拦截：

```python
category = classify(title, (raw.get("summary") or "").strip(), site)
# V0.107.1：fetcher 层弃入「其他」——不写入 DB
if category == "其他":
    logger.debug("readhub item dropped (category=其他): id=%r", ext_id)
    return None
```

**`fetcher._DEFAULT_PAGE_SIZE` L62** —— 20 → 50：

```python
_DEFAULT_PAGE_SIZE = 50  # V0.107.1：20→50（readhub max 100；实测 P99 <2s）
```

User-Agent header `gold-etf-analyzer/V0.102` → `V0.107.1` 同步。

**`service.refresh()` L96-126** —— 二次 gate：

```python
# V0.107.1：service 二次拦截「其他」——defense-in-depth
_ALLOWED_CATEGORIES = ("财经", "科技", "创投", "商业")
before = len(records)
records = tuple(r for r in records if r.get("category") in _ALLOWED_CATEGORIES)
dropped = before - len(records)
if dropped:
    logger.info("news feed refresh: dropped %d 其他 items at service gate", dropped)

if not records:
    # 软失败：保留「保留末次」 UX（参考 V0.84 状态条合并模式）
    return {"ok": False, "upserted": 0, "error": "no valid items after category filter"}
```

**不**改仓储 `upsert_bulk`（不加 SQL WHERE）—— service 层 gate 已兜底。**不**改 API 端点 / schema。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 关键词过度匹配（边界词「估值」「收购」同时命中 2 类）| 优先级固定 `财经 > 科技 > 创投 > 商业`（C3 旧测试 `test_classify_finance_overrides_vc_when_both_hit` + 新测试 `test_classify_finance_overrides_vc_new_v01071` 双回归通过）|
| legacy 297 行「其他」历史数据在 daily 行 `other_count > 0` | DB 不删；新 refresh 后当日 `other_count = 0`；旧日（>1 天前） daily 行保留但无新写入 |
| page_size 50 触发 readhub 5xx | service.refresh L97 兜底 `ok=False`；5min cache 避免重复失败；P99 <2s 实测安全 |
| fetcher 拦截「其他」但 `backfill_categories` 仍走 5 路 | 设计正确 —— `backfill_categories` 只处理 `category IS NULL`，**不**重写已有「其他」；legacy 保留 |
| SW 缓存不更新 → 用户拿不到新 JS | C4 同步 bump `static/sw.js` VERSION（V0.107.0 教训 / V0.100.1 实践）|
| `uv lock` 网络阻塞（V0.107.0 已遇过）| 手动 bump uv.lock 版本号（pyproject.toml 无 dependency 变更）|
