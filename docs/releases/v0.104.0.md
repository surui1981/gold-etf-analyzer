# V0.104.0 · headlines 按日期分页（单日模式 + 日期导航）

> 日期：2026-10-19
> 类型：功能（feature）—— 添加按日期分页能力
> 前置版本：V0.103.1

## 用户原话

> 我们在 headlines 添加按照新闻日期的分页功能。这样方便用户查看新闻

## 问题与目标

**问题**：现有 `/headlines` 只有「最近 N 天」窗口过滤（1/7/30 天）。当用户想精准查看某一天（比如 3 天前）的所有新闻时，唯一办法是把窗口拉大到 30 天，被迫看 30 天的列表才能找到目标日期。

**目标**：让用户能「按日期」精准查看某一天的新闻，并支持日期间快速跳转。

**决策（已 AskUserQuestion 锁定）**：
1. **单日模式 + 日期导航**（推荐）—— 工具栏新增 ◀ 前一天 / [日期选择器] / ▶ 后一天 / 回到今日 控件；与现有 1/7/30 天范围互斥
2. **浏览器本地时区** —— 与现状保持一致；用户看到「2026-10-19」= 他电脑上的当天 0:00-24:00

## 关键设计

### 1. UX 工具栏新行

`#dateNav` 默认 hidden（保持 V0.102 工具栏布局），点日期控件触发后显示：

```
┌──────────────────────────────────────────────────────────────┐
│ 时间: [1 天] [7 天] [30 天]  📅 [◀] [2026-10-19] [▶] [回到今日]  来源 ▼ 语种 ▼  ⟳   │
└──────────────────────────────────────────────────────────────┘
```

**互斥规则**：
- 点日期控件 → 清空所有 `#rangeBtns` 的 active，API 改用 `date=YYYY-MM-DD`
- 点 range 按钮 → 隐藏 `#dateNav`，`#datePicker` 复位到今天（仅 UI 显示），API 改用 `days=N`
- `#btnPrevDay` 当 `!has_older` 时 disabled
- `#btnNextDay` 当 `!has_newer` 时 disabled（用户永远在今日或更早，不能看未来）
- `#btnToday` 仅在 `currentDate !== today` 时显示

### 2. 后端 API 改动

#### `GET /api/v1/news-feed/items` 新增 2 query param

| Param | Type | Default | 说明 |
|---|---|---|---|
| `date` | `str \| None` (YYYY-MM-DD) | None | 单日模式：只返回这一天的新闻 |
| `tz_offset_minutes` | `int` | 0 | 浏览器时区偏移（**带符号**，东八区 = +480） |

**与 `days` 互斥**：同时给 → 取 `date`，`days` 忽略

#### Schema `NewsFeedListOut` 新增 3 字段

```python
current_date: str | None = None  # 回显的 date（YYYY-MM-DD）；None = days 模式
has_older: bool = False          # 这一天之前是否还有更早的新闻
has_newer: bool = False          # 这一天之后是否还有更新的新闻
```

`total` 语义保持不变（`= len(items)`），**0 字段破坏**：现有 6 个测试断言 `data["total"] == len(items)` 不变

#### Repository 核心 SQL

```python
if date is not None:
    tz = timezone(timedelta(minutes=tz_offset_minutes))
    day_start = datetime.combine(date, time.min, tzinfo=tz)
    day_end = datetime.combine(date + timedelta(days=1), time.min, tzinfo=tz)
    stmt = stmt.where(and_(
        NewsFeedItem.publish_date >= day_start,
        NewsFeedItem.publish_date < day_end,
    ))
elif days is not None and days > 0:
    # 旧逻辑保留（V0.103 byte-identical）
    cutoff = datetime.now(timezone.utc) - timedelta(days=days)
    stmt = stmt.where(NewsFeedItem.publish_date >= cutoff)
```

#### `has_items_outside_day()` 2 个 EXISTS 查询

```python
async def has_items_outside_day(self, *, day_start, day_end) -> tuple[bool, bool]:
    older_stmt = select(literal(1)).where(NewsFeedItem.publish_date < day_start).limit(1)
    newer_stmt = select(literal(1)).where(NewsFeedItem.publish_date >= day_end).limit(1)
    has_older = (await self._s.execute(older_stmt)).first() is not None
    has_newer = (await self._s.execute(newer_stmt)).first() is not None
    return has_older, has_newer
```

不走 COUNT，LIMIT 1 存在性查询走 `ix_news_feed_items_publish_date` 索引 < 5ms

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 时区偏移符号约定 JS vs Python 易混 | `tzOffsetMinutes = -getTimezoneOffset()`；2 个测试用例固化 |
| `has_older` / `has_newer` 多 2 个 EXISTS | 现有 `news-feed/status` 同模式，N+2 在 SQLite 走索引 < 5ms |
| `<input type="date">` 老 Safari 不一致 | 现状 scoring.html / trades.html 已用，无反馈 |
| 现有 6 个测试断言 `data["total"] == len(items)` | `date=None` 时 SQL 与 V0.103 byte-identical |
| `has_older=true` 但 limit=100 时 ◀ 可能 0 条 | 接受现状（进阶 next_day/prev_day 字段下版本做） |
| 改 static HTML/JS → SW VERSION 必须 bump | C5 同步 bump 到 v0.104.0 |
