## 五类改动

### 1. CSS 基础 · `print.css` 全局 print 模板（C1）

**`static/print.css`**（4.3 KB / ~80 行）—— 单块 `@media print { ... }`：

- `@page A4 + 14mm 边距`（装订位 + 节省版面）
- **强制 `print-color-adjust: exact`**（深色主题下 chrome 颜色不被浏览器"省墨"反转为白底白字）
- 隐藏全站 chrome：`.topnav` / `.status-panel` / `.nav-btn-export` / `.btn` / `footer` / 时效条 / 警示 / 悬浮按钮 / `canvas`
- 链接 URL 显式展开（`a[href]:not([href^="#"])::after { content: " (" attr(href) ")"; }`）—— 翻 PDF 看到"查阅某页"链接的完整地址
- 表格印刷友好：`border-collapse: collapse` + `tr/thead/tbody { page-break-inside: avoid; }`
- 报告页专属 `.report-cover` / `.report-section` / `.decision-row` / `.snapshot-missing` 类

**`media="print"` 仅 print mode 加载**（零运行时成本）。

### 2. 跨页上下文 · `nav-context.js` 跨页读写（C3）

**`static/nav-context.js`**（6.7 KB / ~120 行）—— IIFE 暴露 `window.PM_NavContext`：

- **白名单 key**：`fStart / fEnd / fSide / fPosition / fKeyword / fSize / target / horizon / days / snapDays / klineDays / klineInterval / filterCountry / filterFrom / filterTo / compressThreshold`
- **`get(key)`** —— 优先 URL `?` query 串，回退 `pm_ctx_v1_<key>` localStorage
- **`write(key, value)`** —— 写 LS + 派发 `nav-context-changed` CustomEvent（与 `account-changed` 范式一致）
- **`apply(map, defaults?)` / `bind(map, onAfter?)`** —— mount 时按 `{key: "#selector"}` map 把 LS 写到 input/select；change 事件触发回写
- **`buildQuery(keys)` / `updateUrl(keys)`** —— 拼/同步 URL 串
- **`buildReportUrl({from, to, days, account_id})`** —— 顶栏导出按钮专用，自动带账本

**版本化命名空间 `pm_ctx_v1_*`** —— 借鉴 `pm_help_seen_version` 升级机制（V0.58.0 help.js）；未来字段增删可改 v2 强制重置，零迁移成本。

**避坑**：与 `review.html` `#status` hash 冲突（warning.js 占用）→ **不用 hash 存 context**，全程 `?` query 串（agent 警告 R1）。

### 3. 顶栏 📄 导出按钮（C4）

**`static/topnav.js`** 改造（V0.84.0 同步注入保持不变）：

- `buildExportButton()` 新增单点模板（**不进 NAV_LINKS** —— 按钮不是链接，单独模板）
- `openReport()` 优先调用 `PM_NavContext.buildReportUrl({days})`；fallback 内联保底（防御：单页加载顺序异常时仍可工作）
- `document.addEventListener("click", ...)` 事件委托 —— 9 页所有 nav 按钮实例复用一次

**9 页统一**：`portfolio / trades / weights / review / central_bank / silver / backtest / trend` 由 `topnav.js` 自动注入；`news.html` 单独内联（该页用硬编码 nav，未走 topnav.js）。

### 4. 报告页 · `report.html` + `report.js` 5 段完整版（C5）

**`static/report.html`**（6.2 KB / ~200 行）—— 5 段结构 + i18n 全覆盖：

- 工具栏（`.no-print` 屏上交互；print mode 隐藏）：days 预设按钮（7/30/90/180）+ 账本显示 + 「生成报告」+ 「打印 / 另存为 PDF」+ 「返回」
- 封面（`.report-cover`）：标题 + 统计区间 + 账本 + 生成时刻
- 5 段主体：持仓（`#positions-body`）/ 时间线 / 消息面 / 收益曲线 / 央行购金
- 状态条（与 9 页统一，print.css 隐藏）

**`static/report.js`**（16 KB / ~250 行）—— 6 端点并行 + 5 段渲染：

- `parseContext()` —— URL `?days= / ?from= / ?to= / ?account_id=` 优先；`pm_ctx_v1_days` + `gold_account_id` 兜底；默认 30 天 / "all"
- `Promise.allSettled([positions, timeline, news-history, news-today, equity-curve, central-bank])` —— 任一失败不影响其他段渲染（R10 缓解）
- `renderPositions / renderTimeline / renderNews / renderCurve / renderCentral` —— 纯表格 + 文字摘要；不画 Chart.js canvas（R2 缓解）
- `decision` 段：`trade.side === "buy" ? "买入" : "卖出"` + 数量 / 价格 / 当时 `trend_index`（颜色按档位）
- `idle compressed` 段：单行 `"{n} 天空闲（已折叠）（{start} ~ {end}）"`
- `snapshot === null` 段：显式标 "数据缺（节假日）" 灰色（**不**兜底 50 —— V0.78.0 Step D 纪律）
- equity-curve 采样：每 5 日 + 首尾
- central-bank 排序：按 `tonnes_net` 降序取前 20

## 教训

1. **V0.88.0 sw.js VERSION 教训生效**：本版 4 处版本号同步一次性完成；`uv lock` 1ms 验证 lockfile 一致；末步 PWA 资源门禁 + routes 门禁全绿 — 严格遵循 MEMORY `sw-version-sync-gate.md` 4 处同步清单。
2. **i18n 自动化门禁救命**：`test_all_data_i18n_keys_resolve_in_zh_cn` 当场捕获 `status.summary_text` 漏声明（R13），避免发版后用户切到 en-US / zh-TW 看到 raw key。**对策**：V0.92+ 加 1 条「新增 data-i18n 属性必须先在 zh-CN 声明 key」lint。
3. **顶层 nav-context.js 命名空间 v1 版本化**：D5 决策 — 借鉴 `pm_help_seen_version` 升级机制。未来字段增删可改 v2 强制重置，零迁移成本。
4. **5 段 vs 2 页的矛盾**：V0.74.0 M7 原路线图写"≤ 2 页"（agent 调研 R2 缓解：canvas 在 print 模式空白），本版走"完整版 5 段 3-5 页"（D2 决策）。月报给合伙人/家人需要全维度，密度优先。**对策**：V0.92+ 可加"精简版 2 页"开关（仅封面 + 时间线 + 消息面摘要），用户自选。
5. **同一 task schema 漏配教训再次衍生**：V0.79.0 任务 #162 加了 `tech_detail` 列 + schema 暴露 + 数据落库三件套；同期 `macro_detail` 做了前两件但漏第三件 ⇒ 漏 6 个版本到 V0.90.0 才修。V0.91.0 报告页消费 timeline / macro_detail 时，**puppeteer mock 必须用真实 schema**（参考 [V0.83 sig() dict bug 教训](sig-dict-bug-v083.md)）。
6. **事件委托 vs 直接绑定的取舍**：顶栏导出按钮 9 页共用，事件委托 `document.addEventListener("click", closest)` 一次即可。trade.html / review.html 等的 filter change 监听既有直接绑又有冒泡委托，**两种并存不冲突**（DOM 事件流：input listener 先 fire，parent delegated handler 后 fire）。
7. **i18n FOUC guard 与 nav-context 同源**：都同步读 LS → DOMContentLoaded 时再应用。比改 `defer` 脚本顺序更稳定 —— 浏览器对 head 内 defer 脚本的执行顺序有规范，但对 body 内同步脚本 + DOMContentLoaded 的组合行为更可控。
8. **静态 JS 门禁兜底**：`check_static_js.py` 自动扫描 16 个静态页内联脚本 + 29 个共享脚本（语法 / 引用 / DOM id）—— 本版新增 `report.js / nav-context.js / topnav.js` 改动全部 1-click 通过，无回归。
