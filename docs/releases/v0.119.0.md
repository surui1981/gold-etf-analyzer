> **发版日期**：2026-10-27 ｜ **类型**：feature ｜ **上一版**：[V0.118.1](v0.118.1.md)
>
> **一句话**：宏观面此前的 8 个因子**全部是市场价格或准市场价格**（美元 / 美债 / VIX /
> 央行购金）—— 没有一个因子反映「政府资产负债表」这条线。2025-2026 年市场的主线叙事

## 一、权重分析（本次要拍板的事）

### 1.1 符号方向 —— 债务↑ 对黄金是利多还是利空？

两条互相冲突的通道：

- **debasement / 财政货币化**：债务↑ → 货币贬值与购买力受损风险↑ → **利多黄金**
- **挤出 / 实际利率**：债务↑ → 风险溢价与实际利率↑ → **利空黄金**

历史证据显示**符号是 regime 依赖的**，不是恒定的：

| 区间 | 美国债务/GDP | 黄金 | 是否符合 debasement |
|------|------------|------|--------------------|
| 2008-2012 | 52% → 82% | 833 → 1660 (+99%) | ✅ |
| 2012-2016 | 82% → 105% | 1660 → 1150 (-31%) | ❌ |
| 2022-2025 | 128% → 122%（回落） | 1810 → 3400+ (+75%) | ❌ |

**取舍**：模型里已经有 `real10y`（18%）在承担「实际利率↑ → 金价跌」这条通道。
若债务因子也取负号，等于把同一条逻辑数两遍。取正号（debasement）才是模型里
**真正缺的那条轴**。

> ✅ **已定：三个因子同号，`positive=True`（债务↑ = 利多黄金，debasement 口径）。**

### 1.2 阈带（best / worst）

`score = clamp((value - worst) / (best - worst) * 100, 0, 100)`，best=100 分、worst=0 分。
沿用现有因子的惯例：**「债务真正影响黄金的那段区间」**，而不是 1960s-80s 低债务时代。

| key | best | worst | 当前读数 → 分数 | 依据 |
|-----|------|-------|----------------|------|
| `us_gov_debt` | 140 | 60 | 122.59 → **78.2** | 1990s 约 60%；2020 峰值 132.7 |
| `cn_gov_debt` | 95 | 40 | 88.33 → **87.9** | 2013-15 约 40%；2024 创历史新高 |
| `eu_gov_debt` | 95 | 60 | 82.9 → **65.4** | 2000-08 约 60-70%；2020-21 峰值 91.4 |

### 1.3 权重分配 —— 旧 8 个按比例缩放，新组占 12%

新增 3 个因子 = **同一个全球财政周期信号的三份读数**，高度共线。三份各给权重
= 同一件事说三遍（这正是 V0.118.0 把三档名义利率压到 20% 的同一条理由）。
所以：**按「一个组」定总权重，组内再按各自对黄金的相关性分配**。

- **美国 5%** —— 储备货币发行国的债务上限 / 期限溢价是当前市场主线；缺点是与
  `real10y` + `dxy` 重复度最高。
- **中国 4%** —— 债务率五年从 59% 冲到 88%（三者中最快），且与模型里全是美国口径的
  `real10y` / `dxy` **相关性最低**；对一家中国黄金 ETF 而言，财政扩张 → 国内金需求
  是真实传导（央行购金也已被 `cb_gold` 部分覆盖）。
- **欧洲 3%** —— 债务率最稳、黄金市场 beta 最小（欧央行几乎不购金）。

> ✅ **已定：12% = 美 5 / 中 4 / 欧 3**，旧 8 个按 **×0.88 等比缩放**（相对比例完全不动）：

| 因子 | V0.118.0 | V0.119.0 | Δ |  | 因子 | V0.118.0 | V0.119.0 | Δ |
|---|---|---|---|---|---|---|---|---|
| dxy 美元指数 | 15% | **13%** | −2 | | cb_gold 央行购金 | 25% | **22%** | −3 |
| us2y | 6% | **5%** | −1 | | us_gov_debt 美国 | — | **5%** | +5 |
| us10y | 8% | **7%** | −1 | | cn_gov_debt 中国 | — | **4%** | +4 |
| us30y | 6% | **5%** | −1 | | eu_gov_debt 欧洲 | — | **3%** | +3 |
| curve_10y2y | 10% | **9%** | −1 | | | | | |
| real10y | 20% | **18%** | −2 | | | | | |
| vix | 10% | **9%** | −1 | | **合计** | 100% | **100%** | 0 |

分组看：美元 13% / 名义利率水平 17% / 曲线形态 9% / 实际利率 18% / 风险偏好 9% /
结构性需求 22% / **政府债务 12%**。

### 1.4 诚实的保留意见

这一组是**近乎恒定的偏移**，不是择时信号。债务水平一年才动 1-4 次，把它当 12% 的
权重，等于把「结构性看多黄金」这个判断固化进模型。它的价值是**分散化 + 一个慢锚**，
不是预测力。

**2026-10-26 线上实测**（`/api/v1/market/gold/trend`，11 因子全在）：

| 项 | 值 |
|---|---|
| 宏观面指数（含债务组） | **38.9**（BEARISH，方向不变） |
| 旧 8 个因子单独归一后的指数 | **33.6** |
| 债务组带来的净抬升 | **+5.3 分** |

**2026-10-27 复测**（重启 8888 后同一端点，同一算法）：

| 项 | 值 |
|---|---|
| 宏观面指数（含债务组） | **38.1**（BEARISH，方向不变） |
| 旧 8 个因子单独归一后的指数 | **32.65** |
| 债务组带来的净抬升 | **+5.47 分** |

⇒ 绝对分数会随 7 个日频因子的滚动分位漂移（38.9 → 38.1），但**债务组的净抬升
两天都在 +5 分上下**（+5.3 / +5.47）⇒ 抬升来自**因子本身**（债务组自身均分
77.8 / 78.2），不是某一天的读数巧合。

⚠️ **方向断点不是常数**：计划期按静态阈值估算过「组权重 ≈18.7% 时宏观面从 BEARISH
跳到 NEUTRAL」，但线上那 7 个日频因子的分值走的是**滚动分位**（`macro_dynamic=true`）
⇒ 它们的分值会随市场漂移 ⇒ 断点也跟着动。10-26 读数下断点在 **≈25.6%**，
10-27 读数下 **≈27.1%**。
**结论不变**：本版取 12%，宏观面方向不变；断点是**要盯着的量**，不是一次性算完的常数。

## 二、数据源（三个源**逐个实测可用**，非推测）

| 因子 | 源 | 最新读数 | 口径 | 频率 |
|------|----|---------|------|------|
| 美国政府债务/GDP | FRED `GFDEGDQ188S`（CBO） | **122.59**（2026Q1，期末 2026-03-31） | 联邦债务/GDP | 季度 |
| 中国政府债务/GDP | FRED `GGGDTACNA188N`（IMF WEO） | **88.33**（2024，期末 2024-12-31） | 一般政府总债务/GDP | 年度 |
| 欧洲政府债务/GDP | Eurostat `GOV_10Q_GGDEBT` | **82.9**（2026-Q2，期末 2026-06-30） | 一般政府总债务/GDP（马斯特里赫特） | 季度 |

- **欧洲口径 = 欧盟 27 国**（`EU27_2020`），不是欧元区 20 国（`EA20` = 89.3）。
- ⚠️ **FRED 的低频序列只有实际值**（预测值不进这条序列）⇒ 中国年度序列的观测年
  **本身就落后日历 1-2 年**。这是源的性质，不是我们的 bug。
- ⚠️ **FRED 季度序列用季初日期**（`2026-01-01`）、年度用年首（`2024-01-01`）；
  Eurostat 用 `"2026-Q2"` 标签 —— `Date.parse('2026-Q2')` 是 `NaN`。
  ⇒ 所有低频 `data_date` 必须归一到 **ISO 期末日期**（季度 +3 月 −1 天；年度 +12 月 −1 天；
  `"2026-Q2"` → `2026-06-30`）。这是本版最容易静默出错的一处。
- ⚠️ **UA 规则（实测）**：FRED = **不带 UA**；Yahoo / 美联储 H.15 = `Mozilla/5.0`；
  Eurostat = **无 UA 限制**。
- ⚠️ `fetch_fred_latest(lookback_days=30)` 永远找不到季度 / 年度序列 ⇒ 改用按序列
  独立的 lookback（季度 200 天 / 年度 900 天）。

## 三、本版新增的两处机制

### 3.1 低频因子的滞后口径（`cadence` + `max_lag_days`）

`static/weights.html` 的滞后 chip 阈值原先硬编码 `AUTO_LAG_WARN_DAYS = 4`（日历日）。
新因子的 data_date 分别是 2026-03-31 / 2026-06-30 / 2024-12-31 ⇒ 滞后
209 / 118 / 664 天 ⇒ **每次都亮「滞后 N 天」红灯**。而这恰恰是季度 / 年度数据的
正常状态。**常亮的告警等于没有告警**（freshness 降级 UX 纪律）。

**修法**：因子规则新增 `cadence`（daily / quarterly / annual）与 `max_lag_days`
（日频 4 / 季度 300 / 年度 **1100**），经 API 字段 `MacroFactorOut.cadence` /
`max_lag_days` 透出；前端对 `cadence != daily` 的因子改挂**中性「季度 / 年度」chip**，
滞后告警只在超过 `max_lag_days`（= 源真的断了）时才亮。
（`cb_gold` 顺带归为 quarterly —— 它的 data_date 是自由文本，滞后本来就解析不出来。）

> ⚠️ **年度阈值从 550 改成 1100 天**（≈3 年，不是 1.5 年）。
> 实测 2026-10-26：FRED 的 IMF WEO 年度序列最新观测是 **2024-12-31 = 664 天前**。
> 拿 550 天当阈值 ⇒ 这一行**永远亮红灯**。3 年的语义 = 「WEO 连续 2 次年更没更新」
> 才算源真的断了。回归测试 `test_gov_debt_lag_threshold_covers_current_observation_age`
> 锁住「阈值必须覆盖当前观测年龄」。

### 3.2 后端自己声明「哪些因子可滚动」（`rolling_factors`）

`static/trend.html` 与 `static/silver.js` 的「N/M 因子使用滚动分位」原先是
`factors.filter(f => f.key !== "cb_gold").length` —— 再加 3 个 skip 因子就要改两处
硬编码列表（必然腐化）。

**修法**：`MacroIndexOut` 新增 `rolling_factors: list[str]`（后端算出可滚动因子清单），
前端直接用它的长度。后端侧 3 个新因子与 `cb_gold` 一起进 `SKIP_ROLLING_FACTORS`
—— 季度 / 年度因子若参与 252 日滚动分位，日频落表会把同一个值重复几十次 ⇒
P10 == P90 ⇒ 阈值退化，且样本不足会让 `is_dynamic_active` 把**整个宏观面**的
「滚动分位」标识打掉。

### 3.3 8 键 → 11 键的权重迁移守卫

`src/app/schemas/settings.py` 的 `LEGACY_MACRO_DEFAULTS` 是 **5 键**（V0.117）的旧默认。
8 → 11 之后，**存量 8 键默认配置会走进按比例缩放分支**，用户拿到 dxy 13.2% 这类
缩放值，而不是设计好的新默认。

⇒ 新增 `LEGACY_MACRO_8_DEFAULTS`（V0.118 的 8 键默认），迁移时并列判断
（这正是「旧默认值也是一种用户状态」那条教训）。

实测迁移口径：

| 存量状态 | 结果 |
|---------|------|
| 5 键默认（V0.117） | 直落新 11 键默认 |
| 5 键**自定义** | 按比例缩放（×0.56）保留用户意图 |
| 8 键默认（V0.118） | 直落新 11 键默认 |
| 8 键**自定义** | 按比例缩放（×0.88）保留用户意图 |

### 3.4 回测网格**不动**

`src/app/schemas/backtest.py::MACRO_DIM_FIELDS` 锁 5 键、`static/backtest.html` 的
`MACRO_FIELDS` 也是 5 键。新因子**没有历史快照** ⇒ 加进网格会让
`_aggregate_from_detail` 对每个历史快照返回 `None` ⇒ 回测出 0 行（V0.118.0 刚修的 bug）。
⇒ **保持 5 键不动**。

> ⚠️ **门禁自身的断言也踩过一次「只能绿一次」的坑**：读数断言原本用
> `text.includes(String(exp.value))` 的**子串匹配**，`exp.value` 写的是内置兜底值
> `88.33`。上游源挂着时（`tier=static`）渲染出来正好是 `88.33` ⇒ 门禁绿；
> **上游源一恢复**（`tier=live`）服务端用 `f"{value:g}"` 渲染成 `88.327`
> ⇒ 子串 `"88.33"` 不在 `"88.327"` 里 ⇒ **门禁翻红**。
> 修法：断言改**数值比较 + 0.01 容差**（`numEq`），期望值填 live 源原始读数
> （`122.59387` / `88.327` / `82.9`）—— live 与 static 兜底两种取值都能通过。
> 教训：**门禁的期望值必须写成「源的真实输出」，不是「某个方便的字面量」**。
