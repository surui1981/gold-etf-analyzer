## 先说一个走错的岔路

第一次诊断量到 `window.marked` 是 `undefined`，差点下结论「marked 没加载、
所有回复都退化成纯文本」。翻 `static/marked.min.js` 才发现这版（v12.0.2）
**不暴露 `.version` 字段**，`window.marked` 本身好好的。

**markdown 引擎没坏，坏的是它外面的东西。** 下面 6 条全部是实测出来的，
诊断脚本 `scripts/_diag_ask_*.mjs` 留在仓库里可复现。

## 六项缺陷

### P0 · 安全：清洗器只拦住 8 个事件处理器里的 1 个 🔴

`static/ask.js` 原来的清洗器是**正则**，而且正则写错了：

```js
.replace(/\s(onc(?:lick|load|error|mouseover|focus|blur|change|submit)\s*=\s*["'][^"']*["'])/gi, '')
```

`on` 后面多了个 `c`。`onc(?:…)` 只能拼出 `onclick`；另外 7 个分支写的是全名
（`load` / `error` / …），**永远接不到 `onc` 后面**。实测：

| `onclick` | `onload` | `onerror` | `onmouseover` | `onfocus` | `onblur` | `onchange` | `onsubmit` |
|---|---|---|---|---|---|---|---|
| ✅ 拦住 | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |

把 `<img src=y onerror="…">` 灌进真实页面，**属性原样进了 DOM**（`onerror` 没触发
只是因为 `/ask/y` 返回 200、图片加载成功 —— 证明的是「注入成功」不是「执行成功」）。

而且即使把正则改对，仍可绕过：`<div style="background:url(javascript:alert(1))">`
**今天就已经活着**（原清洗器根本不管 `style`）。

### P1 · 移动端横向裁切（静默，量得到）

含不可断词的消息会把对话列撑出视口，而 `document.scrollWidth` 仍是 390 ⇒
**尾巴被裁掉且滚不过去**（`overflow:auto` 的滚动容器里，超出部分够不着）：

| 内容 | 对话列宽（390px 视口） | 被裁掉的元素右缘 |
|---|---|---|
| 表格 | 389 ✅ | 无 |
| `<pre>` 代码块 | 431 ❌ | `PRE` right=407（裁 17px） |
| 长 URL | 613 ❌ | `P` right=589 / `A` right=587（**裁约 200px**） |

根因：flex item 默认 `min-width: auto`（automatic minimum size），
**包含块自己先变宽了**，`max-width: calc(100% - 50px)` 和 `word-wrap: break-word`
都救不了。现有 `scripts/_verify_mobile.mjs` 确实覆盖 `/ask`，但只加载**空页面** ——
内容驱动的溢出它在原理上看不见。

### P2 · 标题 / 分隔线零间距

`static/ask.html` 的 `* { margin: 0; padding: 0; box-sizing: border-box }` 把一切清零，
`.message .bubble` 只补回了 `p / ul / ol / table / blockquote` 的间距，
**漏了 `h1`–`h6` 和 `hr`**。实测 `h2` margin `0px 0px`、字号 19.5px 挤在 13px 正文里；
`hr` margin `0px`，top=682 紧贴下一段 top=684（贴脸）。AI 输出里 `##` 和 `---` 满屏都是。

### P3 · 气泡套气泡 → 双边框 + 双内边距

`renderAssistantMsg` 建了一个 `.bubble`，又建一个把它塞进去。
`.message.assistant .bubble` 两个都匹配上 ⇒ **两层边框 + 16px/24px 内边距**。截图肉眼可见。

### P4 · 表格无横向滚动容器

`theme.css` 已有 `.table-scroll` 约定（全站 11 张表在用），对话气泡里的表格没套。
宽表在窄栏里会被压到换行或溢出。

### P5 · 体验缺项

代码块无复制按钮（AI 常返回 JSON/JS）、链接无 `target/rel`（点进去丢对话状态）。

## 改动

### C1 · 清洗器换成本地 DOM 白名单（`static/ask.js`）

删掉正则版 `sanitizeHtml`，换成 DOM 遍历白名单：

- `new DOMParser().parseFromString(html, 'text/html')` 解析到**游离文档**（不碰当前 document）
- **DROP 集合**（连子节点一起删，不是 unwrap）：`script` `style` `iframe` `object`
  `embed` `noscript` `template` `svg` `math` `textarea` `title` `xmp` `frame`
  `frameset` `base` `link` `meta` `form` `input` `button` `select` `option`
  `audio` `video` `source` `img`
- **KEEP 集合**：`p br strong b em i del s code pre blockquote ul ol li dl dt dd
  h1..h6 hr table thead tbody tfoot tr th td caption a span div sup sub small mark`
  —— 其它标签 unwrap（保留文字，丢标签）
- 属性：**只允许 `a[href]`（限 http/https/mailto/`/`/`#`）与 `a[title]`**；
  `on*` 与 `style` 无条件 `removeAttribute` —— 不靠正则判断，靠「不在白名单就删」
- 不放 `img`：避免外链追踪像素

**无正则 ⇒ 不存在「漏写一个字符」这类坑；不引第三方 ⇒ 无供应链面、可逐行审计。**
（用户已明确选择本地白名单而非 vendor DOMPurify。）

### C2 · 移动端不裁切（`static/ask.html` CSS）

```css
.ask-main, .message-stream { min-width: 0; }   /* 链条要一路通到最外层 */
.message, .message .bubble { min-width: 0; }
.message .bubble p, li, td, th { overflow-wrap: anywhere; }
.message .bubble { overflow-wrap: anywhere; }   /* 用户气泡走 textContent，无 <p> 包裹 */
```

最后一条**不能少**：用户气泡的文本是 `.bubble` 的直接子文本节点，上面按
`p/li/td/th` 写的规则根本命中不到它。实测漏掉这条时，用户发一条长 URL 会把气泡
撑到 525px（视口只有 352px）。

`anywhere` 与 `break-word` 的关键差别在 **min-content 计算**：
`break-word` 不影响最小内容宽度，所以挡不住「把整列撑宽」。

> ⚠ 期间踩过一个静默坑：`.message .bubble` 上原本有一条**靠后**的
> `word-wrap: break-word`，而 `word-wrap` 是 `overflow-wrap` 的**别名** ——
> 同优先级下后者静默覆盖前者。删掉那条旧的才看到计算值变成 `anywhere`。

### C3 · 排版补齐 + 去双气泡

- `.message .bubble h1`–`h6` 给适合 13px 正文的字号阶梯（17 / 15.5 / 14 / 13 / 13 / 13 px）
  + `margin: 10px 0 4px` + `:first-child { margin-top: 0 }`
- `.message .bubble hr { margin: 10px 0; border: 0; border-top: 1px solid var(--border) }`
- `strong { font-weight: 600 }` / `em { font-style: italic }` / `del { color: var(--muted) }`
- `renderAssistantMsg` 去掉外层多余的 `.bubble`，改用只做布局的 `.bubble-wrap`

### C4 · 渲染后增强管道（`static/ask.js`）

新增 `enhanceBubble(bubble, isFinal)`：

- 每个 `table` 外面套 `.table-scroll`（复用 `theme.css` 约定，按全站惯例加
  `tabindex="0" role="region"`，键盘可横滚）
- 每个 `pre` 加复制按钮（`navigator.clipboard` + `textarea/execCommand` 降级）。
  按钮排在自己的**工具条行**里（`.code-block` flex column），不叠在代码上 ——
  两个原因都是截图实测出来的：`<pre>` 自己 `overflow-x:auto`，按钮放它里面
  横向一滚就被带走；改放外面做绝对定位、给 `<pre>` 加 `padding-right` 也**没用**，
  **滚动容器的 `padding-right` 只在滚动末端生效**，`scrollLeft=0` 时长代码行
  照样从按钮底下穿过去（截图里第一行 JSON 被 ⧉ 压住）
- 每个 `a` 补 `target="_blank" rel="noopener noreferrer"`（站内 `/` 与锚点 `#` 不动）

挂在两处：
- `renderAssistantMsg`（历史消息 + `message_stop` 后终稿）→ `isFinal=true`，带按钮
- `flushBubble`（流式，80ms 节流）→ `isFinal=false`，**不挂按钮**
  （否则每秒重建 12 次按钮）

两条路径都是先 `innerHTML=` 再增强，天然幂等（门禁连挂 3 次验证不重复套壳）。

### C5 · 提示词显式要 markdown（`src/app/services/ai_chat/prompts.py`）

新增第 5 条：多部分内容用 `##` 小标题分隔、关键数字**加粗**、多项对比用表格、
多步骤用有序列表、原始数据片段放代码块。后面几条顺次后移（6/7/8）。

实测 AI 本来就在用 markdown，这里只是把它从「碰巧」变成「约定」。
配套补 5 条 pytest（含**规则号 1..N 连续无重复** —— 插入一条时最容易忘改后面的号）。

### C6 · 门禁 `scripts/_verify_ask_format.mjs`（97 条断言）

1. **清洗器**（18 个用例 + 8 个事件处理器 + 源码形态检查）
2. **移动端 390px**：4 种内容 × 2 种真实形状，每种 4 条断言
3. **计算样式**：直接断言 `overflowWrap` / `minWidth`
4. **排版**：无嵌套 `.bubble`、`h2` 间距、`hr` 间距与 ≥ 8px 间隙
5. **真实对话 + `enhanceBubble` 真路径**：`.table-scroll`、`role/tabindex`、
   复制按钮、链接 `target/rel`、幂等 ×3、流式不挂按钮

## 门禁本身踩的四个坑（都靠反向验证抓出来）

> 沿用两条既有纪律：门禁跑完要看有没有真的打出 `结果：N passed`；
> 每条新断言都要**回退实现看它是否真的变红**。

| 坑 | 表现 | 修法 |
|---|---|---|
| `DOMParser` 把文档开头的 `<script>`/`<style>` 路由进 `<head>`，而 `sanitizeHtml` 返回 `doc.body.innerHTML` | 把 `script`/`style` 从 DROP 挪走**门禁照样全绿** | 用例前置 `<p>x</p>` 强制落进 body，断言整体输出恰好是 `<p>x</p>tail` |
| 布局断言分不清「靠 `min-width:0` 撑住」还是「靠 `overflow-wrap` 断行」 | 删掉两条规则**各自都是 93 passed 假绿** | 追加直接断言 `getComputedStyle` 的 `overflowWrap` / `minWidth` |
| `pre` 在 `overflow-x:auto` 里，右缘超出视口是**应有之义** | 误报 `✗ pre：CODE right=409` | `inScroller()` 排除横向滚动容器内部的元素 |
| 按模块作用域正则从 `ask.js` 抠函数 | `SANITIZE_DROP is not defined` | 改用 `window.__askTest` 暴露真实运行时函数（对齐 `window.I18n.__test_setLang` 先例） |
| 几何断言单用不够：按钮改回 `position:absolute` 时包装层是 `static`，绝对定位解析到别处，两矩形**恰好不相交** | 96 passed 假绿 | 同时钉死 `position !== "absolute"` 这条属性（同 `overflow-wrap` 的教训：属性判据不能被布局副作用替代） |

另外 `ASK_JS_CODE` 抽源码前**必须剥注释** —— `ask.js` 自己的说明性注释里
就写着 sanitizer 的实现细节，不剥会让源码断言永久假绿。

诊断脚本 `_diag_ask_fmt.mjs` / `_diag_ask_fmt2.mjs` / `_diag_ask_mobile.mjs` /
`_diag_ask_isolate.mjs` / `_diag_ask_pristine.mjs` / `_diag_ask_shot.mjs` /
`_diag_ask_real.mjs` 留在仓库里当复现证据（`_` 前缀 = 诊断，非门禁）。
