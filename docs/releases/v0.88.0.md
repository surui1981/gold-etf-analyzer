## 三类改动

### 1. `check_routes.py` HTTP 路由门禁（核心新增）

**`scripts/check_routes.py`**（新建，~290 行）

**为什么需要**：V0.86.1 hotfix 暴露的核心问题是——「新增静态页必须同步注册根路径
别名」。V0.87.0 已用 FastAPI TestClient 在 `tests/test_dependencies/test_main_app.py`
覆盖 11 个 alias 307 重定向，但 **TestClient 走 ASGI 内存通道**，不验证
「真实 HTTP 服务器 + curl GET → 落地页可达」——本脚本补上集成层验证。

**判定口径**：

| 端点类型 | 期望 status | 数量 |
|---|---|---|
| 页面 alias（11 个 RedirectResponse） | `307` | 11 |
| `/sw.js`（FileResponse） | `200` | 1 |
| `/docs`（test/dev 模式 Swagger UI） | `200` | 1 |
| `/static/trend.html`（StaticFiles mount 抽样） | `200` | 1 |

合计 14 端点。

**模块 API**：

```python
EXPECTED_ALIAS_PATHS = ["/", "/portfolio", "/weights", "/news", "/review",
                       "/central-bank", "/data-health", "/data-health.html",
                       "/trades", "/login", "/reset-password"]

EXPECTED_STATUS = {
    **{p: 307 for p in EXPECTED_ALIAS_PATHS},
    "/sw.js": 200,
    "/docs": 200,
    "/static/trend.html": 200,
}

def discover_routes(app) -> list[str]: ...    # 反射 app.routes
def check_routes(*, routes, fetch, base, expected) -> list[str]: ...  # 双向验证
def main(argv) -> int: ...                     # CLI 入口
```

**双向验证逻辑**：

- `routes - expected.keys`（漂移信号）：FastAPI 路由表里有但未登记 → FAIL
  （防止新增 alias 但忘记同步 EXPECTED_STATUS）
- `routes ∩ expected`：每条按期望表验证 status（核心 happy path）
- `expected - routes`（如 `/static/trend.html` mount）：按期望表独立抽样
  StaticFiles 健康度（mount 不进 routes 反射）

**三种运行模式**：

```bash
# 默认：起 in-process uvicorn → urllib GET 自测（无依赖）
python scripts/check_routes.py
# → [OK] HTTP 路由门禁通过：12 条路由全部返回期望 status

# 验证外部 server（CI 友好）
python scripts/check_routes.py --base http://127.0.0.1:8889

# 只打印发现的路由（CI dry-run）
python scripts/check_routes.py --list
```

**与 TestClient 测试的分层**：

| 层 | 文件 | 验证内容 |
|---|---|---|
| ASGI 内存 | `tests/test_dependencies/test_main_app.py::TestRootAliases` | alias 注册存在 + 307 重定向 |
| HTTP 集成 | `scripts/check_routes.py`（本版） | 真 HTTP GET → 期望 status |
| 静态文件 | `scripts/check_pwa_assets.py`（V0.81） | `/static/*.html` + sw.js 完整性 |

两层门禁互为冗余：TestClient 快（不启服务），HTTP gate 慢（启 uvicorn ~1s）
但捕真实网络层 bug（如 StaticFiles mount 漏配、中间件漏挂）。

**背景**：发版流程漏改 `static/sw.js` 的 `const VERSION`，仍为 `v0.86.1`，
但 `src/app/__init__.py::__version__` 已升级到 `v0.88.0`。
`tests/test_scripts_check_pwa_assets.py::test_real_repo_passes` 与
`test_real_repo_sw_version_matches_app_version` **立即捕获**漂移（CI 友好）。

**修复**：把 `static/sw.js:16` 的 `const VERSION` 从 `"v0.86.1"` 改成 `"v0.88.0"`。
没有功能变更，纯字符串同步；唯一行为变化是浏览器 SW 缓存名从
`gold-shell-v0.86.1` → `gold-shell-v0.88.0`，触发已安装 PWA 用户的缓存重建。

**复盘**：
- V0.88.0 文档（`src/app/__init__.py` 头部注释）已明确列出 4 处版本号同步点
  （①__version__ ②pyproject.toml ③uv.lock ④static/sw.js），但发版时漏了 ④
- `test_real_repo_passes` 这类「门禁测试」的设计价值在此兑现——它们拦截
  流程型 bug，**不依赖人脑记 4 处同步**

  必须纳入发版 checklist 的最后一步（git hook 或 CI gate 都可）

## 教训

1. **集成层门禁 vs 单元层断言互为冗余**：V0.86.1 hotfix 在 TestClient 层
   没问题，但真实 `curl` 会 404——因为中间件顺序错了。TestClient 不走网络，
   不验证中间件；HTTP gate 走真实网络，能捕此类 bug。两层都不可少。
2. **常量同步必须用测试断言**：EXPECTED_STATUS（脚本）与 ROOT_ALIASES
   （测试）任何一处漏更新都会让 V0.85 漏注册 /data-health 类回归漏检。
   `TestExpectedStatusConsistency` 把这种漂移固化为失败用例。
3. **双向验证（routes ∩ expected + routes - expected + expected - routes）
   比单向验证（仅 routes ⊆ expected）更稳**：单向漏掉「新增 alias 但未登记」
   漂移信号；双向同时捕「FastAPI 反射 ≠ 期望表」与「期望表 ≠ FastAPI 反射」
   两个方向。
4. **覆盖率基线必须每次发版前重跑**：V0.87.0 误以为「87% 是终态」，本版
   重新识别三个低洼（grams 56% / import_central_bank 22% / admin 47%），
   集中火力到 100%/98%/90%。增量覆盖率比绝对数字更能反映代码健康度。
