## 〇 一页结论

**症状**：V0.120.0 的两个资金流用例在 **2026-10-31（周六）** 跑就失败，而远程 CI 在
10-29 是 **success** —— 同一份代码、同一个测试，只因为时钟前进了两天。
**根因**：用例把「今天是 2026-10-28」只写进**注释**，实际日期由
`week_end_days(trading_days)` 内部的 `date.today()` 决定 ⇒ 时钟走到周六后
「本周（10-26~11-01）已过完」成立，观测锚点从 **10-23 跳到 10-30**，断言全线失配。
**修法**：把「今天」做成**可注入参数**（生产路径全部不传 ⇒ `None` → 系统日期，
行为与修复前逐字相同），用例显式传固定日期。

**改动面**：`src/app/services/money_flow.py`（3 个私有采集方法加可选参数）+
`tests/test_services/test_money_flow_service.py`（1 个常量 + 6 处传参）。
**零 schema、零接口、零配置、零前端改动。**

## 一、问题

### 现象

```
FAILED tests/test_services/test_money_flow_service.py::test_黄金ETF_窗口末日锚在周末日而不是最新交易日
FAILED tests/test_services/test_money_flow_service.py::test_黄金ETF_周末日份额未发布时自动往前回退
E   AssertionError: assert datetime.date(2026, 10, 30) == datetime.date(2026, 10, 16)
```

失败断言里 `obs_date` 是 **10-30**（周五），而用例期望 **10-16 / 10-23**。
数据构造本身没问题：交易日硬编码到 `2026-10-30`，被"未发布"的份额日是 `10-23`。

### 为什么 10-29 是绿的、10-31 就红

`week_end_days()` 的语义是「每个**已过完的周**的最后一个交易日」，而「已过完」的判据是
**某周的周五是否严格早于今天**（周五当天不算 —— 盘中收盘价未定）。于是：

| 传 `today` | 末周末日 | 用例期望 | 结果 |
|---|---|---|---|
| 2026-10-28（周三） | 2026-10-23 | 10-23 | ✅ 绿 |
| 2026-10-29（周四） | 2026-10-23 | 10-23 | ✅ 绿（CI 跑在这一天） |
| 2026-10-30（周五） | 2026-10-23 | 10-23 | ✅ 绿（周五「当天）不算已过完 |
| **2026-10-31（周六）** | **2026-10-30** | 10-23 | ❌ **红** |

⚠ 一旦过周六，**永久红**（数据最大只到 10-30，锚点最多推进到 10-30，再也不会回到 10-23）。

⚠ 并且这不是孤例：同文件还有两条**月频**用例（`test_融资余额_只取已过完的月份` /
`test_美元流动性_观测日锚在月末而不是最新周`）用 2026-10 的当月数据构造，
它们靠「当月还没过完」才成立 ⇒ **11-01 起同样变红**。

### 关键点：这不是"测试写错日期"那么简单

用例的注释写得完全正确（「「今天」是 2026-10-28（周三）」），问题在于
**这句话没有变成代码** —— 它只是注释。而 `_collect_etf()` 调用
`week_end_days(trading_days)` 时**没有把 today 透传下去**，
所以测试根本没有办法表达「现在假装是 10-28」。

对照证据：**同一仓库的回填路径早就是这么做的** ——
`src/app/services/money_flow_backfill.py:162` 调用
`week_end_days(trading_days, today=end)`，把回填终点显式传进去。
只有**实时采集**这条路径漏了透传，而测试恰好只测实时采集。

## 二、修法

### 生产代码：三个私有采集方法接受可选 today

```python
# src/app/services/money_flow.py
async def _collect_etf(self, today: date | None = None) -> dict[str, FlowReading]:
    ...
    # ⚠️ today 必须透传（不传 ⇒ week_end_days 自己取系统日期 ⇒ 测试随时钟漂移）
    week_ends = week_end_days(trading_days, today=today)

async def _collect_us_liquidity(self, today: date | None = None) -> dict[str, FlowReading]:
    rows = await fetch_us_net_liquidity_monthly(today=today)   # 该函数本就支持 today

async def _collect_cn_margin(self, today: date | None = None) -> dict[str, FlowReading]:
    # 丢掉**还没过完**的当月（其「月末值」其实是月内至今值）
    today = today or date.today()
```

**生产行为不变的最强证据**：`_collect()` 里的 `asyncio.gather` 调用这三个方法时
**全部不传参数** ⇒ `today = None` ⇒ `week_end_days(..., today=None)` 内部回落
`date.today()`，与修复前**逐字相同**。改动只是多了一个「测试可用、生产不用」的入口。

### 测试：一个常量 + 六处传参

```python
# ⚠️ 必须**显式固定**，不要让它随系统时钟漂移
FIXED_TODAY = date(2026, 10, 28)
```

覆盖范围：`_collect_cn_margin` ×2、`_collect_etf` ×2、`_collect_us_liquidity` ×2。
其中 4 处是**当下就红或即将红**的用例，2 处是同一节里同源但尚未引爆的。

### 为什么给 `_collect_us_liquidity` 也加参数

它的月频锚点来自 `fetch_us_net_liquidity_monthly()`，后者的 `month_end_days(..., today=...)`
默认同样取系统日期。**同一个缺陷模式**，一并堵掉，避免下个月再来一轮。
