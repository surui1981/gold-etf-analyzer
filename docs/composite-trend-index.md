# 综合趋势评估指数 · 计算方式与主要参考

> **目标读者**：想弄清「首页那个 0-100 的分到底怎么算出来的」的人（用户 / 接手维护的人） ｜ **状态**：活跃 ｜ **最近更新**：2026-11-08

---

## 〇、一句话 + 当前线上值

**综合趋势评估指数** = 把「技术面 / 宏观参考 / 消息面 / 资金流面」四个 0-100 分，
按各自权重加权合成的一个 0-100 分 —— 分数越高越偏多，越低越偏空。

> 2026-11-08 实测（`/api/v1/market/gold/trend?target=ny&days=60`）：
> **32.7 / 100，等级【下降】**
> = 技术面 16.8 × 38% + 宏观参考 45.7 × 38% + 资金流面 37.7 × 23%
> （**消息面当天未打分 → 整面剔除**，剩余三面权重重新归一化）

⚠️ 这 32.7 换任何一个标的都不一样 —— 见 §5.4「两个 target 是两个指数」。

## 一、总公式

代码位置：[src/app/services/trend.py](../src/app/services/trend.py) 第 **603–616** 行

```
四面打分            faces = [(tech, 25%), (macro, 35%), (news, 25%), (flow, 15%)]
剔除不可用的面      valid = [f for f in faces if f.score is not None and f.weight > 0]
归一化              combined = Σ(score_i × weight_i) / Σ(weight_i)
```

- **四面齐全时** `Σweight = 1.0` ⇒ 等价于普通加权平均。
- **任一面不可用时**（如消息面当天未打分）⇒ 该面**整面剔除**，
  剩余面的权重按 `Σ剩余权重` **重新归一化**（25/35/15 → 33.3/46.7/20）。

> ⚠ **「不可用」不是「中性 50」。** 50 分是一个**判断**（多空平衡），
> 而「数据不足」本质是**置信度**问题。混用会让「没数据」看起来像「有结论」。
> 这条纪律贯穿全链（V0.78.0 起），是本指数最重要的设计前提。

## 二、四个面

### 2.1 技术面（默认权重 25%）

代码：[src/app/services/trend.py](../src/app/services/trend.py) 第 **822–1065** 行

从 K 线序列算出 **5 个维度**，每个映射为 0-100 分，再合成技术面指数。

#### 5 个维度的打分公式

| 维度 | 公式 | 标定 | 最少 K 线 |
|---|---|---|---|
| **结构** | 均线排列分 × 0.6 + MA20 斜率分 × 0.4 | 排列：MA5>MA20>MA40 → 100，反之 → 0，交叉 → 50；斜率：`50 + MA20近5日斜率% × 100` | **40** |
| **动量** | `clamp(50 + 近20日涨幅% × 8)` | +5% → 90，-5% → 10 | **21** |
| **支撑** | `mean(clamp(50 + MA20乖离% × 20), clamp(50 + MA40乖离% × 15))` | ±2.5% 达上下限 | **20** |
| **动能** | `clamp(50 + (RSI(14) − 50) × 1.5)` | RSI 70 → 80，30 → 20 | **15** |
| **回撤** | `clamp(100 − 距区间高点回撤% × 10)` | 回撤 0% → 100，10% → 0 | **10** |

`clamp(x) = max(0, min(100, x))`。

> ⚠ **K 线不够 ⇒ 该维度 `score = None`，不参与合成**（页面上显示「—」）。
> 门槛由每个公式**自身的输入需求**决定（如 RSI(14) 需要 period+1 个收盘价）。
> 5 个维度**全部**不足 ⇒ 技术面整体 `None` ⇒ 整面从综合指数里剔除。

#### 组内平均（默认）vs 单维度加权

默认走 **组内平均**（V0.79.0 Step F）—— 先在组内取算术平均，再按**组权重**加权：

| 组 | 成员 | 组权重（默认） |
|---|---|---|
| 趋势组 | 结构 + 动量 | **0.50** |
| 超买组 | 动能 + 支撑 | **0.30** |
| 风险组 | 回撤 | **0.20** |

- 为什么要分组：5 个维度里「结构/动量」都围绕均线与价格动量、「动能/支撑」都衡量超买超卖，
  高度相关；组内平均能降低这种相关性带来的重复计权。
- **整组缺失** ⇒ 该组权重按比例分给剩余组（不引入 50 兜底）。
- 切到「单维度加权（历史）」模式则用 `TREND_WEIGHTS`：结构 0.30 / 动量 0.20 / 支撑 0.20 / 动能 0.15 / 回撤 0.15。

> 📌 组权重与四面的权重都**可以在应用内改**（`static/weights.html`），改完立即生效。
> 详见 §7。

> ⚠ **切到周 K / 月 K 时技术面被旁路**：5 个维度的标定是按日 K 的 ±5% 量级设计的，
> 聚合到周/月后量纲不匹配 ⇒ 技术面按**中性 50** 计入，并在摘要里显式说明
> 「技术面 5 维度对 W/M K 不适用，已按中性 50 计入，非『数据不足』」。
> 这是**说明过的 50**，不是沉默的 50。

### 2.2 宏观参考面（默认权重 35%）

代码：[src/app/services/macro.py](../src/app/services/macro.py)

**11 个因子**，每个映射为「黄金友好度」0-100 分，加权合成。

映射公式（正负相关通用）：

```
score = clamp((value − worst) / (best − worst) × 100, 0, 100)
```

- `best` = 最利好黄金的一端，`worst` = 最利空的一端。
- 负相关因子（美元、利率、实际利率）：`best` 是**低位**（如美元 best=94、worst=107）。
- 正相关因子（VIX、央行购金、政府债务）：`best` 是**高位**。

| 因子 | 权重 | 符号 | best（最利多） | worst（最利空） | 数据源 | 节奏 |
|---|---|---|---|---|---|---|
| `dxy` 美元指数 | 13% | − | 94.0 | 107.0 | Yahoo `DX-Y.NYB` | 日 |
| `us2y` 美债 2Y | 5% | − | 3.0 | 5.0 | 美联储 H.15 | 日 |
| `us10y` 美债 10Y | 7% | − | 3.8 | 5.4 | 美联储 H.15 | 日 |
| `us30y` 美债 30Y | 5% | − | 4.3 | 5.7 | 美联储 H.15 | 日 |
| `curve_10y2y` 10Y-2Y 利差 | 9% | − | −0.5 | 1.5 | **派生**（10Y − 2Y） | 日 |
| `real10y` 10Y 实际利率 | 18% | − | 0.8 | 3.2 | FRED `DFII10` | 日 |
| `vix` VIX | 9% | + | 30.0 | 13.0 | FRED `VIXCLS` | 日 |
| `cb_gold` 央行购金 | 22% | + | 1200 | 500 | 世界黄金协会 GDT（滚动 12 月） | **季** |
| `us_gov_debt` 美国政府债务/GDP | 5% | + | 140 | 60 | FRED `GFDEGDQ188S` | **季** |
| `cn_gov_debt` 中国政府债务/GDP | 4% | + | 95 | 40 | FRED `GGGDTACNA188N` | **年** |
| `eu_gov_debt` 欧洲政府债务/GDP | 3% | + | 95 | 60 | Eurostat `GOV_10Q_GGDEBT` | **季** |

分组看：美元 13% / 名义利率 17% / 曲线形态 9% / 实际利率 18% / 风险偏好 9% / 结构性需求 22% / 政府债务 12%。

#### 滚动分位（动态阈值）

上表的 `best`/`worst` 是**静态带**；但 7 个日频因子会用**近 252 个交易日的 P90/P10 分位**
动态替换（`macro_thresholds.py`）—— 也就是「这个值相对自己最近一年处在什么位置」。

- **不参与滚动分位的 4 个低频因子**：`cb_gold` + 3 个政府债务因子。
  理由：季度/年度值在日频表里重复几十次 ⇒ P10 == P90 ⇒ 阈值退化。
- API 会返回 `macro_dynamic`（是否全部动态）与 `dynamic_factors`（实际用了滚动的因子清单），
  前端显示「N/M 个因子使用滚动分位」。

#### 降级链

```
用户手动覆盖 > 自动数据源 > 上次成功落库的真实读数 > 静态参考值（STATIC_REF）
```

⚠ **静态兜底值不是市场读数** —— `is_persistable_source` 会把它们挡在 `daily_macro_factors`
历史表之外，否则一次上游故障就能把假常量写进滚动分位窗口，把阈值彻底带偏。

### 2.3 消息面（默认权重 25%）

代码：[src/app/services/news.py](../src/app/services/news.py)

**这是全系统唯一一个「人工打分」的面**：客户每天对主流财经网站的投行黄金展望评分。

- 每天 **3 次打分机会**（slot 1/2/3），**越晚权重越高**（1 : 2 : 3）：
  ```
  effective = Σ(权重_i × 分数_i) / Σ(权重_i)
  ```
- 仅第 1 次打分时为该次分值；第 2 次起按 1:2 / 1:2:3 归一加权。
- 打分记录落在 `news_scores` 表，可按日期补录（标记为补录，复盘统计默认排除）。
- **当天没打分 ⇒ `score = None`** ⇒ 整面从综合指数剔除，并在摘要里写明「消息面未打分，综合指数待定」。

### 2.4 资金流面（默认权重 15%）

代码：[src/app/services/money_flow.py](../src/app/services/money_flow.py)

V0.120.0 新增的第 4 个面，回答「**钱往哪儿流**」。

> 设计边界：**只收流量 / 数量类读数，不收价格类读数**（不收 SHIBOR、不收汇率、不收利率、不收金价本身）。
> 价格与存量口径归宏观面 —— 否则同一条逻辑会被计两遍。

| 因子 | 节奏 | 权重 | 符号 | 源 |
|---|---|---|---|---|
| `cot_gold_net` 黄金投机净多占 OI | 周 | 18% | − | CFTC 分类持仓 |
| `cot_gold_flow` 4 周净多变化 | 周 | 14% | + | 同上 |
| `gold_etf_flow` 上交所 ETF 4 周净申赎 | 周 | 22% | + | 上交所官方份额 |
| `us_liq_net` 美元净流动性 4 周变化 | 月 | 14% | + | FRED |
| `cn_margin_flow` 沪深融资余额月环比 | 月 | 16% | − | 交易所 |
| `cn_money_gap` M1−M2 剪刀差 | 月 | 16% | − | 央行 |

符号口径分三类，别混：

- **`+`（流入口径）**：值越高越利多黄金 —— 钱**流进**黄金 / 钱**变多**。
- **`−`（机会成本口径）**：融资余额下降 = 股市杠杆钱撤出 = 黄金机会成本下降 = 利多黄金；
  剪刀差走阔 = 钱淤积存款 = 抗通胀资产需求上升 = 利多黄金。
- **`−`（拥挤度口径）**：`cot_gold_net` = 投机盘净多占持仓比 ——
  **值越高 = 越拥挤 = 越利空黄金**。这不是「钱在流进」，是「钱已经挤在里面了」。

> **`cot_gold_net` 自 V0.122.0 起从 `+` 改为 `−`**（以 **COMEX/GLD 美元金价**为核心标的实测）。
> 实测：净多占 OI 的**年内五分位**，Q1（最不拥挤）前瞻 60 个交易日 **+6.45%**、
> Q5（最拥挤）**+0.62%** ⇒ 方向反了，差 **5.84pp**。三个子区间
> （2015-18 / 2019-22 / 2023-26）**全部同向**（+10.46 / +4.86 / +1.75pp），
> 518880 人民币金价同口径同结论（全样本 +3.73pp）。
> ⚠ **但效果在衰减**：2023-26 段相关已接近 0，且 518880 在该段**反向**（−2.08pp）
> ⇒ 拥挤度口径**近期偏弱**，这是事实，不要当成稳定信号用。
> 完整测量方法（含**为什么不能用「直接相关」下结论**）见
> [`src/app/services/money_flow.py`](../src/app/services/money_flow.py) 的模块文档
> 「拥挤度口径的实测依据」；证据可用 `python scripts/verify_cot_sign.py` 复算。

#### ⚠ 资金流面 composite 的定位（V0.123.0 复算后订正）

**资金流面 composite 是「当下资金状态」的读数，不是前瞻指标。**

V0.122.0 曾据「改号后 composite 前瞻主导」推出资金流面有前瞻力 ——
该推论在 **V0.123.0 用生产真实打分口径复算后不成立**（口径与数据两处都变了：
当时用的是 z 分数而非 0~100 打分，且 `gold_etf_flow`（权重 22%，最大）
依赖的上交所份额序列当时是坏的）。复算结果（h=60，非重叠 + 年内去均值 +
控制当期金价水平）：

| 变体 | 标的 | 前瞻偏相关 | 回看偏相关 | 比值 | 判定 |
|---|---|---|---|---|---|
| 现状（cot=负） | GLD | +0.1165 (p=0.432) | +0.0910 (p=0.541) | 1.28 | ❌ 功效不足（\|pc_fwd\| < 0.15） |
| 翻 cot（=正） | GLD | +0.1049 (p=0.480) | +0.2669 (p=0.066) | 0.39 | ❌ 三问全不过 |
| 现状 | 518880 | −0.1862 (p=0.217) | +0.1519 (p=0.315) | 1.23 | ❌ 比值不过 |
| 翻 cot | 518880 | +0.0068 (p=0.964) | +0.3141 (p=0.033) | 0.02 | ❌ 三问全不过 |

⇒ **两种符号 × 两个标的，三问（功效 / 比值 > 1.3 / 三段同向）全不过**。
⇒ 读法上要改口：**资金流面适合回答「现在资金站在哪一边」，不适合回答「接下来会怎样」**。

> ⚠ 这**不动摇** `cot_gold_net` 的符号修复 —— 符号的依据是**单因子**证据（+5.84pp，三段同向），
> 该证据 V0.123.0 **逐位复现**。
> 完整证据见 [M8 里程碑文档](releases/milestones/m8-flow-face-evidence-v0.123.md)，
> 复算入口 `python scripts/verify_flow_face.py`。

这些因子的 `best`/`worst` 带不是拍脑袋定的，是**实测历史分位**
（`scripts/calibrate_money_flow_bands.py`，8 年 / 13 年 / 5 年窗口，见源码注释）。

## 三、分数 → 等级 / 方向

代码：[src/app/schemas/thresholds.py](../src/app/schemas/thresholds.py)

**综合指数等级**（`LevelThreshold`，含端点）：

| 分数 | 等级 | 方向色 |
|---|---|---|
| ≥ 75 | 强势上升 | 红（看多） |
| ≥ 55 | 上升 | 红（看多） |
| ≥ 45 | 震荡整理 | 灰（中性） |
| ≥ 25 | 下降 | 绿（看空） |
| < 25 | 弱势下降 | 绿（看空） |

**方向判定**（`DirectionThreshold`，与上面**不是同一套**，注意差别）：

| 用途 | 阈值 | 语义 |
|---|---|---|
| 单维度着色、技术/宏观方向 | ≥60 看多 / ≤40 看空 | 含端点 |
| 消息面方向、共振信号 | >55 看多 / <45 看空 | **严格不等号** |

> 这不是冲突：`UP`（综合指数**等级**）与 `BULLISH`（单次打分**方向**）口径不同。

### 抓取与重算节奏

- **缓存**：K 线与技术面结果按 `(target, interval, 日期, days)` 缓存，跨日自动失效
  （`days` 在缓存 key 里 —— 不同窗口的结果不可互相命中，V0.121.1 起）。
- **主动失效**：任何会改变综合指数成分的写入（消息面打分、宏观因子手动覆盖、改权重）
  都会调用 `invalidate_cached_results()`，下次请求全量重算。
- **调度**：`scheduler.py` 在北京时间 **07:00** 自动预生成（首屏直接命中缓存）。
- **宏观面另有 10 分钟 TTL 缓存**，避免上游接口挂起拖垮接口。

## 五、口径纪律（读这个指数前必须知道的 7 条）

### 5.1 缺数据 ⇒ 剔除，不兜底 50

维度、因子、面三层都是这个原则：

- 技术面 5 维度数据不足 ⇒ 该维度 `None`，不参与合成；
- 5 个维度全不足 ⇒ 技术面整体 `None`，整面剔除；
- 消息面未打分 ⇒ 整面剔除；
- 宏观因子缺读数 ⇒ 该因子剔除，剩余因子按剩余权重归一化；
- 共振信号的有效维度 < 2 ⇒ 构不成「共振」，返回中性，并披露 `missing_dimensions`。

### 5.2 剔面之后权重会重新归一化

消息面未打分时，技术面 25% → **38.5%**、宏观 35% → **38.5%**、资金流 15% → **23.1%**。
所以「同一个市场状态，不同的日子分数会不一样」—— 不一定因为市场变了，
也可能是因为**参与的面变了**。摘要里会写明。

### 5.3 `face_weights` vs `face_weights_nominal`

| 字段 | 含义 | 用途 |
|---|---|---|
| `face_weights` | **实际生效**权重（已剔除 + 已归一化） | 公式、分数条 |
| `face_weights_nominal` | **配置原值**（剔除前） | 标注「消息面原本占 35%，现被剔除」 |

### 5.4 两个 target 是两个指数

| target | 标的 | 用在哪 |
|---|---|---|
| `ny` | 纽约金 COMEX GC | **首页结论块**、趋势页「实时评估摘要」 |
| `etf` | 上交所黄金 ETF 518880 | 趋势页 synthesis-card |

技术面不同（K 线序列不同）⇒ **分数会差几分**。两处数字不打架，因为口径不同。

### 5.5 静态兜底值不是市场读数

宏观与资金流的每个因子都有静态兜底常量。**兜底值会被标成 `static` tier**，
前端挂降级 chip；且**不写入历史表**（`is_persistable_source`）——
否则一次上游故障会把假常量写进滚动分位窗口。

### 5.6 央行购金：合计行与各国行不可相加

世界黄金协会的数据有两套口径：

- **全球合计行**（`WGC_AGGR`）：WGC 估算，**含未披露国**；
- **各国明细行**：仅已上报国。

⇒ 两者**相加 = 重复计数**。V0.121.4 之前旧口径报出 2026Q2 = **336.7 吨**
（= 合计 288.9 + 各国 47.8），真值是 **288.9 吨**。
现在有合计行就只取合计行。详见 [央行购金页](../static/central_bank.html) 与
`src/app/repositories/central_bank_data.py`。

### 5.7 `index.score` 可能是 `null`

全部数据都不可用时综合指数是 `null` ⇒ 页面显示 **「—」**，
**绝不显示 50**（V0.78.0 教训）。

## 六、下游：这个指数被谁消费

| 消费方 | 怎么用 | 代码 |
|---|---|---|
| **决策引擎** | 指数 → 行动档位 + 建议仓位 | `services/decision.py` |
| **共振信号** | 只取 `components` 里的**技术/宏观/消息**三维（**不含资金流**）判定强/弱/背离 | `services/resonance.py` |
| **首页结论块** | 大数字 + 等级徽章 + 加权公式 + 四面分数条 + 因子明细 | `static/home.js` |
| **趋势页** | 实时评估摘要 + synthesis-card | `static/trend.html` |

### 决策矩阵（指数 → 仓位）

| 指数 | 建议仓位 |
|---|---|
| ≥ 75 | 80%（重仓） |
| ≥ 55 | 60%（中高） |
| ≥ 45 | 40%（中性） |
| ≥ 25 | 20%（轻仓） |
| < 25 | 10%（观望空仓） |

行动档位另有一套阈值（`DecisionThreshold`：75 / 65 / 55 / 50 / 40），
且会与**持仓盈亏**联合判定（趋势强 + 有浮盈 ⇒ 加仓；趋势弱 + 浮亏 ⇒ 减仓）。

### 前端为什么要自己重算公式

`index.summary` 是**服务端直出中文串** ⇒ 三语页面下会露馅。
所以前端按 `components` + `face_weights` **重算公式**（三语可用），
服务端那份 summary 只当后端日志/降级兜底。

> ⚠ 另一个坑：`index.composed_by` **恒为 `"weighted"`**（后端构造时漏传），
> 真实值在**顶层** `tech_composed_by`。

## 七、怎么调参数

| 想改什么 | 在哪改 | 生效方式 |
|---|---|---|
| 四面权重（技术/宏观/消息/资金流） | 应用内 `static/weights.html` → `/api/v1/settings/weights` | 立即生效（写 `app_settings` 表 + 失效缓存） |
| 技术面 3 组权重（趋势/超买/风险） | 同上 | 立即生效（V0.121.2 起真正生效，此前是装饰性参数） |
| 技术面 5 维度权重 | 同上 | **仅在「单维度加权（历史）」模式下生效**；组内平均模式下 5 个滑块是**置灰**的 |
| 宏观 11 因子权重 | 同上 | 立即生效 |
| 资金流 6 因子权重 | 同上 | 立即生效 |
| 宏观因子**读数**手动覆盖 | 应用内 `/settings` → `/api/v1/settings/macro-overrides` | 立即生效（`as_of` 必填） |
| 阈值（75/55/45/25 等） | 代码常量 `src/app/schemas/thresholds.py` | 改代码 |

> ⚠ 改阈值前请按 [parameter-evaluation.md](parameter-evaluation.md) §6.2 的三维交叉验证方法
> （Sharpe + 最大回撤 + 命中率/校准）评估新值的实际效果。

## 八、完整算例（2026-11-08，`target=ny`，60 日）

```
① 技术面（组内平均）
   趋势组  结构 0.0（空头排列，MA20 近 5 日下行 0.88%）
             动量 23.4（近 20 日 −3.33%）
             组内均值 = (0.0 + 23.4) / 2 = 11.7      × 组权重 50%
   超买组  支撑 32.4（MA20 乖离 −0.07%、MA40 乖离 −2.26%）
             动能 40.8（RSI(14) = 43.9）
             组内均值 = (32.4 + 40.8) / 2 = 36.6      × 组权重 30%
   风险组  回撤 0.0（距区间高点回撤 14.20%）
             组内均值 = 0.0                            × 组权重 20%
   技术面 = 11.7×0.5 + 36.6×0.3 + 0.0×0.2 = 16.8

② 宏观参考面（11 因子加权）
   dxy 0.0×13% + us2y 30.9×5% + us10y 35.4×7% + us30y 35.5×5%
   + curve_10y2y 68.2×9% + real10y 18.8×18% + vix 100.0×9%
   + cb_gold 55.0×22% + us_gov_debt 76.5×5% + cn_gov_debt 87.9×4%
   + eu_gov_debt 65.4×3%
   = 45.7   （7 个日频因子当时用的是 252 日滚动分位）

③ 消息面 = None（当天未打分）⇒ 整面剔除

④ 资金流面（6 因子加权）
   cot_gold_net 22.9×18% + cot_gold_flow 48.2×14% + gold_etf_flow 7.0×22%
   + us_liq_net 53.3×14% + cn_margin_flow 100.0×16% + cn_money_gap 11.1×16%
   = 37.7

⑤ 归一化合成（剩余三面权重 25% / 25% / 15% → 38.46% / 38.46% / 23.08%）
   = 16.8×38.46% + 45.7×38.46% + 37.7×23.08%
   = 6.46 + 17.58 + 8.70
   = 32.7 / 100   → 等级【下降】（25 ≤ 32.7 < 45）
```

> ⚠ 上表的因子分值按 API **显示的 1 位小数**列出，逐项手加可能与 API 差末位
> （服务端用未舍入的中间值求和再 round）⇒ **以 API 为准**。
> 这也正是 §9 里那些代码位置值得先看一眼的原因。
