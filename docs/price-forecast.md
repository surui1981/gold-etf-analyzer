# 金价区间预测（未来 20 个交易日）· 口径与校准

> **版本：V0.127.1**（口径订正 hotfix，2026-11-12）｜ **标的：COMEX 纽约金（`target=ny`）** ｜ **首次落地：2026-11-12**
>
> 这份文档是**口径真源**：页面上每一个数、图上每一条线，都能在本文找到它的出处与算法。
> 文档里的数**全部是实测值**（不是估计），核验方式见文末「怎么自己复核」。

---

## 一句话

**这个功能不预测金价涨跌，只量化「未来 20 个交易日大致在什么区间」。**

- 区间**中心**恒等于**最新收盘价**，**不做任何方向偏移**（`drift_mode = "none"`）；
- 区间**宽度**由滚动日波动率（EWMA）给出，**形状**由历史类比日的实测分位路径给出；
- 区间**有多大概率罩住真实价格**，用 walk-forward **实测**出来并**写在页面上**（不是名义值）。

---

## 一、三个组件的权威来源

| 组件 | 用什么 | 为什么是它 |
|---|---|---|
| **中心** | 最新收盘价（**无漂移**） | 用户拍板；且方向倾斜当前**不可测**（见 §六） |
| **宽度** | 日对数收益的 **EWMA**（λ=0.94）× 正态分位 | 实测**跨窗口稳定**（训练段 76.8% vs 样本外 79.2%，差 2.4 个百分点） |
| **形状** | 历史类比日的**实测分位路径**（k=20 归一为 1.0） | 实测**短端比正态锥胖 1.32–1.43 倍**（k=1–5 产物实测）；⚠ **跨窗口并非同向**（训练段 ≈1.0）—— 它只作**相对宽度的微调**，不决定宽度 |

### ⚠ 为什么「宽度」不用类比法（实测对照，2588 行真实日线）

在真实 GC 日线（2016-11-14 → 2026-11-11）上做 walk-forward 检验：
算基准日 D 的带子时**只用 ≤ D 的数据**，再看 D+20 的实际收盘是否落在带内。

| 方法 | 名义覆盖 | 训练段实测 | **样本外实测** | 结论 |
|---|---|---|---|---|
| 类比带 P10–P90（未校准） | 80% | 75.0% | **45.8%** | ❌ 严重偏窄 |
| 类比带 P7–P93（在训练段校准到 78.5%） | 86% | 78.5% | **55.4%** | ❌ **校准不泛化**（regime 切换） |
| 类比带 P2–P98 | 96% | 92.0% | 78.1% | ⚠ 事后看才有这个答案 |
| **EWMA 对数正态 P10–P90** | 80% | 76.7% | **77.9%** | ✅ **跨窗口几乎不变** |
| 固定 ±8%（对照） | — | — | 77.4% | ⚠ 不随波动率自适应 |

> ⚠ 上表是**设计阶段**（2026-11-11 早于最终产物）的对照数字；
> **线上产物**（`src/app/assets/forecast/calibration.json`，生成于 2026-11-11T21:16:50Z）
> 的**权威实测值**是 80% 档：训练段 **76.8%** / 样本外 **79.2%** / 近段 **77.5%**（见 §四）。
> 两个数略有出入是因为最终产物用**更新到当日的全量数据**重算了一遍。

**为什么类比宽度会失效**：类比样本自身的分位数是**条件于「波动率相近」**的；
这个子样本的尾部比整体分布薄 ⇒ 它的 P10/P90 系统性低估尾部概率。

**为什么 EWMA 宽度可靠**：它只用**滚动**的日波动率，regime 变了它自己就跟着变。

## 二、口径定义（逐条）

| 项 | 定义 |
|---|---|
| **基准日 D** | `gold_price_daily` 里 `target='ny'` 的**最新一行**（已收盘的交易日） |
| **期限** | **20 个交易日**，按**行序**计（与 `review.py` / `scoring_wide.py` 的既有口径一致，**不用日历日**） |
| **未来交易日** | 由基准日按**周一至周五**外推（**不含美股假日修正**，与仓库既有 `market_clock` 口径一致） |
| **σ** | 日对数收益的 EWMA（λ=0.94），**只用 ≤ D 的数据** |
| **带** | `lower_k = P_D · exp(−z·σ·√H·shape_k)`，`upper_k = P_D · exp(+z·σ·√H·shape_k)`，k=1..20，H=20 |
| **z** | 覆盖率档决定：50% → 0.6745 ／ 80% → 1.2816 ／ 90% → 1.6449 ／ 98% → 2.3263 |
| **shape_k** | 类比形状曲线（k=20 归一为 1.0；产物缺失时退回 √k 锥） |
| **中心线** | `P_D`（**水平线**，无方向偏移） |

### 无前视（这是整个功能的地基）

算基准日 D 的带子时：

- EWMA 的收益序列**只含 ≤ D 的收益**；
- 参与类比匹配的日 `s` 必须满足 **`s + 20 ≤ D`**（否则用到了 D 之后的路径）。

两条都有单测钉死（`tests/test_services/test_price_forecast.py`），
且做过**反向验证**：去掉约束 ⇒ 门禁变红。

## 四、形状：类比形状 vs 对数正态 √k 锥

产物：`src/app/assets/forecast/shape.json`（入库）

| k（交易日） | 1 | 2 | 3 | 4 | 5 | 10 | 15 | 20 |
|---|---|---|---|---|---|---|---|---|
| **类比形状（实测）** | 0.3191 | 0.4378 | 0.5241 | 0.6158 | 0.6578 | 0.7664 | 0.9006 | 1.0000 |
| 对数正态 √k 锥 | 0.2236 | 0.3162 | 0.3873 | 0.4472 | 0.5000 | 0.7071 | 0.8660 | 1.0000 |
| **类比 ÷ 锥** | **1.4269** | 1.3844 | 1.3533 | 1.3770 | 1.3157 | 1.0839 | 1.0399 | 1.0000 |

⇒ **短期（1–5 交易日）金价实际比正态锥更「胖」约 1.32–1.43 倍**，到 10–20 日收敛。

**跨窗口稳定性**（同一算法在另两个窗口上的结果，`shape_stability` 字段）：

| 窗口 | 样本 | k=1 | k=2 | k=3 | k=4 | k=5 |
|---|---|---|---|---|---|---|
| 产物主窗口（277 段） | 277 | 1.43 | 1.38 | 1.35 | 1.38 | 1.32 |
| 近 600 段 | 577 | 1.27 | 1.21 | 1.20 | — | — |
| **训练段（1992 天）** | 1992 | **0.99** | **0.99** | **1.02** | — | — |

⚠ **「跨窗口同向」是假的** —— 训练段里短端**几乎等于正态锥**（0.99–1.02）
⇒ 「短期更胖」是**近年行情的现象**，不是恒定结构。
但**这不影响宽度与覆盖率结论**：形状在 k=20 归一为 1.0，
所以 §三 的实测覆盖率（宽度口径）**不依赖形状**；形状只作为**相对宽度的微调**（最多少 1.4 倍）。

> ⚠ **页面上那个倍数是现算的**（V0.127.1）：`price-forecast.js::shortEndRatioRange()`
> 从校准产物返回的 `shape` / `cone` 两个数组现算 k=1..5 的比值区间
> ⇒ 产物将来重算，页面跟着变，不会再出现「文案写死 ⇒ 与产物对不上」。

> ⚠ **形状产物缺失时**：页面只画 √k 锥并**明示「形状产物缺失」**，
> **绝不拿锥冒充类比形状**（那是把「没有证据」说成「有证据」）。
>
> ⚠ **形状是按标的校准的**：当前产物只覆盖 `ny`。
> `load_shape(horizon, target=...)` 会在标的不符时**退回 √k 锥**——
> 拿 ny 的形状去画 etf/gram 的扇形 =「把别的标的的证据说成这个标的的证据」。

## 五、两法交叉校验

类比法与 EWMA 法的**宽度比** = 类比带半宽 ÷ EWMA 带半宽。

| 统计量 | 值 |
|---|---|
| 均值 | 0.636 |
| p05 | 0.360 |
| p50 | 0.597 |
| p95 | 1.071 |
| 样本量 | 277 |

⚠ **「差 > 40%」是常态而非异常**（比值中位数 0.597 ⇒ 类比带**系统性更窄**）。
所以运行时的判据**不是**「两法不相等」，而是「比值**落在 [p05, p95] 之外**」：

| 状态 | 处置 |
|---|---|
| `analog_unusually_wide` | 比值 > p95 ⇒ **取更宽的一条** |
| `analog_unusually_narrow` | 比值 < p05 ⇒ **仍用 EWMA（更宽）** |
| `disagree` | 两法口径不一致 ⇒ **取更宽的一条** |
| `null`（在正常区间内） | 用 EWMA 宽度，页面显示「两法宽度一致」 |

**取更宽的一条是保守侧**：宁可区间偏宽，也不要给一个偏窄的承诺。

## 六、已知失效条件（页面上也写了）

1. **regime 切换**（波动率结构突变）时，实测覆盖率会下降 ——
   纯类比带曾从训练段 78.5% 掉到样本外 **55.4%**；
   本页的**宽度不用类比法**，正是为了抗这一点。〔页面第 1 条〕
2. **未来交易日按「周一至周五」外推**，不含美股假日修正 ⇒ 预测日期可能差一天（**不影响区间数值**）。〔页面第 2 条〕
3. **历史不足或相似日不足**时**降级并明示**（`method="vol_only"` / `reason="insufficient_analogs"`），
   **不会静默换口径**。〔页面第 3 条〕
4. **形状不是恒定结构** —— 训练段窗口里短端相对正态锥约 **1.0 倍**（近 600 段才是 1.27 倍）
   ⇒ 「短期更胖」是**近期行情**的现象。它只影响扇形的中间形状，
   **不影响 T+20 的区间宽度与实测覆盖率**（形状在 k=20 归一为 1.0）。〔页面第 4 条 · V0.127.1 补〕
5. **形状产物缺失** ⇒ 退回 √k 锥并明示（页面在形状图下方直接写「形状产物缺失」，不静默换口径）。

## 七、接口

| 端点 | 说明 |
|---|---|
| `GET /api/v1/forecast/price?target=ny&horizon=20&coverage=0.8` | 区间 + 扇形路径（20 点）+ 实测覆盖率 + 交叉校验 + `drift_mode` |
| `GET /api/v1/forecast/calibration?target=ny` | 校准产物（各档实测覆盖率 + 样本量）+ **形状曲线** + √k 锥 |

- `target` 取值 `ny` / `etf` / `gram`（**V0.127.0 只交付 `ny`**，其余两个会明确降级）；
- `coverage` 只接受 `0.5 / 0.8 / 0.9 / 0.98`，**其它值 400**（不是 500，也不是悄悄换个值）；
- `horizon` 取值 5–60（**越界 422**）；
- 数据不足 ⇒ **400 + 明确文案**（前端据此显示「样本不足」，而不是画一条假带）。

**缓存**：本端点**不进 `served_cache`**（那是趋势响应的缓存）；
自己缓存 10 分钟，key = (target, horizon, coverage, 最新收盘日, 最新收盘价)
⇒ **新收盘价一进来自动重算** = 用户要的「不断修正」。

## 八、前端三处落点

| 位置 | 内容 | 文件 |
|---|---|---|
| **独立页** `/price-forecast` | 结论卡 + 覆盖率切换 + 趋势导航线（扇形图）+ 形状对照图 + 校准表 + 方法与失效条件 | `static/price-forecast.html` + `static/price-forecast.js` |
| **趋势页**摘要卡 | 一句话结论 + 迷你扇形 + 「详见」链接 | `static/trend.html`（`#pfSummaryCard`） |
| **首页磁贴** | 当前区间一句话（实测覆盖率） | `static/home.html`（`#fcTileRange`） |

三处**共用同一份逻辑**（`static/price-forecast.js`）—— 只写一份，避免各抄一遍必然腐化。

**图表纪律**：
- 扇形图用**独立 canvas**，**不碰**趋势页的 `#trendChart`（它是 category 轴，塞未来日期会改掉历史序列的 x 轴）；
- 仓库里**没有** annotation 插件 ⇒ 不用 `markArea`；
- 每个图都过 `ChartA11y.wrapChart(...)`（`role="img"` + `aria-label` + 数据表兜底）。

## 九、怎么自己复核

```bash
# 1) 线上区间（主入口 192.168.0.204:8888）
curl -s "http://192.168.0.204:8888/api/v1/forecast/price?target=ny&horizon=20&coverage=0.8"
#    ⇒ drift_mode 必须 = "none"；measured.out_of_sample 必须 ≠ measured.nominal

# 2) 校准产物（各档实测覆盖率 + 形状曲线）
curl -s "http://192.168.0.204:8888/api/v1/forecast/calibration?target=ny"

# 3) 重算并与已有产物比对（口径漂移会变红）
PYTHONPATH=src:. python scripts/calibrate_price_band.py --verify

# 4) 证据门（E1–E6 的单测）
PYTHONPATH=src:. python -m pytest tests/test_services/test_price_forecast.py \
                               tests/test_api/test_forecast_api.py -q

# 5) 浏览器门禁（视口 1352×900，禁用缓存 + 绕过 SW）
node scripts/_verify_price_forecast.mjs
```

| 项 | 值 |

| 日波动率 σ | 1.6433%（年化 **26.09%**） |
| **80% 区间** | **3632.27 – 4385.16**（−9.0% / +9.9%） |
| 50% 区间 | 3797.99 – 4193.82（−4.8% / +5.1%） |

| 历史深度 | 2588 行（2016-11-14 → 2026-11-11） |

> 用户举的「4100–4200」只有 **±1.3%** 宽 —— 那大约相当于 **13% 覆盖口径**

> **不能**默认给一个「看起来像用户例子」但实际只覆盖 13% 的窄带。
