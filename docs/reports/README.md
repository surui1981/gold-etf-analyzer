## 为什么放在子目录（而不是 `docs/` 根）—— 请勿挪动

`scripts/check_docs_claims.py` 的扫描范围是：

```python
DOC_FILES = [ROOT / "README.md", *sorted((ROOT / "docs").glob("*.md"))]
```

`pathlib.Path.glob("*.md")` 是**非递归**的 —— 只扫 `docs/` 直接子文件，不进入子目录。

这不是疏漏，而是**必要条件**：本目录的报告是**记述性文档**，
为了说明「当时误判了什么」，必须能原样写出**当时错误或已被废弃的实体名**。
实测把报告放到 `docs/` 根会让门禁**新增 8 处失败**，
全部来自 2026-09-27 那份「版本差距分析」（其中 2 个表名是**凭空捏造**的，
1 处 API 命名错误，1 处把 localStorage key 写错）：

| 被判失败的声明 | 实情 |
|---|---|
| localStorage key `pm_dash_layout` | 实际是 `pm_dashboard_layout`（写错了） |
| 表 `alert_rules` | 它是 `app_settings` 里的 JSON key，**不是表** |
| 表 `portfolios` | **凭空捏造**，代码中不存在 |
| 表 `snapshot_overrides` | **凭空捏造**，代码中不存在 |
| 页面 `central-bank.html` | 实际走 RESTful 路由 `/central-bank`，无此静态页 |
| 端点 `/api/v1/push/unsubscribe` | 不存在 |
| 端点 `/api/v1/market` | 不存在 |

**历史报告应当如实保留错误，而不是为了过门禁去篡改记录** ——
篡改会让「当初误判了什么」这段历史消失。

> 若将来确实需要让某份报告接受门禁校验（例如它不只是记述、还承担权威声明职责），
> 正确做法是**把它移到 `docs/` 根并修正其中的失效声明**，而不是把本目录加进扫描范围。
