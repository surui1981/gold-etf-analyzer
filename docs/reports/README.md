# 内部分析报告（历史存档）

本目录存放项目演进过程中的**阶段性分析报告**：版本差距分析、用户体验改进方向、界面改造评估、客户交互易用性评估、推进路线分析等。它们记录了**当时的判断依据与决策链**，是「为什么这样做」的原始出处；面向使用者的正式文档在 `docs/` 上一层（`application-guide` / `feature-alignment` / `improvement-path` / `ux-roadmap` / `deployment`）。

## 为什么放在子目录（而不是 `docs/` 根）—— 请勿挪动

`scripts/check_docs_claims.py` 的扫描范围是：

```python
DOC_FILES = [ROOT / "README.md", *sorted((ROOT / "docs").glob("*.md"))]
```

`pathlib.Path.glob("*.md")` 是**非递归**的 —— 只扫 `docs/` 直接子文件，不进入子目录。

这不是疏漏，而是**必要条件**：本目录的报告是**记述性文档**，为了说明「当时误判了什么」，必须能原样写出**当时错误或已被废弃的实体名**。实测把它们放到 `docs/` 根会让门禁**新增 8 处失败**，全部来自 `版本差距分析与改进方向-20260927.md`：

| 位置 | 被判失败的声明 | 实情 |
|---|---|---|
| `:72` `:165` | localStorage key `pm_dash_layout` | 实际是 `pm_dashboard_layout`（写错了） |
| `:75` | 表 `alert_rules` | 它是 `app_settings` 里的 JSON key，**不是表** |
| `:76` | 表 `portfolios` | **凭空捏造**，代码中不存在 |
| `:77` | 表 `snapshot_overrides` | **凭空捏造**，代码中不存在 |
| `:91` | 页面 `central-bank.html` | 实际走 RESTful 路由 `/central-bank`，无此静态页 |
| `:93` | 端点 `/api/v1/push/unsubscribe` | 不存在 |
| `:151` | 端点 `/api/v1/market` | 不存在 |

这些正是 `docs/feature-alignment.md` 被登记进 `SKIP_FILES` 的同一类原因（该文件是对账报告，天然会引用错误值用于记述）。**历史报告应当如实保留错误，而不是为了过门禁去篡改记录** —— 篡改会让「当初误判了什么」这段历史消失。

> 若将来确实需要让某份报告接受门禁校验（例如它不只是记述、还承担权威声明职责），正确做法是**把它移到 `docs/` 根并修正其中的失效声明**，而不是把本目录加进扫描范围。
