# 界面「聚类显示」评估与改造报告

> 项目：gold-etf-analyzer（黄金价格投资辅助工具）
> 评估日期：2026-10-01 ｜ 基线版本：V0.76.0 ｜ 改造版本：**V0.77.0**
> 范围：`static/` 下 13 个页面 + 23 个共享脚本

---

## 摘要

界面本身信息是齐全的，但**「同类项平铺」是贯穿全站的系统性问题**：属于同一语义类别的信息项被平铺在同一个容器里，没有分组标题、没有视觉分组，用户必须一条条读完再自己心算归类；更严重的是**同一份数据在多处渲染**——同一批指标被画 2~3 遍，字段互补却要人肉横向对照。

本次评估识别出 **23 处可聚类项**，按「改动价值 / 成本」排序后，**实施其中 5 项聚类改造 + 3 处附带缺陷修复**，并新增一道「渲染行为」门禁（项目此前只有静态门禁，查不出这类缺陷）。

## 一、评估方法

1. 逐页读取 13 个 HTML 的区块骨架，统计 `.card` / `.panel` / `.section` / `<canvas>` / 表格 / 列表的分布与行号。
2. 对每个「同类项」追问三问：**是否属同一语义类别？是否已平铺？是否有分组标题或视觉分组？**
3. 交叉核对共享脚本提供的既有分组机制（避免重造轮子）。
4. 交叉核对渲染函数：判断「同一份数据被几个出口渲染」。

## 三、本次已实施（V0.77.0）

### 3.1 新增全站聚类样式基元 `static/theme.css`

新增一套统一语汇，取代各页各写 padding/margin。**只用 theme 变量 → light / dark / hc 四主题自动适配**；前缀 `pmc-` 避免与页面私有类名（`.card` / `.panel` / `.section` / `.kpi`）冲突。

| 类名 | 用途 |
|---|---|
| `.pmc-cluster` + `.pmc-cluster-head` | 纵向簇（簇标题 + 内容），支持 `.pmc-note` 副说明与 `.pmc-count` 计数徽标（自动靠右） |
| `.pmc-tabs` + `.pmc-tab` + `.pmc-tabpanel` | 簇间切换（同源分面一次只看一面），选中态前景用 `var(--card)` 保证三主题对比度 |
| `.pmc-group` + `.pmc-group-title` | 簇内子组（比簇更轻） |
| `.pmc-grid-title` | grid 容器内的**跨列**子分组标题（`grid-column: 1 / -1`） |

| # | 缺陷 | 影响 | 修法 |

### 3.4 新增门禁：渲染行为验证

**发现的问题**：本次全部改动落在**渲染逻辑**里 —— 语法正确、DOM id 一个不差，`check_static_js.py` 三类检查全绿，但分组完全可能不出现。开发期就踩过一次：验证脚本只提取到函数定义却没调用它，`innerHTML` 为空却「看起来通过」。

**新增**：

- `scripts/check_cluster_render.mjs` —— 从各页源码**提取真实的聚类代码块**，用最小 DOM 桩 + mock 数据在 Node 里**真实执行**，断言产出的 HTML 结构（簇数量 / 簇标题 / 卡片数 / 分组顺序 / 旧结构已消失），共 **33 条断言**。
- `tests/test_ui_cluster_render.py` —— pytest 包装，纳入常规回归；无 node 时跳过（与 `check_static_js.py` 的降级策略一致）。
